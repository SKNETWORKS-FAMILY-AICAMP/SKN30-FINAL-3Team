# 잔여 자원 관리

실시간 상태는 `just doctor`가 정본이다. 이 표는 삭제 승인이 아니라 소유권·보존 기한 확인 목록이다.
자동 감시·자동 정리·예산 차단 서비스는 추가하지 않는다.

| 자원 범위 | 담당자 | 보존·종료 조건 | 처리 |
|---|---|---|---|
| shared F2/general Pod | Infra 운영자 | 사용 종료 시 delete; S3 모델 정본 유지 | 기존 dev-stop이 관리하는 정확한 Pod 이름만 대상 |
| `f2-model-train` | 학습 담당자 확인 필요 | 학습 산출물 인계·백업 완료 후 결정 | 개인/학습 volume은 자동 삭제하지 않음 |
| `f3-vllm-sjkang` | 소유자 확인 필요 | 개인 실험 종료·모델 보존 여부 확인 | shared serving과 분리 |
| 기타 Template·registry | 소유자 확인 필요 | 다른 Pod/Template 참조가 없고 재사용 계획이 없을 때 | 조회 후 명시적 정리 |
| `vllm_pod` Template | 소유자 확인 필요 | 직접 입력된 API key의 사용처 확인 | RunPod Secret 참조로 전환·필요 시 회전 |
| AWS GPU EBS | Infra 운영자 | 일반 stop은 캐시 유지, deep-stop은 삭제 | 정지 중 비용 표시 |
| RDS·백업 | Infra·데이터 소유자 | 환경 종료 정책·snapshot 보존 승인 | 정지 7일 뒤 자동 시작 시각 확인 |
| saved plan | plan 생성 운영자 | 24시간·입력 변경 시 무효 | 새 plan 검토; 과거 plan은 실행하지 않음 |

팀원에게 요청할 때는 자원 ID, 담당자, 용도, 종료일, 백업 필요 여부만 공유하고 키·접속 URL은 전달하지 않는다.
각 소유자가 확인되면 이 표의 미확정 항목을 갱신한다. 과거 점검의 자원 개수는 현재 잔액·청구액으로 해석하지 않는다.
