# 데이터셋 설계 지침

## 요구사항을 데이터 계약으로 변환

기능명을 기준으로 데이터셋 구조를 고정하지 말고 다음 질문으로 현재 요구사항을 해석한다.

1. 평가할 동작과 제외할 동작은 무엇인가?
2. 한 사례의 입력, 기대 출력과 관측 가능한 실패는 무엇인가?
3. 반드시 거부·보류·불명확 처리해야 하는 경우는 무엇인가?
4. 정답의 원천과 판정 권한은 누구에게 있는가?
5. 자동 정답이 가능한가, 전문가 라벨이나 다중 검수가 필요한가?
6. 어떤 주체·원천·시간·시나리오가 분할 누수 단위인가?

답을 데이터셋 목적, 사례 단위, 입력 계약, 정답 계약, 금지 조건과 slice 정의로 기록한다. 요구사항에 없는 필드나 상태를 사실처럼 추가하지 않는다.

## 산출물 계층

- 원본: 변형하지 않은 입력과 출처 메타데이터를 보존하되 개인정보 정책에 따라 접근을 제한한다.
- 중간 산출물: 비식별화, 파싱, 정규화와 라벨링 단계별 결과를 원본과 연결한다.
- 정제 데이터: 평가 계약을 만족하고 품질 검증 대상이 되는 사례를 구성한다.
- 배포 데이터: 불변 버전, manifest와 체크섬을 가진 소비자용 산출물로 발행한다.

디렉터리 이름이나 저장 기술보다 계층 간 의미와 계보를 먼저 고정한다. 원본과 배포 데이터를 같은 위치에서 덮어쓰지 않는다.

## 사례와 라벨

각 사례에는 최소한 다음 의미를 표현할 수 있게 한다.

- 안정적인 사례 식별자와 데이터셋 버전
- 원천 참조와 이용·동의 조건
- 입력과 정답
- 원시 값과 정규화 값의 구분
- 정답 근거 또는 판정 출처
- 불명확, 판정 불가, 제외와 결측의 구분
- 그룹·시간·난이도·오류 유형 등 분할과 slice에 필요한 가명 메타데이터

빈 값, 해당 없음, 관측 실패와 라벨 누락을 하나의 값으로 합치지 않는다. 라벨 정의와 예외 예시는 기능 요구사항 또는 별도 버전된 라벨 가이드가 소유하게 한다.

## 분할과 누수 방지

- 모델이나 규칙을 조정하는 개발 데이터와 최종 판정 데이터를 분리한다.
- 동일 주체, 원천 문서, 파생 샘플, 유사 시나리오와 시간상 후속 레코드가 분할을 넘지 않게 그룹 기준을 정한다.
- 증강본과 원본을 서로 다른 분할에 넣지 않는다.
- 운영 시점의 일반화를 평가해야 하면 시간 순서 분할을 검토한다.
- 분할 설정, 그룹 키, 난수 시드와 사례 목록을 버전으로 고정한다.
- 학습 데이터가 필요하지 않은 작업에 학습 분할을 관성적으로 만들지 않는다.
- 층화 키 외에 결과를 좌우하는 축이 있으면 분할 보고서에 그 분포를 함께 남긴다. F2는
  라벨로 층화하지만 장부 종류와 장부 불일치가 결과를 좌우하므로 split별 분포를 확인한다.
- 분할 도구는 한 작업의 스키마가 늘어나면 도구를 새로 만들지 않고 입력 스키마를 넓힌다.
  `split_f2_sllm_dataset.py`는 분류(`scenario_id`)와 full-output(`sample_id`)을 함께 받는다.

## 출처와 개인정보

- 출처, 이용 조건, 수집 목적, 처리 위치, 접근 주체, 보존·삭제 조건을 manifest에 기록한다.
- 개발·평가에는 합성 또는 승인된 비식별 데이터를 우선한다.
- 가명 식별자는 원래 개인정보를 복원할 수 없는 방식으로 관리한다.
- 합성·증강·수작업 작성·운영 추출 데이터를 구분한다.
- 실제 분포와 다른 합성 데이터의 한계를 품질 보고서에 명시한다.

## 배포 manifest

manifest에는 최소한 다음을 기록한다.

- 데이터셋 ID, 버전, 목적과 상태
- 데이터 계약과 라벨 가이드 버전
- 원천과 변환 계보
- 분할 방식, 사례 수와 주요 분포
- 개인정보 분류와 보존 조건
- 생성 설정, 코드 버전과 난수 시드
- 파일별 체크섬
- 알려진 한계와 사용 금지 범위

정답이나 원문 개인정보를 manifest에 직접 넣지 않는다.

## 품질 게이트

- 스키마와 필수값
- 식별자·원천·내용 중복
- 참조와 근거 무결성
- 라벨 값과 정규화 규칙
- 분할 누수와 평가 오염
- 주요 slice의 최소 대표성
- 개인정보와 비밀값 잔존
- manifest 건수와 실제 산출물 일치
- 체크섬과 재현성

실패한 데이터를 조용히 삭제하거나 자동 수정하지 말고 오류 유형, 건수와 처리 결정을 보고한다.
