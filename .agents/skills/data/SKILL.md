# 데이터셋과 평가 데이터 개발

기능별 필드·지표·합격 기준은 요구사항 정본에서 찾아 데이터셋과 평가 계약으로 변환한다. 이 스킬에 기능 요구사항을 복제하거나 미확정 기준을 승인된 결정처럼 만들지 않는다.

## 필요한 문서 선택

공통 탐색·결정 확인·지식 갱신은 루트 `AGENTS.md`와 project-wiki를 따른다. [참조 인덱스](references/index.md)와 요구사항 인덱스에서 해당 작업의 문서만 읽는다.

| 변경 | 읽을 정본 |
|---|---|
| 데이터셋 목적·사례·라벨·분할·manifest·발행 | [데이터셋 설계](references/dataset-design.md), 운영 규칙은 `data/README.md` |
| 지표·slice·사람 평가·기준선·임계값·비교 | [평가 설계](references/evaluation-design.md) |
| 구조·도구·포맷·품질 방식 | [결정 인덱스](references/decisions/index.md)와 관련 ADR |
| 미확정 저장·라벨링·분할·품질·평가 선택 | [미해결 질문](references/open-questions.md) |
| 개인정보·외부 데이터 | project-wiki 개인정보 정책과 출처 등록 상태 |

## 책임과 경계

- Data는 원천 등록·수집·비식별화·정제·적재, 정답과 평가 입력의 검수·계보, 분할·버전·manifest·체크섬과 데이터 품질 검증을 소유한다.
- 모델·프롬프트·Agent·그래프·추론과 실험 실행, HTTP API·업무 규칙·운영 DB 트랜잭션·Repository, UI·IaC는 소유하지 않는다. `data/`에는 테스트 코드를 추가하지 않는다.
- 모델 성능 평가 구현·실행에는 ai 스킬을 함께 사용한다. Data는 데이터·정답·slice·평가 계약, AI는 모델 실행·지표 계산·추적·결과 생성을 담당한다.
- 운영 데이터·사용자 피드백은 Backend의 승인된 계약으로 받으며 운영 DB에 직접 결합하지 않는다. 소비 모듈에는 버전된 계약과 산출물 위치를 제공한다.
- 실행환경·의존성은 `data/`에서 독립 관리한다. 루트 공통 Python 환경·공통 패키지와 필요하지 않은 내부 계층을 미리 만들지 않는다.

## 개인정보와 평가 무결성

- 개발·평가에 실사용자 개인정보를 기본 사용하지 않는다. 원문 개인정보·비밀값·인증정보를 저장소·로그·프롬프트에 기록하지 않는다.
- 외부 처리자에게 전달하는 필드·저장 여부·리전·삭제 조건을 확인한다. 합성 데이터를 표시하고 대표성 근거 없이 실제 성능으로 일반화하지 않는다.
- 동일 주체·원천·시나리오의 분할 누수를 막고 최종 평가 정답·숨김 slice·사례를 추론 입력과 튜닝에서 차단한다.
- 원본부터 발행까지 계보를 유지한다. 라벨·평가셋 수정은 기존 불변 버전을 덮어쓰지 않고 새 버전·manifest·체크섬으로 발행한다.

## 검증과 완료

품질 검증을 운영 파이프라인 기능으로 구현한다. 스키마·필수값·중복·건수·참조 무결성·주요 slice·개인정보 잔존·분할 누수·정답 오염을 검사하고 계보·설정·시드·코드 버전·체크섬으로 재현성을 확인한다. 평가 계약 변경은 AI 소비자 호환성을 검증한다. 승인·구현된 품질 명령을 사용하며 도구가 미확정이면 검증 공백을 보고한다.
