# ADR-0008: F3 판정의 근거 reference와 제한된 구조화 출력

## 맥락

RunPod Qwen의 L1 중개 판정은 입력 카드에 이미 있는 근거 원문과 긴 설명을 출력 JSON에 다시
생성했다. 3후보 표본에서 출력 1,326 tokens, 약 146.92초가 걸렸고 첫 토큰 이후 decode가
지연의 대부분이었다. JSON 파싱이나 후보 SQL이 아니라 반복적인 모델 출력 생성이 병목이었다.

## 결정

- Backend–AI 공개 `brokerage-judgment:v1` DTO와 DB 저장 형식은 유지한다.
- 판정 모델 입력의 카드별 중복 근거는 요청 안에서 결정적으로 만든 `evidence_catalog`에 한 번만
  싣고 카드 본문은 reference를 사용한다.
- 모델 출력은 근거 원문 대신 catalog의 정수 `evidence_refs`를 후보별 1~3개 반환한다. AI 조립
  단계가 요청 카드의 원본 `Evidence`, side와 field를 복원한다.
- 존재하지 않는 reference와 다른 후보 카드의 reference는 계약 위반으로 거절하고 기존 제한된
  repair 대상에 포함한다. 모델이 근거 원문을 만들거나 수정할 자리는 없다.
- 비교·장애물·양보·기각의 공통 의미는 내부 reason code로 받고 고정 한국어 문구로 조립한다.
  후보별 detail과 행동 문구는 각각 120자로 제한한다.
- 최대 후보 5건의 합성 파일럿 3회에서 정상 출력은 1,451~1,468 tokens였다. 2,048 tokens를
  판정 호출의 보수적인 tail guard로 적용한다. 이는 정식 p99가 아니며, 배포 후보의 고정 평가셋
  30회 이상에서 분포를 다시 측정해 상한을 재검토한다.
- 프롬프트는 `brokerage-judgment-prompt:v5`, 조립 절차는
  `brokerage-judgment-workflow:v2`로 올린다. 공개 계약 버전은 바꾸지 않는다.

## 결과와 적용

같은 로컬 합성 DB·RunPod FP8 모델의 L1 3후보 판정은 출력 868 tokens, 61.84초였고 warm 전체
실행은 61.10초에 완료됐다. 기존 표본의 판정 1,326 tokens·146.92초 및 warm 전체 150.85초보다
각각 57.9%, 59.5% 짧다. 단일 전후 표본이므로 품질 승인이나 p95를 뜻하지 않는다.

저장 트리거, `ANCHOR_READY` 주차, 사용자 요청 뒤 후보·판정 실행, Frontend와 공개 HTTP 응답은
바꾸지 않는다. 포지션 카드의 최초 근거 추출은 상담 원문에서 정확한 인용을 만들어야 하므로
이번 reference 변경 범위에 포함하지 않는다. 카드 출력 상한은 별도 분포 없이 추정해 적용하지
않는다.
