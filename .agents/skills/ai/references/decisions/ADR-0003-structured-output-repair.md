# ADR-0003: 구조화 출력 계약 위반은 되먹여 다시 만든다

- 상태: 승인됨
- 결정일: 2026-08-27

## 맥락

구조화 출력에서 우리가 강제하는 규칙은 두 종류다. JSON schema 가 표현하는 것(타입, 열거값,
길이)과 `model_validator` 가 표현하는 교차 필드 규칙이다. 두 번째는 **스키마 문법에 자리가
없어 모델이 그 존재를 알 방법이 없다.**

F3 후보 포지션 카드가 이 때문에 결정적으로 실패했다. `hard_deadline` 을 세우려면 timing
constraint 가 하나 이상 있어야 한다는 규칙(F3-PC-04)을 모델이 반복해서 어겼다.

재시도만으로는 풀리지 않았다. 포지션 카드와 중개 판정은 재현성을 위해 온도 0으로 부르므로
(F3-NF-08) 같은 입력을 다시 던지면 같은 답이 온다. Worker 의 lease 재시도 3회가 동일한 위반을
세 번 반복하고 종료하는 것을 로그로 확인했다. 프롬프트에 규칙 문장을 추가해도 규칙이 쌓이면
그중 하나를 흘린다.

더 큰 구멍이 하나 더 있었다. 응답을 공개 결과로 조립하고 요청과 대조할 때 나는 실패
(`PositionCardContractError`, `BrokerageJudgmentContractError`)는 **첫 시도에 재시도 없이**
종료됐다. 인용문 위조는 LLM 의 대표적인 실패인데 복구 경로가 전혀 없었다.

## 결정

- 계약을 어긴 출력은 **검증이 지적한 내용을 대화에 덧붙여 다시 부른다.** 입력이 달라지므로
  온도 0에서도 다른 표본이 나오고 모델은 그제서야 어긴 규칙을 안다.
- 되먹임은 Provider 어댑터가 아니라 **생성기가 부르는 자리**에 둔다. 조립·대조 단계의 실패도
  같은 되먹임 대상이어야 하며 어댑터 안에서는 그 층이 보이지 않는다.
- 되먹일 수 있는 실패만 잡는다. 전송 실패(시간 초과, rate limit)는 모델에게 알려 줄 것이
  없으므로 Worker 의 lease 재시도에 맡긴다.
- 되먹임 문구에는 **필드 경로, 우리가 계약에 적어 둔 고정 규칙 문구와 내부 식별자만** 담는다.
  모델이 만든 값, 상담 원문, 성명·연락처는 담지 않는다. 외부 Provider 로 나가는 내용이므로
  개인정보 정책의 프롬프트 조항이 그대로 적용된다.
- 되먹임 상한은 생성 1회당 **3회**(원본 1 + 되먹임 2)다. Worker 의 lease 재시도 3회와 곱해
  한 실행 단계의 외부 호출은 최대 9회다. 상한은 모듈 상수로 노출해 조절할 수 있게 둔다.
- 상한을 다 쓰면 **마지막 예외를 타입 그대로 다시 던진다.** 되먹임은 성공률만 바꾸고 실패의
  등급은 바꾸지 않으므로 Backend 의 실행 수명주기 분류는 달라지지 않는다.
- 되먹여 고칠 수 있는 계약 오류는 `core.errors.OutputContractError` 를 조상으로 둔다. `core` 가
  기능 모듈을 import 하지 않고도 이 부류를 한 덩어리로 잡기 위한 표식이다.

## 대안

- **모델 교체.** 상위 모델도 표현되지 않은 규칙을 100% 지키지는 않는다. 확률만 낮추고 원인은
  남으며 비용이 오른다. 되먹임을 넣고도 실패율이 남으면 그때 별도 결정으로 다룬다.
- **invariant 완화.** "근거 없는 마감일을 만들지 않는다"는 승인된 요구사항이다. 규칙이 틀린
  것이 아니라 전달되지 않은 것이므로 요구사항을 깎을 이유가 없다.
- **어댑터 안에서 되먹임.** 조립·대조 층을 덮지 못한다.

## 결과

- 합성 seed 5개 케이스가 전부 `COMPLETED` 에 도달했다. 이전에는 후보 카드 단계에서
  `FAILED_TERMINAL` 로 끝났다.
- 되먹임이 흡수하지 못한 실패는 Worker 의 lease 재시도가 이어받는다. 두 층이 함께 동작하는
  것을 종단 실행에서 확인했다.
- 한 단계의 외부 호출 상한이 1회에서 9회로 올라간다.
- 되먹임이 왜 필요한지 자체가 "표현할 수 없는 규칙을 프롬프트가 책임진다"는 구조에서 나온다.
  그 책임이 지켜지는지는 `ai/tests/architecture/test_prompt_covers_output_contract.py` 가
  기계적으로 고정한다. 모델 출력 schema 에서 도달 가능한 모든 `model_validator` 는 프롬프트
  전달 표에 등록되어 있어야 한다.
