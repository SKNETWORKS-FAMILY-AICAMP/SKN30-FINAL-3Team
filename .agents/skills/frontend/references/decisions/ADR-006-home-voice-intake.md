# ADR-006: 첫 화면을 진입점 선택으로 두고 신규 음성메모 접수가 장부를 판정한다

## 맥락

지금까지 로그인 직후 화면은 매물장 그리드였다. 사용자가 가장 먼저 보는 것이 40열짜리 표라서
"새 상담을 접수한다"는 일이 표 위 도구 모음의 부수 동작으로 밀렸다. 음성메모 진입점은 매물장
도구 모음과 구입장 도구 모음에 따로 있었고, 어느 쪽에서 눌렀는지가 곧 어느 장부에 행이 생기는지를
정했다. 상담 내용이 아니라 사용자가 서 있던 화면이 장부를 결정하는 구조다.

F2 계약은 이미 상담 유형을 분류해서 돌려준다. 매도의뢰·매수문의·공동중개·단순문의 네 가지이고,
필드 제안은 `매물장 + 매도의뢰`와 `구입장 + 매수문의`에서만 만들어진다. 장부와 상담 유형이
어긋나면 `ledger_mismatch`가 켜지고 상담 로그 초안만 남는다. 즉 장부를 먼저 고르게 하면
사용자가 잘못 고른 순간 그 분석의 필드 제안은 통째로 버려진다.

## 결정

- 로그인 후 첫 화면은 진입점 선택 화면(`홈`)이다. `음성 메모 입력`, `매물장 연결`,
  `구입장 연결` 세 가지를 같은 높이에 둔다.
- 신규 음성메모 접수는 상단바의 단일 진입점이 소유한다. 화면 어디에 있든 같은 버튼이고,
  어느 장부에 행이 생길지는 분석 결과가 정한다.
- 상담 유형 → 장부 판정은 React에 의존하지 않는 순수 함수 하나(`routeConsultation`)가 소유한다.
  매도의뢰는 매물장, 매수문의는 구입장이다.
- **공동중개와 단순문의는 장부를 단정하지 않는다.** 계약상 두 유형은 어느 장부로 분석해도
  필드 제안이 없어 판정할 근거가 없다. 판정 함수는 `null`을 돌려주고, 접수 화면이 기본 장부를
  쓰면서 사용자에게 직접 확인하라고 알린다.
- 장부를 정하지 않은 접수는 기준 장부(매물장)로 먼저 분석하고, 판정이 다르면 판정된 장부로 한 번
  더 분석한다. 어긋난 분석은 필드 제안을 만들지 않으므로 재분석 없이는 매수문의의 손님 정보를
  받을 수 없다. 요청이 두 번 나가는 경우는 매수문의 한 유형뿐이다.
- 접수는 행을 만들고 선택한 제안만 채운 뒤 상세를 연다. **저장하지 않는다.** 서버로 보내는
  시점은 사용자가 상세에서 저장을 누를 때다.
- 매물장에서 세대를 한 건 선택한 상태의 음성메모는 그대로 남긴다. 대상이 이미 정해져 있어
  장부를 판정할 일이 없으므로 신규 접수와 다른 버튼(`선택 세대 음성메모`)으로 구분한다.
- 상단바의 `연결됨` 표시는 없앤다. 실제 연결을 확인하지 않는 고정 문구였고, 오프라인 상태는
  이미 배너와 상태 표시줄이 알린다.

## 결과

- 상담 내용이 장부를 정한다. 사용자가 화면을 잘못 골라 필드 제안을 버리는 경로가 사라진다.
- 매수문의 접수는 음성 업로드와 분석이 두 번 일어난다. 비용과 지연이 두 배이므로, 한 번의 분석에서
  두 장부의 제안을 함께 받을 수 있는지는 F2 계약 소유자와 별도로 논의한다. 그전까지 재분석이
  화면 쪽에서 취할 수 있는 유일한 정확한 방법이다.
- 첫 화면이 바뀌어 장부 그리드는 한 번의 이동을 더 거친다. 장부를 계속 보는 사용자에게는 비용이
  생기므로, 마지막으로 본 화면을 기억할지는 사용 관찰 후 정한다.
- `홈`은 아직 요구사항 정본과 Screen Matrix에 없는 화면이다. 요구사항 ID가 붙기 전까지
  확정된 화면 구조로 표현하지 않는다.
