# ADR-002: TypeScript를 프론트엔드 표준 언어로 사용

## 맥락

프론트엔드의 컴포넌트 계약, API 데이터, 상태 전이와 리팩터링 경계를 정적으로 검증할 공통 기준이 필요하다. 컴파일 시점의 타입은 외부 데이터의 런타임 안전성을 대신하지 않으며, 기존 JavaScript를 한 번에 전환하면 기능 변경과 마이그레이션 위험이 섞일 수 있다.

## 결정

- 프론트엔드 운영 코드의 표준 언어로 TypeScript를 사용한다.
- TypeScript의 `strict` 검사를 기본으로 사용한다.
- 새 운영 코드는 원칙적으로 `.ts` 또는 `.tsx`로 작성한다.
- 기존 JavaScript는 변경 범위에서 안전하게 검증할 수 있을 때 점진적으로 전환하고, 광범위한 변환은 별도 변경으로 수행한다.
- API 응답, URL 파라미터, 사용자 입력과 브라우저 저장소 데이터는 런타임에서 별도로 검증한다.
- 설치 버전과 컴파일러 설정의 정본은 `frontend/package.json`, lockfile과 `tsconfig`로 관리한다.

## 결과

- 공개 경계와 상태 모델에서 타입 오류를 조기에 발견하고 리팩터링의 영향을 추적할 수 있다.
- `any`와 무검증 타입 단언으로 마이그레이션을 완료한 것처럼 처리하지 않는다.
- TypeScript 의존성, `tsconfig`, 타입 검사 명령과 기존 파일 전환이 코드에 반영되기 전까지 이 결정은 구현 완료를 의미하지 않는다.
