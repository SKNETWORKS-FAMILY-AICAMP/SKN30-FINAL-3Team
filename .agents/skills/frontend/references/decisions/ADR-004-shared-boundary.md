# ADR-004: 여러 기능이 공유하는 경계를 `src/shared`에 둔다

## 맥락

기능 모듈은 자기 UI, 상태, API 변환을 가까이 두는 것을 원칙으로 한다. 그런데 실제로는 기능
사이에 같은 코드가 필요해지는 지점이 있고, 그때 세 가지 중 하나가 벌어지고 있었다.

- 다른 기능의 내부 파일을 깊은 경로로 가져간다. CSRF 토큰 보관소가 장부 기능 안에 있어
  인증과 F2가 `features/ledger/api/session.ts`를 직접 참조했다.
- 우회해서 다시 만든다. F2 음성 업로드는 공용 HTTP 경계를 쓰지 않고 `fetch`를 직접 호출한다.
- 배럴을 통해 가져가면서 필요 없는 의존까지 끌어온다. 장부 공개 진입점에서 금액 포맷터를
  가져오면 장부 훅과 transport가 전부 딸려 온다.

F3 교차 판정이 HTTP 경계, 런타임 검증기, 금액 표기의 세 번째 사용처가 되면서 이 상태를 그대로
두면 F3가 장부에 의존하게 되는 상황이 됐다. 의존 방향이 뒤집힌다.

## 결정

- 여러 기능에서 **실제로 반복되고 의미가 안정된** 코드만 `src/shared` 아래로 올린다. 반복되기
  전에 미리 올리지 않는다.
- 이름만 포괄적인 `utils`, `common` 또는 거대한 공통 컴포넌트를 만들지 않는다. 무엇을 담는
  경계인지 이름으로 말할 수 있을 때만 모듈을 만든다.
- 현재 경계는 셋이고 공개 진입점은 넷이다.

  | 공개 진입점 | 담는 것 | 설정 의존 |
  |---|---|---|
  | `shared/api` | `request()`, `expectNoContent()`, CSRF 보관소 | 있음 |
  | `shared/api/errors.ts` | `ApiError`, `isCanceled`, 상태 코드 분류 | 없음 |
  | `shared/decode` | `DecodeError`와 원시 런타임 검증기 | 없음 |
  | `shared/format` | 억·만 금액과 평형 표기 | 없음 |

- **설정에 의존하는 모듈과 순수한 모듈을 한 배럴로 묶지 않는다.** `shared/api`는
  `import.meta.env`를 읽는 설정 모듈에 의존한다. 검증기와 포맷터를 같은 배럴에 넣으면 값 하나를
  검사하려는 쪽이 브라우저 번들러 없이는 못 도는 코드까지 끌어오고, Node 테스트에서 깨진다.
- 같은 이유로 `shared/api`는 **진입점이 둘**이다. 오류 분류는 전송을 필요로 하지 않는데 배럴이
  전송과 함께 내보내면, 분류만 쓰는 순수 모듈이 `import.meta.env`까지 끌어온다. 그래서 순수한
  `errors.ts`를 그 자체로 진입점으로 둔다. **오류 분류만 필요하면 배럴이 아니라 `errors.ts`를
  가져온다.** 배럴은 전송이 필요할 때만 쓰고, 편의로 함께 내보내는 `ApiError`는 이미 배럴을
  쓰는 쪽이 import을 두 줄로 늘리지 않게 하는 용도다.
- 오류는 **분류만 공유하고 사용자 문구는 각 기능이 소유한다.** 같은 403이라도 장부는 무엇을
  고쳐야 하는지 알려줘야 하고 인증은 계정 존재 여부를 감춰야 한다.
- 기능 모듈은 다른 기능의 내부 파일을 깊은 경로로 가져오지 않는다. 공개 진입점만 쓴다.
- 공개 진입점은 실제로 밖에서 쓰는 것만 내보낸다. 쓸 사람이 없는 이름을 미리 열면 그것도
  계약이 되어 내부를 고칠 때마다 딸려 온다.

## 결과

- 인증·F2·장부가 장부 내부를 참조하던 세 곳이 정리됐다. F3는 장부의 **런타임 코드**에 의존하지
  않는다. 후보 표시 이름을 만들기 위해 장부 공개 진입점의 행 타입만 `import type`으로 참조하며
  타입은 번들에 남지 않는다. 장부 행의 필드 구성이 곧 화면에 보이는 후보 이름이라 F3가 같은
  10여 개 필드를 다시 정의하면 매퍼가 바뀔 때 조용히 어긋난다.
- `LedgerApiError`가 `ApiError`로 바뀌었다. 장부 전용 이름이 공용 전송 계층에 남아 있으면
  다음 사용처가 그대로 복사한다.
- 순수 모듈은 브라우저 없이 테스트할 수 있다.
- 동작은 바뀌지 않았다. 기존 테스트가 그대로 통과하는 것이 이 변경의 성공 기준이었다.
- 아직 올리지 않은 것이 있다. `multipart/form-data` 업로드는 F2 한 곳뿐이라 그 기능에 두었고,
  두 번째 사용처가 생기면 `shared/api`로 올린다.
- 설정 의존과 순수를 나누는 규칙을 `shared/api` **안에도** 적용했다. 오류 분류만 필요한 F3·장부의
  문구 모듈은 배럴 대신 `shared/api/errors.ts`를 가져온다. 배럴을 쓰면 `httpClient`를 거쳐
  `import.meta.env`를 읽다 Node 테스트에서 깨진다. `errors.ts`는 import이 하나도 없는 순수
  파일이라 진입점으로 삼는 데 옮길 코드가 없었다. 규칙이 문서로만 남지 않도록 두 문구 모듈을
  모두 이 진입점으로 맞췄다.
- 이 경계는 도구로 강제되지 않는다. 프론트엔드에 lint 설정이 없어 배럴에서 `ApiError`만 가져가는
  순수 모듈이 생겨도 그 모듈을 Node 테스트에 넣기 전까지는 드러나지 않는다. 순수 모듈에 테스트를
  붙이는 시점이 실질적인 검사 지점이다.
