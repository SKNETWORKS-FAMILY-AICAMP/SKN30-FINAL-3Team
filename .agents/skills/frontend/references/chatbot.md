# F4 챗봇 화면 상태

기능 정본은 [챗봇 요구사항](../../../../docs/requirements/chatbot/overview-and-scope.md), 화면 정본은 [챗봇 화면](../../../../docs/screen/chatbot.md)이다. 기능은 서버의 `GET /api/v1/chatbot/conversation` 응답 `enabled`로 탐색하며 기본 비활성화 배포를 지원한다.

- 공개 진입점은 `frontend/src/features/chatbot/index.ts`의 `Chatbot`이다. 공통 셸은 `userKey`, `onAction`, `onSessionExpired`, `suspended`로 사용자와 기존 화면 이동·모달 우선순위를 연결한다.
- 사용자별로 controller와 React 화면을 새로 생성한다. 대화·입력 초안·결과·선택은 메모리에만 두며 브라우저 영속 저장소에 기록하지 않는다.
- JSON은 공통 HTTP·CSRF 경계를, 진행 상태는 별도 native EventSource를 사용한다. 재접속·폴링·패널 열기는 GET만 호출하며 질문을 자동으로 재전송하지 않는다.
- 완료·실패·중단 복원에는 대화의 활성 요청 또는 최신 메시지의 요청 상태를 조회한다. revision이 작거나 완료 이후 실행 상태로 돌아가는 이벤트는 버린다.
- 삭제·계정 전환·unmount는 generation과 AbortController로 이전 읽기·SSE 응답을 무효화한다. 삭제 실패 시 이력을 유지하고 관찰을 재개한다. 다른 탭의 삭제·재생성을 발견해 대화 ID가 바뀐 경우에도 이전 이력·페이지·조건 초기화 응답을 폐기하고 busy 상태를 해제한다.
- 결과 페이지 이동은 서버에서 재조회한다. 순번 참조는 최근 완료 2쌍의 저장된 원래 첫 페이지에서만 선택한다. 재조회된 페이지는 첫 페이지로 돌아와도 개별 상세 버튼만 제공하며, 대화 교체·최근 문맥 만료·페이지 이동 시 참조 선택을 해제한다.
- 패널은 모바일에서도 비차단 영역이다. Escape로 접고 열기 버튼으로 초점을 복원하며 기존 Modal이 열리면 패널을 접는다. 전체 삭제 확인은 PatternFly Modal을 사용한다.

## 대화 패널 사용성

- 사용자 요청에 따라 오른쪽 전체 높이 오버레이 사이드 패널로 연다. 메인 콘텐츠를 밀지 않으며 별도 backdrop을 만들지 않는다. 폭·반응형·접기 배치는 [화면 정본](../../../../docs/screen/chatbot.md#진입과-배치)을 따른다.

- 첫 화면은 매물·손님·일정 추천 질문을 목록으로 보여 주며, 클릭은 입력칸 채우기만 수행한다. 첫 화면은 스크롤 맨 위에서 연다.
- 검색 조건은 상단에 `검색 조건` 제목·조건 칩·초기화를 항상 한 줄로 표시한다. 조건이 많으면 칩 영역만 가로로 스크롤하며 키보드로도 접근할 수 있다. 저장·기억 안내는 헤더의 휴지통 옆 도움말 아이콘으로 팝오버를 열어 확인하고, 조건 초기화와 대화 전체 삭제는 별도 동작으로 유지한다.
- `useChatScroll.ts`는 이전 이력 추가 시 보이던 메시지 위치를 복원한다. 과거 답변을 읽는 동안 새 답변이 도착해도 맨 아래로 끌어내리지 않는다. 긴 새 답변은 요약부터 보여 주고 `최신 대화로 이동`으로 맨 아래와 입력칸에 이동한다.
- 처리 중에도 다음 질문의 초안을 작성할 수 있으나 전송·참조 선택·조건 변경은 잠근다. 실패한 질문 재시도는 별도 초안과 참조 선택을 소비하지 않으며, 새 요청에 임의의 참조 답변을 전달하지 않는다.
- 입력 후 포커스는 다른 컨트롤로 이동한 사용자를 방해하지 않는 범위에서 입력칸으로 복원한다. Enter 전송·Shift+Enter 줄바꿈·한국어 IME 조합 Enter 방지는 유지한다.
- 패널 높이와 footer 상한은 대화와 입력칸을 함께 보이게 유지한다. 결과는 서버 기준 시각·건수·페이지와 상세 이동을 함께 표시하며, 0건일 때 조건 조정 방법을 안내한다.

- 입력 영역은 사용자 시각 참조에 따라 PatternFly TextArea의 테두리를 이 컴포넌트 안에서만 제거하고 폼 전체의 focus-within 표시를 제공한다. 공통 디자인 토큰과 원형 Button을 사용하며, 입력 높이는 내용에 맞게 늘어나되 25dvh로 제한한다. 시각적 라벨 대신 접근 가능한 `질문` 이름과 단축키 설명을 유지한다.
- 평상시 하단 안내·제목·구분선은 숨기고, 글자 수는 1,800자부터 표시한다. 완료·저장 상태는 헤더 도움말에 포함하고 보조기술용 상태 알림은 유지한다. 실행·실패·연결 복구 상태는 하단에서 계속 제공한다. 팝오버의 Escape는 패널까지 접지 않는다.

- 조회 결과의 항목명·값은 두 열로 나란히 왼쪽 정렬한다. 값을 패널 우측 끝으로 보내지 않고, 매물 간 세로 여백은 작은 간격 토큰으로 유지한다.

## 검증 환경

- 2026-09-09 Windows Chrome 152에서 합성 HTTP/SSE 브라우저 13개 테스트를 통과했다. 1366×768·1920×1080의 전체 높이·메인 배치 보존과 360×740·720×500의 overflow/입력 노출, 초안·IME 이벤트·수동 재시도·이력 스크롤을 포함한다. 실제 앱 접속·패널 표시도 Windows Chrome으로 확인했다. 실제 AI 응답 품질·스크린리더 전체 준수·공유 dev 배포 검증은 포함하지 않는다.
- 브라우저 테스트의 `CHATBOT_BROWSER_WS_ENDPOINT`는 같은 Playwright 버전으로 실행한 외부 브라우저 서버에 연결한다. WSL에서 Windows Chrome을 사용하는 경우 이 값을 전달할 수 있다. 지정하지 않으면 기존 로컬 Chromium을 사용한다. `CHATBOT_SCREENSHOT_DIR`를 지정하면 합성 화면 캡처를 해당 경로에 저장한다.

검증: `npm run test:chatbot`, `npm run test:chatbot:browser`, `npm run typecheck`, `npm run build`. 브라우저 검증은 합성 HTTP 서버와 실제 SSE를 사용하고 기존 DB·모델에 접근하지 않는다.
