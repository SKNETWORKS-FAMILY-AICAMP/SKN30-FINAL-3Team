# Admin Operations & Data Safety

이 문서는 프로젝트 [개인정보 정책](../../../project-wiki/references/privacy/policy.md)을 UI에 적용하는 보조 규칙이다. 개인정보 처리의 정본은 해당 정책이다.

## 권한과 인증 상태

- UI의 숨김 또는 disabled 처리는 서버 권한 검증을 대체하지 않는다.
- 401, 403, 세션 만료, 읽기 전용과 일시적 오류를 구분한다.
- 권한 없는 기능은 존재 자체가 민감하면 숨기고, 기능 인지는 가능하지만 실행만 제한되면 이유와 함께 disabled 처리할 수 있다.
- 세션 만료 시 사용자가 입력 중인 비민감 데이터를 가능한 범위에서 보존하고 재인증 후 복구 여부를 명확히 알린다.
- 권한 변경 결과는 대상, 변경 전후 권한과 적용 시점을 확인할 수 있게 한다.

## 파괴적 작업

- 삭제, 비활성화, 권한 회수와 되돌릴 수 없는 변경은 danger action으로 표현한다.
- 확인 화면에 정확한 대상, 영향 범위, 되돌릴 수 있는지와 후속 결과를 표시한다.
- 일반 취소 버튼과 파괴적 실행 버튼을 시각적·문구상 명확히 구분한다.
- 이름 입력 같은 강화 확인은 고위험·대규모·복구 불가능 작업에 제한한다.
- 처리 중 중복 제출을 막고 성공, 실패와 부분 실패를 구분한다.

## 대량 선택과 작업

- 선택 건수와 범위를 항상 표시한다.
- 현재 페이지 선택과 필터 결과 전체 선택을 혼동하지 않게 한다.
- 필터, 정렬, 페이지 변경 시 선택 유지·초기화 정책을 화면에서 예측 가능하게 한다.
- 실행 전 대상 수, 필터 조건과 예상 영향을 확인한다.
- 부분 실패 시 성공·실패 건수, 실패 대상과 안전한 재시도 방법을 제공한다.
- 비동기 장기 작업은 진행 상태와 취소 가능 여부를 제공한다.

## 개인정보와 민감정보

- 업무 목적에 필요한 최소 컬럼만 기본 노출한다.
- 개인정보는 권한과 업무 필요에 따라 마스킹하고 전체 보기와 복사 기능을 별도 통제한다.
- 비밀번호, 토큰, 인증 헤더와 비밀값은 화면, URL, 오류 상세, Toast와 브라우저 로그에 노출하지 않는다.
- 검색어, 필터와 URL state에 개인정보가 들어갈 수 있는지 검토한다.
- 개발·테스트 화면에 실사용자 개인정보를 기본 사용하지 않는다.

## 내보내기와 복사

- CSV·Excel 내보내기는 허용된 컬럼과 현재 필터·선택 범위를 실행 전에 보여준다.
- 숨겨진 컬럼이 export에 포함되는지 명시하고 개인정보 최소화 원칙을 적용한다.
- Enterprise 기능이 필요한 export 형식은 라이선스 승인 여부를 확인한다.
- 복사·내보내기 완료 메시지에 원문 개인정보를 반복 노출하지 않는다.
- 감사 기록이 필요한 작업은 backend 계약과 함께 결정하며 UI 로그만으로 대체하지 않는다.

## 감사 가능성

중요한 운영 작업은 누가, 무엇을, 언제, 어떤 범위에 수행했는지 사용자가 확인할 수 있는 피드백을 제공한다. 감사 로그의 저장, 보존과 접근 권한은 backend 및 프로젝트 정책에서 별도로 결정한다.
