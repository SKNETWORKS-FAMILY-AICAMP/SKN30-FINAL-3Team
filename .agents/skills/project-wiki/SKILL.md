# 프로젝트 위키

## 시작 절차

1. 항상 저장소 루트의 `.agents/skills/project-wiki/references/index.md`를 먼저 읽는다.
2. 인덱스에서 현재 작업과 직접 관련된 문서만 선택해 읽는다.
3. 프로젝트 아키텍처, 정책 또는 모듈 경계를 바꾸기 전 프로젝트 결정 인덱스와 관련 ADR을 읽는다.
4. 모듈 내부 구조나 개발 방식을 바꾸기 전 해당 모듈 스킬의 references와 결정 인덱스를 읽는다.
5. 미확정 사항에 의존하는 작업이면 관련 프로젝트 또는 모듈의 `open-questions.md`를 읽는다.
6. 해당 모듈을 수정할 때 루트 `AGENTS.md`가 지정한 모듈 스킬도 함께 사용한다.

전체 참조 문서를 한꺼번에 불러오지 않는다. 각 인덱스에서 최종 문서로 직접 이동하고, 관련 없는 문서는 읽지 않는다.

## 요구사항 조회

- 기능 범위, 사용자 동작, 수용 기준 또는 요구사항 ID가 관련되면 루트 인덱스에서 `docs/requirements/index.md`로 이동한다.
- 정확한 ID가 있으면 `rg -n --glob '*.md' --glob '!sources/**' '<요구사항-ID>' docs/requirements`로 분할 정본을 찾는다.
- 개념으로 찾을 때는 요구사항 인덱스의 검색 의도와 ID 접두어를 먼저 보고 관련 파일만 읽는다.
- 둘 이상의 기능에 걸친 작업은 공통 요구사항과 각 기능의 관련 문서를 함께 읽는다.
- `docs/requirements/sources/`는 출처 대조가 필요할 때만 읽고 구현 판단의 일상적인 탐색 경로로 사용하지 않는다.

## 지식 판정

정보를 다음 상태로 구분한다.

- `출처`: 공신력 있는 외부 자료 또는 사람이 제공한 원문에서 확인된 정보
- `결정`: 팀이 명시적으로 승인한 프로젝트 또는 모듈 결정
- `구현됨`: 현재 저장소나 배포 환경에서 확인된 상태
- `계획됨`: 구현 의도가 있으나 아직 완료되지 않은 상태
- `제안`: 검토 중인 선택지
- `미확정`: 추가 합의나 검증이 필요한 내용

계획, 제안 또는 현재 구현을 승인된 결정으로 바꾸지 않는다. 사실과 추론을 구분하고, 확인할 수 없는 내용은 `미확정`으로 기록한다.

## 결정 소유권

- 여러 루트 모듈에 영향을 주는 프로젝트 아키텍처, 공통 계약, 개인정보, 개발환경과 Git 정책은 project-wiki에 기록한다.
- 한 모듈 내부의 구조, 라이브러리, 패턴, 테스트와 런타임 선택은 `.agents/skills/<module>/references/`에 기록한다.
- 모듈별 결정은 해당 모듈의 `references/decisions/index.md`와 ADR에서 관리한다.
- 모듈 결정이 다른 모듈의 공개 계약이나 프로젝트 경계를 바꾸면 project-wiki에도 별도 프로젝트 결정을 작성한다.
- 같은 결정을 프로젝트 위키와 모듈 references에 복제하지 말고 정본에 링크한다.

## 위키 갱신 절차

작업 중 다음과 같은 영구 프로젝트 지식이 생기면 같은 브랜치에서 project-wiki를 갱신한다.

- 승인된 프로젝트 요구사항 또는 정책
- 모듈 책임이나 시스템 경계의 변경
- API, 이벤트, 데이터 계약의 변경
- 개인정보 처리 방식의 변경
- 여러 모듈에 공통인 개발·운영 규칙
- 기존 프로젝트 결정을 대체하는 새로운 결정

모듈 내부의 선택은 해당 모듈 스킬의 갱신 절차를 따른다. 임시 디버깅 기록, 일회성 관찰, 개인 메모, 아직 확인되지 않은 추측은 기록하지 않는다.

갱신할 때 다음을 수행한다.

1. 하나의 정본 문서만 수정하고 같은 내용을 여러 파일에 복제하지 않는다.
2. 새 프로젝트 문서를 만들면 project-wiki의 `references/index.md`에 직접 링크와 읽을 조건을 추가한다.
3. 미확정 사항은 소유 범위의 `open-questions.md`에 질문, 영향, 결정 주체를 기록한다.
4. 프로젝트 아키텍처나 정책 결정만 project-wiki ADR로 남기고 `decisions/index.md`에 추가한다.
5. 의미 있는 project-wiki 변경은 `references/log.md`에 한 줄로 기록한다.
6. 외부 또는 사람용 원문을 반영하면 project-wiki의 `sources/manifest.yaml`에 출처와 반영 범위를 기록한다.

## ADR 규칙

- project-wiki ADR에는 프로젝트 공통 또는 모듈 간 결정만 기록한다.
- 승인된 ADR을 암묵적으로 덮어쓰지 않는다.
- 결정을 변경하면 기존 ADR을 보존하고 상태를 `대체됨`으로 바꾼다.
- 새 ADR에서 대체한 ADR 번호와 변경 이유를 명시한다.
- 팀이 승인하지 않은 기술 후보는 ADR이 아니라 소유 범위의 `open-questions.md` 또는 관련 문서의 `제안`으로 남긴다.

## 사람용 문서와의 관계

기획서, WBS, 스프레드시트와 같은 사람용 문서를 위키의 정본으로 취급하지 않는다. 개발 요청에서 새롭고 장기적인 프로젝트 지식이 확인되면 필요한 부분만 짧고 구조적인 Markdown 또는 YAML로 변환한다.

원문 전체를 복사하지 않는다. 위키에는 개발에 필요한 요구사항, 계약, 데이터 정의, 결정 및 제약만 유지한다.

## Git 규칙

위키와 모듈 결정 변경은 코드와 같은 작업 브랜치 및 PR에 포함한다. `main`에 병합된 문서만 팀이 승인한 공유 지식으로 간주한다. 브랜치와 PR 정책은 저장소 루트의 `.agents-rule/git.md`를 따른다.

## 토큰 절약 규칙

- 먼저 각 인덱스의 표와 상태만 읽고 필요한 문서만 연다.
- 문서 하나에는 하나의 책임만 둔다.
- 장황한 배경, 회의 대화, 중복 예시는 제거한다.
- 큰 원문은 위키에 복사하지 않고 manifest에 위치와 반영 범위만 남긴다.
- 문서가 100줄을 크게 넘거나 서로 다른 검색 의도를 가지면 분리한다.
