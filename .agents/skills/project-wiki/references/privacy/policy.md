# 개인정보 정책

## 원칙

- 목적에 필요한 최소 개인정보만 수집한다.
- 수집 목적, 처리 위치, 보존 기간, 접근 주체를 구현 전에 확인한다.
- 목적이 끝난 정보는 승인된 정책에 따라 삭제하거나 익명화한다.
- 개발·테스트에 실사용자 개인정보를 기본 사용하지 않는다.
- 외부 서비스 전송은 서비스, 전송 필드, 저장 여부와 리전을 확인한다.

## 분류

| 등급 | 예시 | 기본 처리 |
|---|---|---|
| 공개 | 공개 데이터, 공개 문서 | 출처와 이용 조건 기록 |
| 내부 | 비공개 기획, 운영 지표 | 팀과 승인된 시스템만 접근 |
| 개인정보 | 이름, 연락처, 사용자 식별자 | 최소 수집, 접근 제한, 보존 기한 필요 |
| 민감·비밀 | 인증정보, 토큰, 비밀번호, 고위험 개인정보 | 저장소·로그·프롬프트 기록 금지 |

## 구현 규칙

- 비밀값은 환경 변수 또는 비밀 관리 서비스에서 주입한다.
- 로그에는 토큰, 인증 헤더, 원문 개인정보, 전체 프롬프트를 남기지 않는다.
- 로그와 이벤트에 식별자가 필요하면 가능한 경우 내부 식별자나 가명값을 사용한다.
- S3, 데이터베이스, 큐와 백업의 접근 권한을 최소 권한으로 제한한다.
- 전송 구간 암호화와 저장 암호화를 활성화한다.
- OpenAI API, RunPod 또는 다른 외부 처리자에게 전송되는 데이터를 별도로 검토한다.
- 개인정보가 포함된 실패 메시지를 DLQ에 장기간 방치하지 않는다.

## 변경 검토

개인정보를 새로 처리하는 기능은 PR에 다음을 명시한다.

- 수집 필드와 목적
- 저장소와 처리 리전
- 접근 주체
- 외부 전송 대상
- 보존 및 삭제 방식
- 로그, 백업, 큐에 남는 정보

법률상 세부 보존 기간, 동의 문구와 정보주체 요청 절차는 서비스 기획 및 법률 검토 후 확정한다.
