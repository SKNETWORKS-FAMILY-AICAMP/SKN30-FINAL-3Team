# 아키텍처 경계

## 기본 원칙

- 루트 모듈은 책임과 배포 가능성을 기준으로 분리한다.
- 모듈 내부 상세 폴더 구조는 지금 고정하지 않는다.
- 상세 구조와 개발 방식은 각 모듈 스킬의 권장안을 따르고, 승인된 모듈 결정은 해당 스킬의 `references/decisions/`에서 관리한다.
- 하나의 기능이 여러 모듈에 걸치면 관련 모듈 스킬을 모두 적용한다.
- 모듈 간 내부 구현을 직접 참조하기보다 명시적인 API, 이벤트 또는 데이터 계약을 사용한다.

## 모듈 경계

| 모듈 | 포함 | 포함하지 않음 |
|---|---|---|
| frontend | 화면, 사용자 상호작용, API 클라이언트 | 서버 비즈니스 로직, 인프라 프로비저닝 |
| backend | 동기 API, 일반 배치, 큐 생산·소비, 서버 오케스트레이션 | AI 그래프 내부, 데이터 수집 파이프라인, IaC |
| ai | AI 워크플로, 실행 상태, 모델·프롬프트·도구 실행 | 일반 API 전체, DB·트랜잭션, 범용 큐 인프라 정의 |
| data | 수집, 정제, 변환, 운영 데이터 품질 검증 | 프론트엔드, API 서비스, 테스트 코드 |
| infra | Terraform 후보 기반 AWS 및 외부 인프라 정의, 비밀값 저장·접근 제어·런타임 주입 | 애플리케이션 런타임 로직, 애플리케이션 설정 해석 |

## AI–Backend 경계

AI의 모델·그래프 구현과 Backend의 API·영속성 구현은 [ADR-0006](../decisions/ADR-0006-ai-backend-boundary.md)의 프레임워크 중립 Python 인터페이스와 런타임 주입 경계를 따른다.

## 보류 사항

- `backend/` 안에서 API, 배치, 이벤트 처리를 추가 하위 모듈로 나눌지는 보류한다.
- 공통 패키지는 실제 중복과 안정된 소유권이 확인되기 전까지 만들지 않는다.
- 각 Python 모듈의 패키지 관리자, Python 버전, 내부 구조는 모듈 스킬 정리 시 결정한다.
