# ADR-0014: F3 프로토타입의 합성 입력은 마스킹 단계를 생략

- 상태: 승인됨
- 결정일: 2026-08-24
- 관련 계약: [F3 AI 계약](../contracts/f3-ai.md)
- 관련 정책: [개인정보 정책](../privacy/policy.md)

## 맥락

F3 포지션 카드 프로토타입은 케이스 테스트용 합성 장부와 상담 로그로 생성 품질과 실행 흐름을
먼저 검증한다. 이 단계에서 실사용자 데이터용 마스킹 파이프라인까지 함께 구현하면 프로토타입
검증 범위가 불필요하게 커진다. 반대로 합성 입력과 실제 개인정보 입력을 같은 문자열 계약으로
구분하지 않으면 임시 생략이 운영 기본값으로 남을 수 있다.

## 결정

- F3 프로토타입에서는 실제 인물을 나타내지 않는 seed·fixture·수기 합성 데이터만 사용한다.
- 합성 입력은 별도 마스킹 변환 없이 Provider 프롬프트에 전달할 수 있다.
- 요청은 `input_privacy_mode=SYNTHETIC_PROTOTYPE`을 명시하고 생성기 조립 지점도
  `allow_synthetic_prototype=True`로 별도 opt-in해야 한다. 기본 생성기는 이 모드를 거절한다.
- Backend Worker도 배포 환경에서 `F3_ALLOW_SYNTHETIC_PROTOTYPE=true`를 별도로 명시해야 한다.
  기본값은 `false`이며 opt-in이 없으면 활성 Worker는 DB·Provider 접근과 작업 선점 전에 기동을
  거절한다. 이 설정은 데이터가 합성임을 코드가 증명한다는 뜻이 아니라 검토된 합성 전용
  환경이라는 운영자 선언이다.
- 실사용자 이름·로그인 ID·연락처·생년월일이나 운영 DB의 상담 원문은 이 예외에 포함하지 않는다.
- 전체 프롬프트·전체 모델 응답과 상담 원문을 로그에 남기지 않는 기존 정책은 유지한다.
- 외부 Provider, 처리 리전과 저장 여부의 선택은 이 결정에 포함하지 않는다. 별도 결정 전에는
  합성 데이터 사용 여부와 무관하게 운영 외부 전송을 승인한 것으로 보지 않는다.
- 실제 F1 사용자 입력을 F3 Worker에 연결하기 전에 Backend 마스킹을 구현하고 요청을
  `input_privacy_mode=MASKED`로 전환한다. 이 전환이 프로토타입 예외의 종료 조건이다.

## 결과

프로토타입은 마스킹 구현을 기다리지 않고 합성 케이스로 진행할 수 있다. 대신 합성 모드는
명시적 이중 opt-in이라 실수로 기본 실행 경로가 되지 않는다. 합성 여부는 코드가 문자열만 보고
증명할 수 없으므로 팀은 실제 개인정보가 seed·fixture와 수기 입력에 섞이지 않도록 검토해야 한다.
실사용자 데이터를 연결하는 PR은 마스킹 구현, Provider 전송 항목과 처리 위치를 다시 검토한다.
