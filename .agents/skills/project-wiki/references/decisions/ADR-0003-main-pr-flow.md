# ADR-0003: 작업 브랜치에서 main으로 직접 PR

- 상태: 대체됨
- 결정일: 2026-08-12
- 대체 ADR: [ADR-0013](ADR-0013-dev-integration-pr-flow.md)

## 맥락

4명 규모의 MVP 팀에서 장기 `develop` 브랜치는 병합 흐름과 운영 상태 판단을 복잡하게 만들 수 있다.

## 결정

- 별도 `develop` 브랜치를 두지 않는다.
- 짧은 작업 브랜치에서 `main`으로 PR을 연다.
- 최소 1명 승인과 자동 검증을 거친다.
- 기본적으로 squash merge한다.
- `main`은 실행 가능하고 운영 배포 가능한 상태로 유지한다.
- 세부 운영 정책의 정본은 저장소 루트 `.agents-rule/git.md`로 관리한다.

## 결과

브랜치 흐름이 단순해진다. 대신 작은 PR, 브랜치 보호와 안정적인 자동 검증이 중요해진다.

## 대체 이유

실제 팀 개발과 전달 파이프라인은 `dev`를 통합 브랜치로 사용한다. 반복되는 PR 대상 브랜치 변경을 없애고 개발 통합과 릴리스 기준을 분리하기 위해 2026-08-24부터 ADR-0013으로 대체한다.
