# ADR-0017: Git 정본 기반 한 문서 산출물 운영

- 상태: 승인됨
- 결정일: 2026-08-25

## 맥락

강사 제출용 산출물, Google Drive 배포본, 관리 시트와 현재 프로젝트 위키·docs 사이에 내용과 버전 차이가 있다. 사람용 문서를 매 작업마다 전부 읽거나 최신 수정 시각만으로 정본을 선택하면 에이전트의 탐색 비용과 오판 위험이 커진다. 제출 상태는 규칙만으로 판단할 수 없어 사람이 소유해야 한다.

Codex에는 Google Drive 플러그인이 연결되어 읽기가 확인되었지만 실제 쓰기 권한은 아직 검증하지 않았다. Claude Code의 Google Drive·Sheets 연결 여부도 확인되지 않았다.

## 결정

- `docs/deliverables/registry.yaml`을 산출물 목록, Git 소스 상태와 외부 연결 식별자의 정본으로 사용한다.
- 이관된 문서의 본문, 근거 map과 검증·배포 이력은 Git에서 관리하고 Drive는 사람이 승인한 배포본으로 사용한다.
- 과거 Drive 전용 문서는 `external_pending_import`로 등록하고, 요청된 한 문서만 Git으로 이관한다. 여러 산출물을 한 작업에서 일괄 작성하거나 이관하지 않는다.
- 산출물과 프로젝트 정본이 충돌하면 최신 시각만으로 선택하지 않고 사람에게 결정을 요청한다.
- 제출 상태와 피드백 처리 여부는 사람이 판단한다. 에이전트는 현재 작업에서 사람이 대상과 정확한 값을 확인한 경우에만 상태 셀에 그대로 옮기며 레지스트리에 현재 상태를 복제하지 않는다.
- WBS는 `manual_on_request`로 두고 명시된 요청에서만 관리한다.
- v1은 사용자가 열거한 8개 산출물만 포함한다. 4주차, 중간 발표와 향후 6~7주차 산출물은 제외한다.
- 머신러닝/딥러닝 학습결과서와 학습한 ML/DL 모델은 `feat/ml-poc`의 `ml/field_proposal_reliability/`를 별도 Git 정본으로 사용한다.
- 외부 배포는 문서 검증과 별개 승인 단계다. Codex는 사람이 파일명·형식·업로드를 명시적으로 승인한 경우 새 Drive 파일을 만들고 읽기로 검증한 뒤, `3팀` 시트에서 제목으로 행을 다시 찾아 링크와 확인된 상태만 수정한다. 기존 Drive 파일을 덮어쓰거나 삭제하지 않는다.
- Claude Code는 연결 수단과 쓰기 권한이 검증될 때까지 Git 결과와 수동 배포 안내까지만 제공한다.

## 결과

에이전트는 전체 사람용 문서 집합을 매번 읽지 않고 레지스트리에서 한 문서의 소스와 배포 위치를 찾을 수 있다. Git 이관 전 문서는 명시적으로 전환 상태가 남고, 배포 자동화의 부분 실패가 기존 제출물을 파괴하지 않는다.

문서별 이관에는 반복 작업이 필요하고 Drive·시트 쓰기 권한은 첫 개별 배포까지 미검증으로 남는다. Claude Code의 외부 연결은 별도 확인이 필요하다.
