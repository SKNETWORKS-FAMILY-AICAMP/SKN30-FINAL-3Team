# ADR-0025: F2 신규 음성을 한 번 분석해 추천 장부와 유형별 필드를 반환한다

- 상태: 승인됨·코드 구현
- 결정일: 2026-09-07
- 승인 주체: 프로젝트 요청자
- 대체 범위: [Frontend ADR-006](../../../frontend/references/decisions/ADR-006-home-voice-intake.md)의
  신규 접수 2회 분석과 Frontend 상담 유형→장부 판정 소유 결정을 대체한다.
- 관련 계약: [F2 음성 분석 API](../contracts/api.md)

## 맥락

신규 음성메모는 아직 연결된 장부가 없는데도 기존 F2 요청이 `ledger_type`을 필수로 받았다. Frontend는
매물장으로 먼저 분석하고 결과가 매수문의이면 같은 음성을 구입장 기준으로 다시 보냈다. 이 구조는
매수문의마다 STT와 sLLM 추론을 두 번 실행하고, 첫 요청에서는 올바른 구입장 필드 제안을 만들 수
없었다. 또한 현재 장부가 모델 입력에 포함되어 상담 유형 분류를 불필요하게 유도할 수 있었다.

## 결정

1. 모델 입력은 STT 상담 텍스트와 양쪽 장부의 허용 필드만 포함한다. 모델은 상담 유형을 분류하고,
   매도의뢰이면 매물장 필드, 매수문의이면 구입장 필드, 기타상담이면 빈 필드를 한 번에 출력한다.
2. `ledger_type`은 유지한다. 다만 모델 입력의 현재 장부가 아니라, pipeline이 상담 유형에서 결정한
   추천 대상 장부를 뜻한다. 매도의뢰는 `매물장`, 매수문의는 `구입장`, 기타상담은 null이다.
3. 신규 접수는 `current_ledger_type`과 `current_fields`를 보내지 않는다. Backend는 한 번의 STT와
   한 번의 sLLM 분석 결과로 추천 장부와 해당 장부 필드 제안을 반환한다.
4. 기존 상세 분석은 `current_ledger_type`과 `current_fields`를 보낸다. 추천 장부가 현재 장부와
   다르면 `ledger_mismatch=true`로 두고 필드 제안을 억제해 잘못된 장부 수정은 계속 막는다.
5. 과거 요청 필드 `ledger_type`은 배포 전환 기간에만 `current_ledger_type` 별칭으로 받는다.
   신규 Frontend는 이를 보내지 않는다.
6. 기존 full-output 원천 데이터의 `ledger_type`·`ledger_mismatch`는 데이터 정합성 검증에 남긴다.
   모델 SFT·평가 prompt와 completion에서는 제외하며, 불일치 행은 올바른 대상 장부 필드 정답이
   비어 있으므로 단일 입력 자동 라우팅 학습·평가에서 제외한다.

## 결과

- 신규 매수문의도 음성 업로드, STT, sLLM 추론이 각각 한 번만 실행되고 구입장 필드가 바로 제안된다.
- 장부 추천 규칙은 Frontend와 모델 출력에 중복되지 않고 AI pipeline 한 곳에서 결정적으로 적용된다.
- `ledger_type` 응답을 사용하는 화면은 유지할 수 있지만 의미가 추천 대상 장부로 명확해진다.
- 기존 상세 화면의 잘못된 장부 덮어쓰기 방지는 유지된다.
- 새 5-key full-output 형식으로 adapter를 재학습·평가하고 배포해야 변경된 prompt에서의 품질을
  보장할 수 있다.

## 고려한 대안

- **Frontend에서 먼저 분류한 뒤 재분석**: 현재 구현처럼 정확한 장부 필드를 얻지만 매수문의의
  STT·추론 비용과 지연이 두 배이고 분류·추출의 입력이 달라질 수 있다.
- **모델이 `ledger_type`도 직접 출력**: 상담 유형과 같은 규칙을 모델이 두 필드로 중복 출력해
  모순 가능성이 생긴다. 상담 유형에서 결정적으로 파생하는 편이 검증과 호환성이 단순하다.
- **두 장부 필드를 항상 모두 추출**: 잘못된 장부 필드가 섞일 수 있어 유형별 허용 필드 경계를
  모델 prompt와 pipeline 검증에 유지한다.
