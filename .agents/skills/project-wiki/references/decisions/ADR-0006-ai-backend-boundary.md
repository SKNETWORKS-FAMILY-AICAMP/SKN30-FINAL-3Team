# ADR-0006: AI와 Backend의 프레임워크·영속성 경계 분리

- 상태: 승인됨
- 결정일: 2026-08-17
- 대체: ADR-0002

## 맥락

AI 모듈은 모델, 프롬프트와 멀티에이전트 비교 실험 때문에 변경 빈도가 높다. AI 구현이 DB·API에 결합되거나 Backend가 특정 그래프·프롬프트 구현에 결합되면 모델과 저장 기술을 독립적으로 변경하기 어렵다.

## 결정

- 루트 모듈은 `frontend`, `backend`, `ai`, `data`, `infra`로 둔다.
- AI 루트 모듈명은 실제 저장소 및 에이전트 지침과 일치하는 `ai`를 사용한다.
- 모듈 내부 상세 폴더 구조는 모듈별 스킬에서 결정하며 루트 공통 Python 환경과 `packages/`를 미리 만들지 않는다.
- Python 모듈은 각자 실행 환경과 의존성을 관리하고 `data/`에는 테스트 코드를 두지 않는다.
- `ai/`는 모델 어댑터, 프롬프트·구조화 출력, 워크플로·그래프, 실행 상태와 도구 정의를 소유한다.
- `ai/`는 FastAPI와 SQLAlchemy를 import하지 않으며 DB 스키마, 연결, 세션, 트랜잭션과 Repository를 알지 않는다.
- `backend/`는 API, 인증·인가, 애플리케이션 서비스, 트랜잭션, Repository와 AI 결과 저장을 소유한다.
- `backend/`는 LangGraph와 프롬프트를 직접 다루지 않는다.
- Agent와 그래프 노드는 DB를 직접 수정하지 않는다. DB 부수 효과는 프레임워크 중립 Python capability port로 요청하고, 주입된 Backend Tool Adapter가 검증과 트랜잭션 후 수행한다.
- 모듈 경계에는 표준 Python 타입과 프레임워크 중립 DTO·인터페이스만 사용한다. FastAPI·SQLAlchemy·LangGraph 타입은 경계 밖으로 노출하지 않는다.
- LangGraph와 구체적인 DB·체크포인트 제품의 채택 여부는 이 결정에 포함하지 않는다. 채택하더라도 각 구현은 위 경계 내부에 격리한다.

## 결과

DB와 API 기술 변경은 AI 그래프에 미치는 영향을 줄이고, 모델·프롬프트·오케스트레이션 변경은 Backend에 미치는 영향을 줄인다. 대신 공개 실행 계약과 capability adapter를 유지하고 양쪽의 계약 테스트를 작성해야 한다.

Agent가 유발하는 부수 효과는 Backend 검증과 트랜잭션을 반드시 거치므로 직접 DB 도구보다 구현 코드가 늘지만, 권한·일관성과 재실행 안전성을 한곳에서 통제할 수 있다.
