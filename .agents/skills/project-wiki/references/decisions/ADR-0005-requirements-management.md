# ADR-0005: 제품 요구사항을 분할 정본과 얇은 라우터로 관리

- 상태: 승인됨
- 결정일: 2026-08-14
- 관련 결정: ADR-0001을 제품 요구사항 관리 범위에서 보완

## 맥락

F1·F2·F3 통합 요구사항 원문은 1,839줄이며 공통 정의, 화면, 데이터, AI 처리, 비기능, 개인정보와 수용 기준처럼 서로 다른 검색 의도를 포함한다. 원문 전체를 에이전트가 작업마다 읽으면 탐색 비용이 크고 관련 없는 내용이 컨텍스트에 섞인다.

원문에는 안정적인 F1·F2·F3 요구사항 ID가 다수 존재하므로 ID 검색과 문서 라우팅을 결합할 수 있다. 동시에 사람이 제공한 원문과 팀이 승인한 결정의 상태를 구분해야 한다.

## 결정

- `docs/requirements/`의 공통·기능별 분할 문서를 제품 요구사항의 편집 정본으로 사용한다.
- 제공받은 원문은 `docs/requirements/sources/`에 변경하지 않는 출처 스냅샷으로 보존하고 manifest에 체크섬과 반영 범위를 기록한다.
- `docs/requirements/index.md`를 요구사항 전용 라우터로 사용하고 project-wiki 루트 인덱스에서 직접 연결한다.
- 에이전트는 정확한 ID가 있으면 출처 폴더를 제외한 분할 정본을 검색하고, 개념 검색은 라우터에서 관련 파일을 선택한다.
- project-wiki에는 요구사항 전체를 복제하지 않고 공통 아키텍처, 계약, 개인정보 정책과 승인된 결정만 반영한다.
- 요구사항 ID와 구현·테스트 경로는 별도 추적 파일에서 연결하며 상세 요구사항 문장을 복제하지 않는다.
- 저장 위치와 승인 상태를 분리한다. 제공 문서에서 옮긴 내용은 팀 승인 전까지 `출처` 상태를 유지한다.

## 결과

에이전트는 긴 통합 원문 대신 관련 파일만 읽을 수 있고, 정확한 ID 검색으로 요구사항을 직접 찾을 수 있다. 출처와 편집 정본이 함께 존재하므로 변경 시 changelog와 manifest를 확인해야 하며, 통합 문서가 필요할 경우 분할 정본에서 생성해야 한다.
