# 한 문서 산출물 운영 흐름

## 대상 선택과 사전 확인

1. 사용자 요청을 레지스트리의 정확한 `artifact_id`, `title` 또는 `sheet_row_key` 한 건에 연결한다.
2. 일치 항목이 없거나 둘 이상이면 사람에게 대상 한 건을 요청하고 작업을 시작하지 않는다.
3. `week: 4`인 요청은 v1 범위 밖임을 알리고 중단한다.
4. WBS는 현재 요청에 WBS 읽기·수정이 명시되지 않았으면 중단한다.
5. 대상의 소스 모드에 따라 그 문서와 관련된 정본만 읽는다. 전체 Drive 폴더, 전체 관리 시트 또는 모든 프로젝트 문서를 일괄 탐색하지 않는다.

## 작성·대조·검증

1. `external_pending_import`는 대상 Drive 파일을 출처로 읽고, 관련 project-wiki·docs·코드만 찾는다.
2. `git_branch`는 `source_ref`의 `source_paths`만 확인하며 현재 브랜치에 존재한다고 가정하지 않는다.
3. 기존 산출물과 Git 정본의 차이를 사실, 충돌, 미확정으로 나눈다.
4. 최신 수정 시각만으로 충돌을 해결하지 않는다. 사용자 결정이 없으면 영향과 선택지를 보고하고 멈춘다.
5. 결정된 내용만 대상의 `content`와 `source-map.yaml`에 반영한다.
6. 문서 형식, 링크, 표와 이미지 등 대상 형식에 맞는 검증을 수행한다.
7. 대상 한 건의 결과를 보고하고 종료한다. 다른 문서 작업을 이어서 수행하지 않는다.

## 외부 배포 승인 조건

다음이 모두 충족되어야 배포를 시작한다.

- 대상 산출물이 정확히 한 건이다.
- Git 정본과 출력 파일 검증이 완료되었다.
- 사람이 이번 요청에서 출력 파일명, 형식과 Drive 업로드를 명시적으로 승인했다.
- 상태 셀도 바꾸려면 사람이 대상과 정확한 상태값을 이번 요청에서 확인했다.

작성·검증만 요청한 경우에는 배포 승인이 없는 것으로 처리한다.

## Codex Drive·시트 배포

1. Google Drive 플러그인의 Drive 및 Sheets 스킬에서 현재 쓰기 안전 절차를 읽는다.
2. 레지스트리의 대상 폴더를 다시 확인한다.
3. 사람이 승인한 고유 파일명으로 새 파일을 업로드한다. 기존 파일을 덮어쓰거나 삭제하지 않는다. 같은 이름이 이미 있으면 업로드 전에 사람에게 확인한다.
4. 업로드 결과를 Drive 메타데이터로 다시 읽어 파일 ID, URL, 폴더와 파일명을 검증한다.
5. 관리 스프레드시트 메타데이터를 읽어 정확한 `3팀` 탭과 현재 `sheetId`를 확인한다.
6. 헤더와 필요한 데이터 범위만 읽는다. 저장된 행 번호를 사용하지 않고 `산출물 구분` 열에서 `sheet_row_key`를 정확히 검색한다.
7. 일치 행이 0개 또는 2개 이상이면 시트를 수정하지 않고 중단한다.
8. 대상 링크·상태 셀의 값, 서식과 데이터 검증을 읽는다.
9. `산출물 링크\n(구글 드라이브 업로드)` 셀을 검증된 새 URL로 바꾼다.
10. 사람이 상태를 확인하지 않았으면 `상태` 셀은 그대로 둔다. 확인했다면 허용된 값인지 검사한 뒤 받은 값을 그대로 입력한다.
11. 관련 변경은 하나의 일관된 batch로 적용하고 대상 셀을 다시 읽어 확인한다.

행 번호와 열 문자는 시트 정렬·삽입으로 바뀔 수 있으므로 레지스트리에 저장하지 않는다. 열은 매번 헤더로 찾는다.

## 실패 처리

- Drive 업로드가 실패하면 시트를 수정하지 않는다.
- 업로드 후 시트 처리가 실패하면 업로드 파일을 삭제·덮어쓰기하지 않는다.
- 성공한 단계, Drive 파일 ID·URL, 실패한 단계와 재개 조건을 보고한다.
- 검증되지 않은 셀이나 다른 행을 복구 목적으로 수정하지 않는다.

## Claude Code 경계

Claude Code의 Google Drive·Sheets 연결 수단과 쓰기 권한은 미확정이다. 검증 전에는 Git 본문·출력과 사람이 수행할 배포 안내까지만 제공하고 Drive 업로드나 시트 수정을 시도하지 않는다.
