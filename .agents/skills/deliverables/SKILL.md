# 산출물 운영

이 스킬은 사람용 제출 문서와 에이전트용 프로젝트 지식의 정합성을 한 문서씩 관리한다. 산출물 목록과 외부 연결 정보는 [`docs/deliverables/registry.yaml`](../../../docs/deliverables/registry.yaml)을 정본으로 사용한다.

## 시작 절차

1. 저장소 루트 `AGENTS.md`와 project-wiki의 `references/index.md`를 읽는다.
2. 레지스트리에서 작업 대상이 정확히 한 건인지 확인한다. 대상이 없거나 여러 건이면 파일을 읽거나 수정하기 전에 사람에게 한 건을 선택하도록 요청한다.
3. 대상의 `management_mode`, `source_mode`, `source_ref`, `source_paths`를 확인한다.
4. 4주차 산출물은 처리하지 않는다. WBS는 현재 요청에 WBS 작업이 명시된 경우에만 읽거나 수정한다.
5. 문서를 등록하거나 레지스트리를 바꿀 때는 [레지스트리 계약](references/registry-schema.md)을 읽는다.
6. 문서를 작성·대조·검증·배포할 때는 [한 문서 운영 흐름](references/workflow.md)을 읽는다.

## 정합성 경계

- 프로젝트 요구사항, 아키텍처, 계약과 정책은 project-wiki와 각 정본 문서에서 확인한다.
- 기존 Drive 산출물이 Git 정본과 충돌하면 수정 시각이나 문서 순서만으로 어느 한쪽을 채택하지 않는다. 충돌 내용과 영향을 사람에게 제시하고 결정을 기다린다.
- `external_pending_import` 문서는 선택된 한 건만 Git으로 이관한다. 다른 산출물의 본문이나 Drive 파일을 함께 읽거나 수정하지 않는다.
- 작업이 끝나면 대상 문서의 변경과 검증 결과만 보고하고 멈춘다. 다음 문서를 연속해서 작성하지 않는다.

## 제출 상태와 외부 쓰기

- 제출 상태, 제출 완료 여부와 피드백 처리 완료 여부를 파일·링크·날짜에서 추론하지 않는다.
- 상태값은 사람이 현재 작업에서 대상 산출물과 정확한 값을 확인한 경우에만 관리 시트에 그대로 옮길 수 있다. 레지스트리에는 상태값을 저장하지 않는다.
- 문서 작성·검증 요청은 Drive 업로드나 시트 수정을 허가하지 않는다. 외부 배포는 사람이 파일명·형식·업로드를 명시적으로 승인한 별도 요청에서만 수행한다.
- Codex에서는 연결된 Google Drive 플러그인의 Drive·Sheets 안전 절차를 읽고 사용한다. Claude Code에서는 연결 수단과 쓰기 권한이 검증될 때까지 외부 쓰기를 중단하고 Git 결과와 배포 안내만 제공한다.
- 외부 쓰기 일부가 실패하면 성공한 업로드를 삭제하거나 기존 파일을 덮어써 복구하려 하지 않는다. 확인된 부분 완료 상태와 후속 조치만 보고한다.

## 완료 조건

- 한 산출물만 변경되었다.
- 사용한 Git 정본과 확인 커밋을 기록했다.
- 충돌과 미확정 사항을 숨기지 않았다.
- 문서 형식별 검증을 수행했다.
- 외부 배포가 있었다면 Drive 파일과 시트 셀을 다시 읽어 확인했다.
- 사람 확인 없는 제출 상태가 기록되지 않았다.

레지스트리를 변경한 뒤 `python3 .agents/skills/deliverables/scripts/validate_registry.py`와 skill-creator의 `quick_validate.py`를 실행한다.
