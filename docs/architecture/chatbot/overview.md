# 업무 챗봇 도입·구현 타당성 검토

**권장안: 읽기 전용 자연어 조회, 기존 F2 화면 연결, SSE 진행 표시, 제한된 멀티턴부터 도입한다.**
F3 연동은 사용자 요청대로 개발 보류하고, 공공 시세 기능은 선택 확장으로 둔다.
기능 상세 정본은 [요구사항](../../requirements/chatbot/overview-and-scope.md)이다. [사용자 합의](../../requirements/sources/chatbot-design-decisions-2026-09-08.md)와 [구현 요청](../../requirements/sources/chatbot-implementation-scope-2026-09-08.md)에 따라 1차 코드를 구현했다. 이 문서의 도입 효과·공수는 기획 당시의 추정이며, 현재 코드·Luna 평가·Qwen 보류·배포 범위는 [구현·검증](implementation-and-validation.md)이 정본이다. 팀 병합 검토와 공유 dev 적용은 별도다.

## 도입 근거와 한계

| 근거 | 기대 효과·검증할 가설 |
|---|---|
| [F1 검색](../../requirements/f1/search.md)은 여러 컬럼·로그에서 대상을 찾는 업무를 정의함 | 자연어를 조건으로 바꾸면 필터 위치·코드를 몰라도 조회 가능. 실제 시간 절감은 사용자 비교로 확인 |
| F2 진입과 장부·할 일 조회가 여러 화면에 분산됨 | 추천 질문과 실행 버튼으로 기능 발견·시연 경로를 단순화 |
| 범용 Provider·구조화 생성과 조회 서비스가 이미 있음 | 새로운 모델 서버·장부 DB 없이 기능별 경계를 재사용할 여지가 큼 |
| [F3 역할](../../requirements/f3/overview-and-common.md)은 양측 입장 판단임 | 챗봇의 조건 조회와 F3 판단을 분리해 중복 에이전트 개발을 줄임 |
| [현재 MVP](../../requirements/common/mvp-scope-and-evaluation.md)는 F2·F3 평가 우선 | 챗봇은 추가 범위다. 사용자 가치가 작거나 핵심 평가를 지연시키면 조회 도구 수부터 축소 |

정확한 동·호 검색이나 반복 필터는 기존 UI가 더 빠를 수 있다. 모델 해석 시간·오해 가능성이 추가되므로 모든 조회를 챗봇으로 옮길 근거는 없다.
포트폴리오 가치는 단순 말풍선보다 자연어 조건 정확도, 권한 격리, 두 모델 비교와 실제 단계 공개를 측정해 보여줄 때 생긴다.

## 현재 기반과 필요한 추가 작업

| 확인한 기반 | 현재 상태 | 챗봇에서 추가할 일 |
|---|---|---|
| [Frontend 의존성](../../../frontend/package.json) | React 19·TypeScript·Vite·PatternFly 6·AG Grid 사용 | 셸의 플로팅 패널·결과 카드·문맥·SSE 소비 |
| [장부 조회](../../../backend/src/domain/property_ledger/repository.py) | 사무소 범위·삭제 제외·조건·페이지 조회 코드 존재 | 챗봇용 제한 DTO, 금액·면적 범위 등 빠진 필터와 집계 추가 |
| [장부 API](../../../backend/src/api/property_ledger.py) | 선택값 필터 중심. 자연어 가격 범위가 그대로 지원되지는 않음 | 기존 서비스/조회 로직을 확장하고 조회 카드용 최소 응답 구성 |
| [Time Keeper](../../../backend/src/domain/time_keeper/service.py) | 날짜 기반 조회 구현 | 종류·기간 정확 필터와 개수 제한 처리. 잘린 목록만 받아 전체를 센 것으로 답하지 않음 |
| [F2 API](../../../frontend/src/features/f2/api/f2Api.ts) | 신규 음성은 한 번 분석. 기존 모달·검토·draft 흐름 존재 | 셸 액션 연결. 과거 [프론트 설명](../f2/frontend-voice-field-population.md)의 2회 분석 설명보다 최신 코드·ADR-0028을 우선 |
| [F2 실행](../f2/online-runtime.md)·[F3 실행](../f3/online-runtime.md) | F2 동기, F3 polling. 두 기능의 SSE는 미구현 | 챗봇 SSE를 새로 구현. F2 내부 진행 SSE까지 완료된 것으로 취급하지 않음 |
| [AI Provider](../../../ai/src/brokerage_ai/providers/registry.py) | 모델별 어댑터·구조화 검증 기반 존재 | 챗봇용 공개 facade·프롬프트·조건 스키마·평가 추가. F3 프롬프트 재사용은 하지 않음 |

배포 환경을 직접 점검한 결과는 아니다. 기존 문서의 오래된 설명과 작업 트리의 코드 상태를 구분한 검토다.

## 복잡성과 작업량 추정

1인일은 담당자 한 명의 집중 개발 1일이다. 기존 코드에 익숙한 담당자, 합성 데이터, 사용 가능한 모델 endpoint를 전제로 한 **미검증 추정**이며 병렬 작업 시 달력 일수와 다르다.

| 작업 | 복잡성 | 예상 추가 공수 | 큰 변수 |
|---|---|---|---|
| 조회 질문·스키마·평가 기준 확정 | 낮음~중간 | 1~2인일 | 실제 필요한 조건 수 |
| 조회 도구 3종·권한·조건 해석·템플릿 답변 | 중간 | 3~5인일 | 기존 필터 부족, 금액·면적 정규화 누락 |
| 플로팅 UI·추천 질문·F2 연결 | 낮음~중간 | 1.5~2.5인일 | 기존 상세·모달 전환과 미저장 상태 |
| 실행 생성·SSE 구독·취소·오류·배포 경로 확인 | 중간 | 1~2인일 | 프록시 버퍼링과 모델 호출 취소 |
| DB 3테이블·이력/상태 복원·삭제/중복/중단 경합 검증 | 중간 | 2~4인일 | 기존 메모리 전용안 대비 추가 공수 |
| 최근 2회 문맥·대상 선택 | 중간 | 0.5~1.5인일 | 모호한 지시와 조건 오염 |
| 두 모델 평가·통합·회귀 확인 | 중간 | 2~3인일 | 모델 repair·GPU 혼잡 |
| **1차 합계** | **중간** | **11~20인일** | **GPU 최초 구축·외부 승인 대기는 제외** |
| 선택 실거래 요약 | 중간~높음 | +3~6인일 | 키·응답 확인, 단지 매핑·정정·집계 |
| F3 실행 통합 | 높음 | 보류, 재산정 | 실행 ID·중복·장기 작업 복구·판정 UX |

1차 최종 범위는 조회 3종과 F2 연결이다. 구현 순서는 매물 조회·저장/복원 수직 슬라이스를 먼저 완성하고 구입장·할 일을 더한다.
2026-09-23 종료 제약과 F2/F3 평가 시간을 고려해 담당자 배분은 별도 일정 조정이 필요하다.

## 사용할 스택과 선택 이유

| 계층 | 권장 | 이유 |
|---|---|---|
| UI | 현재 React·TypeScript·PatternFly, fetch·ReadableStream·AbortController | 기존 셸·폼·패널 재사용. 전용 채팅 SDK나 별도 전역 상태 라이브러리를 먼저 넣지 않음 |
| API·조회 | 현재 Python 3.13·FastAPI·Pydantic·SQLModel/SQLAlchemy·PostgreSQL | 인증·조회·정확한 계산을 Backend에 유지. 새 저장이 필요하면 기존 Yoyo 경로 사용 |
| AI | 기존 Provider·구조화 출력·repair, 제한된 선형 workflow | 의도→검증된 도구→결과로 충분. LangGraph는 설치돼 있지만 챗봇 채택을 강제하지 않음 |
| 모델 | local Luna / dev Qwen 27B 범용 경로 | [모델 검토](runtime.md)의 환경·성능 조건 적용 |
| 상태·전송 | PostgreSQL 대화·메시지·요청 3테이블 + 실행 생성/GET SSE 구독 | 저장된 상태·결과로 새로고침 복원. Redis·SSE 이벤트 저장·작업 자동 재개는 1차에 추가하지 않음. [저장 설계](persistence.md) |
| 검색 확장 | 우선 관계형 조건 조회 | 벡터 DB·RAG는 구조화 조건 조회에 불필요. 전역 의미 검색 필요성이 확인될 때 별도 비교 |

## 확장 순서와 비용

각 도구는 이름·입출력 스키마·권한·시간/건수 상한·결과 카드 종류를 갖는다. 기능 추가 시 도구·Backend capability·카드·평가 사례를 함께 추가한다.
F3는 준비될 때 별도 실행 어댑터로 등록하고 기존 실행 상태를 이용한다. 대화 실행 영속화와 GET 구독은 1차에 포함하되, 단계 재생·작업 자동 재개용 저장은 해당 요구가 생길 때 추가한다.
local 비용은 실제 입력·출력·repair 토큰으로, dev는 GPU 가동 시간·저장·전송·기존 F3와의 경합으로 측정한다. 가격 견적이나 신규 GPU 구매·배포는 이번 검토에 포함하지 않는다.
