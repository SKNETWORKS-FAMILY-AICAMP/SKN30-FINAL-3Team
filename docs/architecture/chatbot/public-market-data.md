# 선택 기능: 공공 API 기반 실거래 요약 검토

조사일: 2026-09-08. 공식 소개·개발 문서를 확인했으며 인증키 발급·실제 데이터 API 호출·지역별 품질 검증은 수행하지 않았다.
챗봇 1차 필수 범위가 아니다. [요구사항](../../requirements/chatbot/overview-and-scope.md) · [도입 검토](overview.md)

## 확인한 공식 API

| 후보·공식 출처 | 확인된 제공 방식 | 적합한 질문 | 제약·추가 확인 |
|---|---|---|---|
| [국토교통부 아파트 매매 실거래가](https://www.data.go.kr/data/15126469/openapi.do) | 법정동 코드 앞 5자리와 계약년월 6자리로 지역·월 조회, REST/XML | “이 단지의 최근 매매 거래를 보여줘” | 소개상 층 정보 제공, 동 정보는 등기 완료 조건. 특정 호수의 현재 가격을 식별하는 용도로 사용하지 않음 |
| [국토교통부 아파트 전월세 실거래가](https://www.data.go.kr/data/15126474/openapi.do) | 지역 코드·계약년월 조회, 신고·확정일자 자료, REST/XML | “같은 면적의 최근 전세 거래를 보여줘” | 동/호 정보 미제공. 전세·보증부 월세 구분과 금액 단위는 실제 응답 명세로 확정 |
| [한국부동산원 R-ONE Open API](https://www.reb.or.kr/r-one/portal/openapi/openApiIntroPage.do) | 인증키 신청 후 부동산 통계 연계 | “이 지역 가격지수 추이를 보여줘” | 지역 통계와 특정 단지·호수 가격을 혼동하지 않음. 통계표·지역·항목 코드 선택 필요 |

국토부 두 API 소개는 무료·이용허락범위 제한 없음·개발/운영 자동승인·개발계정 신청 가능 트래픽 10,000으로 표시한다.
이 숫자의 적용 단위와 실제 계정별 한도·변경 공지는 신청 시 재확인한다. 무료 데이터라고 전체 운영비·무제한 호출·SLA가 보장되는 것은 아니다.
[R-ONE 개발가이드](https://www.reb.or.kr/r-one/portal/openapi/openApiDevPage.do)는 XML/JSON, 페이지 조회와 통계표·항목 지정을 설명하며 외부 브라우저 직접 호출 대신 서버 중계를 요구한다.
표본 호출 건수는 같은 가이드의 설명과 예시에 차이가 있어 보장값으로 채택하지 않는다. 인증된 실제 응답으로 확인한다.

## 권장 첫 범위

**아파트 매매 실거래 요약 한 종류부터** 시작한다. 대상 단지·전용면적 범위·최근 3~6개월을 사용자가 확인한 뒤 거래 사례와 집계값을 보여준다.
이는 과거 신고 거래의 요약이다. 현재 호가·감정가·적정 매수가·향후 상승 예측 기능으로 정의하지 않는다.
전월세와 지역 가격지수는 매매 조회의 단지 매핑·출처·날짜 표시가 검증된 뒤 추가한다.

| 출력 제안 | 처리 원칙 |
|---|---|
| 거래 목록 | 계약일·면적·층·거래금액 등 실제 제공 필드만 표시. 누락은 정보 없음으로 표시 |
| 집계 | 같은 거래 종류·단지·면적 기준에서 건수·중앙값·최소/최대. Backend 코드로 계산 |
| 비교 | 조건과 기간이 같은 집합끼리 비교. 전세와 월세 보증금, 다른 면적 집합을 섞어 평균내지 않음 |
| 근거 | 제공기관·출처 링크·조회 범위·계약 기간·수집 시각·유효 표본 수 |
| 표본 부족 | 초기 제안으로 5건 미만이면 거래 사례만 보여주고 추세 판단은 보류. 임계값은 팀 검토 대상 |
| 정정·해제 | 실제 API의 해제/정정 필드와 식별 규칙을 확인해 반영. 확인되지 않은 필드가 있다고 가정하지 않음 |

최신 월은 신고 지연·정정 등으로 집합이 달라질 수 있으므로 조회 시각을 고정해 표시하고 이후 재조회로 갱신한다.
단순 월별 중앙값 변화는 거래된 면적·층 구성의 차이로도 생길 수 있다. 동일 조건을 맞춰도 인과적 가격 상승 설명으로 단정하지 않는다.

## 구현과 복잡성

1. Backend가 공개된 지역·월 인자만으로 API를 호출한다. API 키와 고객 질문·연락처·상담 원문을 외부 요청에 함께 보내지 않는다.
2. 허용된 API 호스트·서비스만 사용하고 모델이 임의 주소를 구성하지 못하게 한다. XML 파싱은 외부 엔티티·문서 크기·timeout을 제한한다.
3. 법정동 코드·주소·단지명·전용면적으로 내부 단지와 후보를 매핑한다. 이름만 같은 단지를 자동 병합하지 않고 모호하면 사용자 선택을 받는다.
4. 여러 달·페이지의 성공 여부를 확인한 뒤 집계한다. 일부 월 조회 실패를 전체 기간 0건으로 답하지 않는다.
5. 지역·월·서비스를 키로 제한된 캐시를 두고 수집 시각·만료를 표시한다. 초기 24시간 TTL은 후보이며 정정 재조회·최종 갱신 정책을 별도 확정한다.
6. AI에는 검증된 집계와 허용된 설명 근거만 제공한다. 모델이 기억하는 과거 시세로 API 실패를 메우지 않는다.

초기 실행 중 API 중계·집계는 Backend가 소유한다. 대량 이력 적재·정기 갱신을 실제로 도입할 때 데이터 파이프라인 소유권을 `data/`와 협의한다.
외부 API adapter·카드 추가만으로 끝나지 않고 지역 코드·단지 매핑·결측·정정·표본 편향 처리가 필요하므로 **추가 3~6인일**을 추정한다. 키 발급과 데이터 품질에 따른 대기는 제외한다.

## 착수 전 확인할 것

- 실제 API key로 시연 지역의 최근 6개월 응답을 받아 필드·금액 단위·페이지·오류·호출 한도를 확인한다.
- 동명이름·주소 변형·거래 해제·빈 월·부분 응답 사례에서 다른 단지나 잘못된 거래가 섞이지 않는지 확인한다.
- 전체 페이지 집계와 수작업 검산을 비교한다. 결과가 없을 때 기간을 자동 확장하지 않고 사용자 선택을 받는다.
- `시세분석`이라는 명칭 대신 `최근 실거래 요약`을 쓸지와 F4 가격 평가 제외 범위의 관계를 합의한다.
- API 데이터 제공 조건은 연동 착수 시 다시 확인한다. 본 조사는 실제 가격 추천·법률 해석 또는 데이터 품질 보증을 제공하지 않는다.
