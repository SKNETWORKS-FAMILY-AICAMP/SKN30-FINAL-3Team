# F3 확장 기획 검토와 검증 계획

기준 dev `5950681`, 브랜치 `docs/f3-expansion-plan`. 최신 origin/dev를 fetch한 뒤 별도 워크트리에서 작성했다.
[기능 정의](../../requirements/f3/judgment-results-list.md)를 먼저 작성한 뒤 공인중개사 페르소나 서브에이전트에 검토를 요청했다.
추가로 챗봇 확장 조사와 API·화면 일관성 검토를 독립 서브에이전트가 수행했다. 런타임 구현·배포·실제 모델 호출은 하지 않았다.

## 필요성 판단

페르소나는 아파트 매매·전세·월세를 취급하는 2~3인 중개사무소의 숙련 중개사를 가정했다.
이는 **가상 역할 시뮬레이션이며 실제 공인중개사 인터뷰·사용성 실험이 아니다.** 시장 필요성이 검증됐다고 표현하지 않는다.

| 대안 | 역할 검토에서 기대한 효용 | 한계와 판단 |
|---|---|---|
| 상세의 포지션 카드만 | 통화 전 당사자 사정·협상 여지 복기 | 열지 않은 장부의 연결을 발견하기 어려움. 근거 자료로 유지 |
| 상세에서 수동 판정 | 지금 보는 대상에 집중 | 대상마다 이동·실행·대기 반복. 가격 인하 후 가능한 상대를 기억해야 함 |
| 조건부 자동 판정 + 결과 목록 | 다른 업무 중 준비된 연결·이유를 돌아와 확인 | 미판정 누락·이전 분석 오인·반복 연락을 방지하는 조건으로 우선 권고 |

결론은 **독립 카드 화면보다 결과 목록이 연결 대상을 찾는 업무에 더 적합하다는 가설이 타당하다**이다.
자동화의 성과는 실행 횟수보다 놓칠 연결의 발견·다음 확인 대상 선택 시간으로 평가한다.
목록을 다시 열 계기가 없거나 기존 장부 검색만으로 충분하면 효용은 낮아질 수 있다.

## 페르소나 발견 사항과 반영

| 사례/우선순위 | 발견 사항 | 기획 반영 |
|---|---|---|
| 새 매물/손님, MUST | 양방향 발견과 동료 담당 확인 필요 | 매물/손님 기준 탭·장부 상세 연결·대표 후보 담당자/미지정 |
| 18건 중 5건만 판정, MUST | 5건 전부 기각이면 기본 필터에서 잔여 13건을 놓칠 수 있음 | 미판정 전용 필터와 항상 보이는 건수 진입. 미판정≠기각·무후보 |
| 오래된 조건, MUST | 이전 강함이 현재 연락 우선순위로 오해됨 | 행의 등급 옆 이전 분석 표시, 기본 최신 추천 집계 제외, 현재/당시 조건 구분 |
| 반복 상대, MUST | 동료가 이미 연락한 쌍인지 알기 어려움 | 기존 상담·피드백 읽기와 원본 이동. 쌍별 확인 기록과 일반 상담 구분. 기록 없음≠미연락 |
| 이미 연락함, MUST | 영구 제외·거절로 처리하면 가격 변경 뒤 기회가 사라짐 | 기존 피드백 의미 유지. 새 업무 완료/영구 숨김 상태 도입 안 함 |
| 가격 인하, MUST | 같은 등급 재등장만으로 재검토 이유 불명확 | 현재 핵심 조건·기록으로 확인한 변경 이유. 실제 비교 없이 ‘새 후보’ 표시 안 함 |
| 매물/손님 탭, SHOULD | 첫 탭보다 이후 업무 맥락 유지가 중요 | 최초 매물 기준, 이후 탭·필터·선택 복원 |
| 필터 과밀, SHOULD | 장부 하나를 더 관리하는 느낌 | 주요 필터·담당자·검색 우선, 거래유형/단지 상세 필터. 사무소 전체 기본+내 담당 바로가기 |
| 메뉴 명칭, SHOULD | 교차 판정 용어가 현업에 낯설 수 있음 | 이번 명칭 제안 유지, 실제 검증에서 ‘연결 후보’와 비교 |
| 연락 시스템 확장 | 기록 필요성이 CRM 신설로 커질 위험 | 기존 읽기만 추가. 연락 완료·발송·업무 배분·새 알림·개인 읽음은 후속 |

상담 기록이 특정 매물·손님 쌍의 연락 사실을 보장하지 않으면 ‘최근 상담 기록’으로 표시한다.
확인된 연락 피드백만 해당 쌍의 기록으로 연결하며 AI가 연락 여부를 추정하지 않는다.

## 기존 정책과 기술 검토 반영

페르소나가 제기한 top-5/‘컷 없음’ 충돌은 원문·변경 이력을 추가 확인했다.
[F3-BR-12·13](../../requirements/f3/delegates-and-brokerage.md)과 2026-08-31 변경 이력에서 최초 5건은 사용자 승인이다.
이번 기획은 그 상한을 유지한다. F3-CR-05의 ‘판정 자체는 전부’ 잔존 문구를 전체 자동 판정 승인으로 확대 해석하지 않는다.
조건부 자동 전체 흐름은 기존 저장=카드 정책의 변경 제안이므로 ADR-0018 후속 개정이 필요하다.

API·화면 일관성 검토에서 다음 네 항목을 [계약안](expansion-contracts.md)에 반영했다.

- result_id는 완료된 match_evaluation snapshot 식별자. 입력/근거 변경에 새 결과를 만들고 단순 재검증과 구별한다.
- 페이지 밖 선택 후보를 별도 반환하고 snapshot 소속을 검증한다. 미판정 후보에 가짜 카드·등급을 만들지 않는다.
- 공개 차단을 정상 후보 0건과 구분한다. 차단 시 건수 null·안전한 상태만 반환한다.
- 같은 입력의 카드 전용 실행을 사용자 전체 요청이 원자적으로 승격하고 자동 이벤트가 다시 낮추지 않는다.

[챗봇 검토](chatbot-extension.md)는 공통 Backend 조회/접수·권한·수명주기 재사용을 권고한다.
전용 ADR은 확인되지 않았으며 연동 의도는 기존 요구사항·아키텍처의 후속 항목으로 확인했다.

## 실제 사용자 검증 제안

다음은 실행 전 계획이다. 실험 결과나 승인된 SLA가 아니다.

- 소규모 사무소 중개사 3~5명이 동일한 가상 장부로 상세 카드·수동 판정·자동 결과 목록을 비교한다. 순서는 교차한다.
- 새 매물 연결, 가격 인하 후 재연락 검토, 새 손님 제안, 동료의 기존 기록, 이전 분석 판별, 18건 중 13건 미판정 인지를 과제로 준다.
- 외부 연락 없이 ‘누구에게 어떤 근거로 연락할지’를 설명하게 한다. 첫 유효 연결 선택 시간, 이동·대기, 유효 후보 누락, 이전 분석 오인, 반복 연락 위험 인지를 측정한다.
- 잠정 통과 조건은 수동 방식보다 탐색·대기 부담이 줄고 후보 누락·이전 근거 오인·중복 연락 위험이 증가하지 않는 것이다. 시간 목표는 수동 기준 측정 후 합의한다.
- ‘평소 이 목록을 다시 열 계기가 있는가’를 확인한다. 발견성이 낮으면 장부 상세 요약·메뉴 준비 건수의 효과를 먼저 검증하고 알림부터 추가하지 않는다.

개발 검증은 [기능 수용 기준](../../requirements/f3/judgment-results-list.md)과 [로컬·dev 측정 계획](position-card-infrastructure.md)을 따른다.
상시 GPU 전제에서는 동일 가동시간·사양의 임대료 절감 대신 준비된 결과 비율·사용자 대기·챗봇 p95·큐 적체를 비교한다.
실제 필요성 판단은 역할 검토, 작동하는 구현의 정확성/부하 검증, 실제 중개사 과제 검증을 구분해 갱신한다.

## 이번 문서 변경의 확인

`node .github/scripts/check-skill-docs.mjs`는 6개 스킬·139개 Markdown 검사에서 오류 0건이었다.
변경/신규 Markdown의 상대 파일 링크와 `git diff --check`도 통과했다. 원본 작업 디렉터리는 변경하지 않았다.
이 검사는 문서 구조·링크 검사이며 위 실제 사용자 과제, API 구현 테스트, DB·GPU 실측을 대신하지 않는다.
