# 업무 챗봇 화면·동작 검토안

[기능 요구사항](../requirements/chatbot/overview-and-scope.md) · [기존 Screen Matrix](SCREEN_MATRIX_F1_F2_F3.md) · [통신안](../architecture/chatbot/api-and-stream.md)
기능 소속은 사용자 선택에 따라 F4이며 세부 Screen ID는 아직 부여하지 않는다. 패널 배치는 2026-09-09 사용자 요청에 따라 전체 높이 오버레이 사이드 패널로 변경했다. 사용자당 대화 1개·이력 조회·전체 삭제·새로고침 복원은 [설계 합의](../requirements/sources/chatbot-design-decisions-2026-09-08.md)를 따른다.

## 진입과 배치

- 로그인 후 앱 공통 셸의 우측 하단에 `업무 챗봇 열기` 버튼을 둔다. 그리드 저장·페이지 이동·알림 버튼을 가리지 않게 배치한다.
- 노트북·데스크톱에서는 화면 오른쪽 끝에 전체 뷰포트 높이의 오버레이 사이드 패널을 연다. 폭은 사용자 요청으로 기존보다 20% 줄여 화면의 36%를 기준으로 28.8~38.4rem 범위로 제한하며, 48rem 미만 화면에서는 전체 폭을 사용한다. 메인 화면의 폭·배치·스크롤은 밀거나 재배치하지 않는다. 배경 차단막은 추가하지 않는다.
- 패널이 열리면 하단 플로팅 버튼은 숨기고 패널 상단의 접기 버튼과 Escape로 닫는다. 닫은 뒤 플로팅 버튼으로 초점을 복원한다. 입력 영역은 하단에, 긴 대화는 별도 스크롤 영역에 둔다.
- 장부 조회·스크롤은 유지한다. 기존 상세 Modal이 열려 있다면 그 포커스·미저장 상태를 우선하고 챗 패널을 겹쳐 조작하지 않는다.
- 패널 열기는 현재 대화·이력·활성 요청을 조회하며 모델을 호출하지 않는다. 닫기는 접기이고 요청 중지는 별도다. 접힌 버튼에는 실제 진행 상태를 표시한다.
- 사용자당 대화 1개이며 여러 대화방을 만드는 `새 대화`와 대화방 목록은 제공하지 않는다. 저장한 메시지는 `대화 이력`에서 페이지로 다시 읽는다.
- 1차 문맥 대상은 챗봇의 최근 답변에서 명시적으로 고른다. 현재 장부의 선택 행을 자동 주입하는 기능은 후속 범위다.

## 첫 화면 구성

```text
┌ 업무 챗봇          대화 이력  전체 삭제  접기 ┐
│ 장부 조건을 찾고 음성메모 입력을 도와드려요.│
│ 현재 검색 조건: 없음                      │
│                                          │
│ 이런 걸 물어보세요                        │
│ [매매 15억 이하 매물 찾기]                 │
│ [전세를 찾는 손님 보기]                    │
│ [이번 달 만기 일정 보기]                   │
│ [음성메모로 장부 작성하기]                 │
│                                          │
│ 대화 내역은 저장돼요. 답변할 때는 현재     │
│ 검색 조건과 직전 2회의 질문·답변을 참고해요.│
│ [질문을 입력하세요                 ] [전송]│
└──────────────────────────────────────────┘
```

추천 질문은 실제 활성 도구에 맞춰 제공한다. 조회 버튼은 질문을 입력칸에 채우고 사용자가 전송한다.
F2 버튼은 사용자가 직접 선택한 화면 이동이므로 기존 음성 입력 화면을 연다. 아직 지원하지 않는 F3·시세 버튼을 실행 가능한 모습으로 배치하지 않는다.
F3를 직접 물으면 `챗봇의 교차 판정 연동은 준비 중이에요`라고 안내한다. 일반 조건 검색을 F3 판정처럼 표현하지 않는다.

## 대화와 결과

| 영역 | 표시·동작 |
|---|---|
| 사용자 질문 | 입력 원문과 전송 상태. Enter 전송, Shift+Enter 줄바꿈, 한국어 IME 조합 중 Enter는 전송하지 않음 |
| 진행 | “조건 해석 중”→“매물장 조회 중” 등 실제 이벤트. 검색 출처·검증된 조건을 표시하고 가짜 백분율은 쓰지 않음 |
| 적용 조건 | 단지·거래·금액·면적·기간 칩. 조건 변경·해제 후 명시적 다시 조회 제공 |
| 조회 답변 | 짧은 요약, 기준 시각, 전체 건수와 표시 범위. 가격·단위·날짜는 서버 값 사용 |
| 결과 목록 | 단지/대상·거래·가격/예산·면적 등 해당 도구의 최소 정보. 첫 10건, 다음 페이지·상세 열기 |
| 상세 열기 | 검증한 대상 ID로 기존 세대/손님 상세를 열고 챗 패널은 접음. 장부 필터·스크롤·draft 보존 |
| 확인 질문 | 단지 동명이름·전용/공급 면적·지시 대상 등 명확한 선택지. 답변 전 임의 조회하지 않음 |
| 후속 질문 | “그중 전세만”, “가격순으로”, “두 번째 상세 열기”. 현재 조건·현재 카드 기준이 모호하면 재선택 |

진행 중에는 같은 대화의 새 질문·검색 조건 변경을 막고 기존 요청 완료 또는 명시적 중지 후 다시 시도하게 한다. 여러 탭에도 같은 서버 규칙을 적용한다.

장부 목록이 지원하지 않는 필터라면 `장부에서 동일 조건 보기` 버튼을 만들지 않는다. 챗봇 내부 페이지와 검증된 개별 상세 진입부터 제공한다.
금액 조건을 바꾸어도 대화가 F1 저장을 수행하지 않으며, 결과에서 연락처 복사·실발송 기능을 새로 제공하지 않는다.

## F2 연결

1. 추천 버튼 또는 답변의 `음성메모 입력 열기`를 사용자가 누른다. 자연어 인식만으로 분석을 시작하지 않는다.
2. 신규 접수는 기존 AppShell의 음성 입력 액션으로 연결한다. 기존 대상 수정은 해당 화면이 실제 제공하는 F2 진입만 연결한다.
3. 챗 패널을 접고 기존 F2 모달로 포커스를 옮긴다. 원래 화면의 draft를 초기화하거나 다른 대상에 적용하지 않는다.
4. 개인정보 확인→파일 선택→분석→제안 선택→F1 상세 저장을 기존 화면에서 수행한다.
5. F2 취소 시 원래 화면으로 복귀한다. 저장 결과 콜백이 없는 상태에서 챗봇에 “저장 완료”를 표시하지 않는다.

F2 자체의 내부 진행 SSE는 이번 범위에 포함하지 않는다. 챗봇은 `음성 입력 화면으로 이동`까지만 진행으로 알린다.

## 실패·기억 한계 문구

| 상황 | 안내 예시·다음 행동 |
|---|---|
| 결과 없음 | “조건에 맞는 매물이 없어요. 가격이나 단지 조건을 바꿔보세요.” 조건 해제 제공 |
| 모호한 입력 | “30평은 전용면적과 공급면적 중 어느 기준인가요?” |
| 모델 혼잡·꺼짐 | “지금은 답변을 준비할 수 없어요. 잠시 후 다시 시도해 주세요.” 질문 보존, 수동 재시도·기존 장부 이용 |
| 연결 끊김 | “연결 상태를 확인하고 있어요.” DB 상태 조회 후 완료 결과 복원 또는 SSE 재연결. 실행 POST를 반복하지 않음 |
| 서버 중단 | “서버가 중단되어 답변을 완료하지 못했어요.” 저장된 질문을 유지하고 수동 재시도 |
| 권한·삭제된 대상 | “이 항목을 열 수 없어요. 목록을 다시 조회해 주세요.” 대상의 비공개 정보 노출 금지 |
| 지난 문맥 참조 | “답변에는 최근 2회의 대화만 참고해요. 대상이나 조건을 다시 알려주세요.” 저장한 이력 자체가 없다는 표현은 피함 |
| 단일 질문 모드로 축소 시 | “이전 대화를 기억하지 않아요. 조건을 한 번에 입력해 주세요.” 실제 동작과 함께 변경 |

`최대 2번의 대화만 기억 가능해요` 대신 **무엇을 언제까지 참고하는지** 명시한다. 대화를 2번만 할 수 있다는 뜻으로 오해하게 하지 않는다.
검색 조건 해제는 현재 조건만 바꾸고 저장된 대화를 지우지 않는다. 장부 미저장 편집값은 챗봇 이력 삭제와 무관하게 보존한다.

## 저장 이력·전체 삭제

- 패널에 저장된 이전 메시지를 페이지로 조회하고, 오래된 답변에는 당시 기준 시각을 표시한다. 상세 이동과 후속 조회는 현재 권한·값을 다시 확인한다.
- 새로고침·탭 종료 후에도 서버는 처리·결과 저장을 계속한다. 다시 접속하면 현재 대화와 활성 요청을 읽고 최신 상태를 복원한다.
- 사용자가 삭제하거나 시연 환경이 폐기될 때까지 이력을 보존한다. 로그아웃은 브라우저 표시만 비우며 다시 같은 사용자로 접속하면 이력을 조회할 수 있다.
- `전체 삭제`는 되돌릴 수 없다는 확인을 거쳐 대화·메시지·요청 기록을 운영 DB에서 즉시 삭제한다. 진행 중이면 결과 저장도 막는다는 점을 알린다.
- 서버의 삭제 성공 후에만 화면을 비운다. 실패하면 이력을 유지하고 재시도를 안내한다. 이후 첫 질문은 새 conversation ID를 사용한다.
- 다른 탭이나 늦은 SSE 이벤트로 삭제된 대화를 다시 표시하지 않는다. 타 사용자로 계정이 바뀌면 이전 구독과 화면 메모리를 제거한다.
- 현재 공용 dev 합성 계정은 같은 작성자로 취급되어 이력을 공유한다. 실제 사람별 비공개 채팅이 구현됐다고 표시하지 않는다.

## 접근성과 시각 기준

[Frontend Design Guide](../../.agents/skills/frontend/references/design/index.md)의 PatternFly 컴포넌트·semantic token을 재사용한다.
버튼 접근 가능한 이름, 열기/접기 포커스 복귀, 좁은 화면·200% 확대·키보드 이동을 검증한다.
단계 변경만 `aria-live="polite"`로 알리고 스트림 청크마다 읽어주지 않는다. 사용자가 이전 답변을 읽을 때 자동 스크롤을 강제하지 않는다.
데스크톱 비차단 패널은 배경을 잠그지 않고, 모바일을 modal로 구성할 경우에만 적절한 포커스 가두기·복귀를 적용한다.

## 구현·검증 범위

1차 UI는 단일 사용자 대화·서버 이력·SSE 복원·명시적 취소·전체 삭제를 구현했다. 기능은 Backend 활성 설정을 따른다. 상세 이동은 현재 그리드에 없는 장부 행과 다른 달의 캘린더 일정도 ID로 다시 조회한다. 페이지를 재조회한 답변은 원래 저장된 순번과 달라질 수 있으므로 첫 페이지로 돌아와도 번호 지시를 비활성화하고 카드의 상세 버튼을 제공한다. 참조가 직전 2회 범위를 벗어나거나 대화 ID가 바뀌면 선택을 해제한다. 검증 결과와 미적용 환경은 [구현·검증](../architecture/chatbot/implementation-and-validation.md)에 기록한다.
