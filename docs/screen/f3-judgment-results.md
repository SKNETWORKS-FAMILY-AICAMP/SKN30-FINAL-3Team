# F3 교차 판정 결과 화면 명세

기능 범위는 [결과 목록 요구사항](../requirements/f3/judgment-results-list.md)의 F3-JL-01~06이다. 기존 PatternFly 6 디자인 시스템으로 구현했다. 별도 Screen ID는 아직 부여하지 않았다. 검증은 [구현 기록](../architecture/f3/implementation-and-validation.md)을 따른다.

## 노출 위치

| 위치 | 1차 추가/변경 | 사용자 행동 |
|---|---|---|
| 공통 상단 메뉴 | `홈 / 매물장 / 구입장 / 교차 판정` 순서 | 교차 판정을 누르면 독립 업무 목록. 앱 기본 첫 화면은 홈 유지 |
| 매물·구입장 그리드 | 신규 AI 카드 컬럼은 추가하지 않음 | 기존 상세 진입 유지. 메뉴에서 전체 기회 확인 |
| 매물 상세 | 해당 listing_id의 교차 판정 요약 | ‘강함 2 · 약함 1 · 갱신 중’ 및 결과 보기 |
| 구입장 상세 | 해당 requirement_id의 같은 요약 | 결과 보기, 실패/오래됨이면 최신 분석 요청 |
| 교차 판정 결과 행 | 오른쪽 결과 Drawer | 후보 선택 후 근거/양측 포지션 카드 펼침 |
| 챗봇 | 1차 변경 없음 | 후속에 동일 목록/결과로 이동하는 typed action 재사용 |

현재 [AppShell.jsx](../../frontend/src/AppShell.jsx)는 activeNav와 조건부 렌더링을 사용한다.
새 페이지 조합·이동 처리는 feature 진입점과 작은 셸 navigation adapter에 두고 거대한 셸 내부에 목록/조회 로직을 추가하지 않는다.
`CrossMatchSection`은 GET 요약/결과 조회와 명시적 최신 분석 POST를 분리했다. 화면 보기만으로 판정하지 않는다.

## 화면 구성

위에서 아래로 다음 순서다.

1. 제목 ‘교차 판정’, 마지막 목록 확인 시각, ‘목록 새로고침’(GET만).
2. ‘매물 기준’/‘손님 기준’ 탭. 결과가 앵커별 비교라는 짧은 설명.
3. 최신 연결 후보/최신 강함/미판정 조건 후보/확인 필요/전체 필터와 건수. 담당자·검색을 우선하고 단지·거래유형은 상세 필터에 둠. 사무소 전체 기본, ‘내 담당’ 바로가기.
4. 대상별 행: 대상·현재 주요 조건·대표 후보 최대 3건과 상대 담당자/미지정·검토 이유·판정 범위·분석 기준/최신성·행 열기.
5. 서버 페이지 탐색. 갱신된 목록은 사용자 새로고침 전 현재 읽는 행의 위치를 강제로 바꾸지 않음.

오래된 등급 바로 옆에는 ‘이전 분석’을 표시한다. 기본 목록은 CURRENT 강함/약함 기준이며 ‘확인 필요’에서 이전 결과·갱신 상태·현재 조건 확인을 함께 제공한다.
대표 후보는 같은 앵커의 저장된 AI rank 기준이다. 강함이 없으면 약함을 제공하고 전부 기각이면 해당 사실을 표시한다.
원장 필드와 AI 추정값을 섞어 하나의 ‘현재 가격’으로 보이지 않게 한다. 추정의 근거와 기준 시각은 상세에서 확인한다.
휴대전화·상담 원문은 목록에 넣지 않는다. 후보 표시명·최소 조건은 Backend가 권한 확인 후 제공한다.

## 결과 Drawer와 원장 연결

상단에는 앵커, 최신/이전 분석, 생성 시각, 현재 갱신 상태를 표시한다.
후보 목록에는 강함/약함/기각/미판정과 ‘조건 후보 18 · AI 판정 5’ 같은 범위를 고정 표시한다.
후보를 고르면 맞는 이유·걸림돌·양보할 부분·다음 대화 제안·항목별 근거와 양측 카드가 보인다.
‘성사율 90%’ 등 현재 계약에 없는 수치를 만들지 않는다.
선택 후보에는 확인 가능한 최근 상담/피드백의 시각·기록 종류·원본 진입을 제공한다. 해당 쌍에 연결된 ‘이미 연락함’과 일반 대상 상담을 구분하고 기록 없음은 미연락으로 표시하지 않는다.
동작은 각 원장 열기·원본 로그 열기·기존 관심없음 피드백이며 발송·일정 생성은 제공하지 않는다.
카드는 기본 접힘, 다음 행동과 근거를 먼저 보여준다. 카드 직접 정정/이력 비교는 이번 범위가 아니다.

원장/로그로 이동하면 현재 탭·필터·cursor·선택 앵커/후보를 보존한다. 복귀 시 권한과 현재 결과를 재조회한다.
기존 원장 상세가 미저장 편집 중이면 같은 상세 안의 판정 요약/패널을 이용한다. 페이지 이동이 필요하면 기존 저장·이탈 보호를 통과한다.
세대에 여러 매물이 연결되면 현재 선택된 매물 ID를 사용하고, 선택이 없으면 매물을 먼저 선택하게 한다.
동일 매물·손님 쌍이 반대 탭에도 나와도 독립 판정 방향을 표시한다.

## 식별자와 복원

앱 셸의 공통 이동 대상은 `{view: 'f3_judgments', anchor_type?, anchor_id?, result_id?, candidate_id?}`로 제안한다.
새로고침 복원은 `/?view=f3-judgments&anchor_type=LISTING&anchor_id=123&result_id=456`처럼 내부 식별자만 사용한다.
로그인 후 현재 권한을 재검사한다. URL에 이름·연락처·상담 검색어를 넣지 않는다. 특정 router 라이브러리 도입은 요구하지 않는다.
result_id는 당시 결과, anchor_id는 현재 대상이다. 현재 결과가 바뀌면 ‘더 최신 분석 있음’과 전환을 제공하고 조용히 다른 후보로 바꾸지 않는다.
대상/결과가 삭제·접근 불가이면 안전한 안내 후 목록으로 돌아간다. 로그아웃·계정 변경은 이전 결과와 선택 상태를 제거한다.

## 상태와 갱신

| 상황 | 표시·동작 |
|---|---|
| 최초 loading | skeleton, 중복 실행 버튼 없음 |
| 첫 결과 준비 | 대기/분석 중, 저장을 다시 누르라고 안내하지 않음 |
| 이전 성공 + 갱신 중/실패 | 이전 기준 시각과 현재 상태를 함께 표시 |
| 공개 불가/유효 카드 없음 | 안전한 사유·원장 확인. 건수를 0으로 만들거나 ‘후보 없음’으로 표시하지 않음 |
| 후보 없음 | 정상 완료, 검색 조건·정보 확인용 원장 열기 |
| 판정한 후보 전부 기각 | AI 판정분에 추천 없음. 미판정이 있으면 잔여 조건 후보 수·진입을 함께 표시 |
| 미판정 후보 | ‘AI 미판정’으로 명시하고 등급/행동을 생성하지 않음 |
| 필터 결과 없음 | 미판정 조건 후보가 있는 대상 N건 보기, 준비/이전 결과/실패 건수와 필터 이동. ‘맞는 대상 없음’으로 단정하지 않음 |
| 조건 미충족/정보 부족 | 원인과 원장 확인. 무한 재시도 버튼은 제공하지 않음 |
| HTTP 오류/offline | 마지막 결과를 보존하고 조회 실패 표시. 저장된 작업 FAILED와 구분 |
| 권한 상실 | 해당 본문·근거 즉시 제거 |

현재 보고 있는 생성 중 앵커만 기존 실행 상태 API를 1→2→5초 간격으로 확인한다. 완료 때 결과를 재조회한다.
60초 뒤 자동 확인을 일시 중단해도 작업 취소/실패로 표시하지 않고 수동 확인을 제공한다.
목록 전체에 행당 polling을 만들지 않는다. 열린 목록은 일괄 GET 최대 10초 간격 후보로 시작하고 hidden/이탈 시 중단한다.
목록/작업 polling 간격은 제안 기본값이며 부하 측정으로 조정한다. 현재 읽는 Drawer는 업데이트로 닫히거나 다른 후보로 이동하지 않는다.

PatternFly 6의 기존 Table/Drawer·버튼·상태 표현을 재사용한다. 색만으로 등급/실패를 구분하지 않고 키보드 선택·Drawer 닫기 후 초점 복귀를 제공한다.
기획 검토 반영 이력은 [검증 기록](../architecture/f3/planning-validation.md)에 둔다.
