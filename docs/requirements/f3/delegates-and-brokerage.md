# F3 대리·중개 판정

### 5. 매물 대리

세대·매물의 보유자 입장을 세운다. 팔거나 세놓는 쪽을 대변한다.

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-LA-01 | 입력 범위 | 세대·매물 데이터 · 임대차 현황 · 날짜 신호 · **소유자·임차인 상담 로그 전체**를 읽는다 | 필수 | 설계서 |
| F3-LA-02 | 반대편 격리 | 손님 측 데이터와 손님 상담 로그를 읽지 않는다. 이 사실이 실행 로그로 확인 가능해야 한다 | 필수 | 설계서 |
| F3-LA-03 | 도구 | 매물 조회 · 로그 검색 · 접촉 이력만 호출한다 | 필수 | 설계서 |
| F3-LA-04 | 출력 | 매도측 포지션 카드 1장 (4장 규격) | 필수 | 설계서 |
| F3-LA-05 | 로그 전량 참조 | 로그가 많은 세대에서도 최신 N건만 보고 판정하지 않는다. 요약·검색으로 전 기간을 다룬다. 2018년 기록까지 지우지 않는 F1의 정책이 여기서 자산이 된다 (F1 설계 원칙 3) | 필수 | 설계서·F1 |
| F3-LA-06 | 의향 철회 판정 | 과거 매도 의향이 있었더라도 이후 로그에서 철회가 확인되면 `intent: 철회`로 판정한다. 최신 진술이 과거 진술을 이긴다 | 필수 | 신규 |
| F3-LA-07 | 결정권 판정 | 임차인이라 결정권이 없는 경우, 공동명의로 단독 결정이 불가한 경우를 구분해 표시한다. 배치 판정의 발송 제외 근거가 된다 (F3-BT-06) | 필수 | 설계서 |
| F3-LA-08 | 로그 부족 처리 | 접촉 이력이 부족해 판단이 불가하면 억지로 채우지 않고 `불명`으로 반환한다. 「판단 불가」도 유효한 판정이다 | 필수 | 설계서 |

### 6. 손님 대리

구입장 손님의 매수·임차 입장을 세운다. 사거나 들어가는 쪽을 대변한다.

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-CA-01 | 입력 범위 | 손님 데이터 · 희망 조건 · 날짜 신호 · **손님 상담 로그 전체**를 읽는다 | 필수 | 설계서 |
| F3-CA-02 | 반대편 격리 | 매물 측 데이터와 소유자 상담 로그를 읽지 않는다. 실행 로그로 확인 가능해야 한다 | 필수 | 설계서 |
| F3-CA-03 | 도구 | 손님 조회 · 로그 검색 · 접촉 이력만 호출한다 | 필수 | 설계서 |
| F3-CA-04 | 출력 | 매수측 포지션 카드 1장 (4장 규격) | 필수 | 설계서 |
| F3-CA-05 | 실질 예산 상한 | 장부 표기 예산과 로그에서 확인되는 실제 상한이 다르면 둘을 함께 반환한다. 예 — 표기 28.5억 / 추정 상한 30억, 근거 "30억 이하로 보고 있다" | 필수 | 설계서 |
| F3-CA-06 | 자금 상태 반영 | "본인 집이 팔려야 살 수 있다" 등 자금 조건부 진술을 `inflexible` 또는 `timing.constraints`에 반영한다 | 필수 | 설계서 |
| F3-CA-07 | 의지 판정 | "꼭 살 사람" 취지의 반복 진술, 반대로 조용해진 이력을 근거로 `intent`와 `urgency`를 구분해 판정한다 | 필수 | 설계서 |
| F3-CA-08 | 로그 부족 처리 | F3-LA-08과 동일하게 처리한다 | 필수 | 설계서 |

### 7. 중개 판정

앵커 1장과 후보 N장을 한 번에 받아 등급·순위·행동을 정한다.

#### 7.1 입력과 출력

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-BR-01 | 일괄 입력 | 앵커 포지션 카드 1장 + 반대편 포지션 카드 N장을 **한 번의 호출**로 받는다. 후보를 1장씩 개별 호출하지 않는다 | 필수 | 설계서 |
| F3-BR-02 | 앵커 단일 전송 | 앵커 카드를 후보 수만큼 반복 전송하지 않는다. 반복 전송은 토큰 낭비이며 판정이 흔들린다 | 필수 | 설계서 |
| F3-BR-03 | 등급 | 각 후보에 강함 / 약함 / 기각 등급을 부여한다 | 필수 | 설계서 |
| F3-BR-04 | 순위와 비교 근거 | 후보 간 순위를 매기고 **상호 비교 근거**를 낸다. "이 물건이 괜찮다"가 아니라 "왜 이걸 먼저 보여주는가"를 답해야 한다 | 필수 | 설계서 |
| F3-BR-05 | 걸림돌 특정 | 가격 차 · 시점 차 · 조건 차 중 **무엇이 결정적인가**를 지목한다. 복수 나열이 아니라 결정적 요인을 특정한다 | 필수 | 설계서 |
| F3-BR-06 | 양보 지점 | 누가 · 무엇을 · 얼마나 움직이면 되는지 제시한다. 양측 카드의 `flexible`을 근거로 한다 | 필수 | 설계서 |
| F3-BR-07 | 행동 제안 | 누구에게 먼저 · 무슨 말을 · 어떤 경로로 접촉할지 제안한다. 경로는 `contactability`를 따른다 | 필수 | 설계서 |
| F3-BR-08 | 일정 제안 | 임장 등 약속이 필요하면 일정을 제안한다. 승인 시 F1에 일정을 생성한다 (F3-IF-04) | 권장 | 설계서 |
| F3-BR-09 | 기각 권한 | 양측 대리가 모두 긍정적이어도 시점 불일치 등을 근거로 **성사 불가를 선언**할 수 있다. 위계가 여기서 생긴다 | 필수 | 설계서 |
| F3-BR-10 | 기각 사유 기록 | 기각 시 사유를 반드시 남기고 결과 화면에 접어서 노출한다. 조용히 사라지는 후보를 만들지 않는다 | 필수 | 설계서 |
| F3-BR-11 | 사용 범위 | 중개 판정은 교차 판정 전용이다. 배치 판정에서는 교차 옵션(11.4)을 켤 때만 쓴다 | 필수 | 설계서 |

#### 7.2 N의 상한

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-BR-12 | 카드 예산 | 포지션 카드 1장을 약 300토큰 규모로 유지한다. 15장이면 약 4,500토큰으로 판정 품질이 유지된다 | 권장 | 설계서 |
| F3-BR-13 | 상위 15건 우선 | 후보가 15건을 넘으면 SQL 점수(가격 근접도 · 평형 일치 · 접수 최신순)로 상위 15건만 먼저 카드화한다 | 필수 | 설계서 |
| F3-BR-14 | 나머지는 페이징 | 나머지는 「조건만 맞는 매물 N건 더 보기」로 지연 로딩한다. **컷이 아니라 페이징**이며, 남은 건수를 화면에 표시한다 | 필수 | 설계서 |
