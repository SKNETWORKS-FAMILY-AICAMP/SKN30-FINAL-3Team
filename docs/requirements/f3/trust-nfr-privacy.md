# F3 신뢰·비기능·개인정보

### 14. 신뢰 루프

대리가 엉뚱한 포지션을 두 번 세우면 아무도 보지 않는다.

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-TR-01 | 근거 표시 | 모든 판정 항목에 근거 원문을 붙이고, 인용이 없으면 「추정」으로 표시한다 (F3-CM-02) | 필수 | 설계서 |
| F3-TR-02 | 포지션 정정 | 중개사가 포지션을 직접 정정할 수 있다. 정정 내용은 상담 로그에 기록되어 다음 판정의 입력이 된다 | 필수 | 설계서 |
| F3-TR-03 | 관심없음 + 사유 | 모든 판정 항목에 [관심없음]과 사유 선택(조건 안 맞음 / 이미 연락함 / 판정이 틀림 / 기타)을 제공한다 | 필수 | 설계서 |
| F3-TR-04 | 기각 건 노출 | 기각 판정도 사유와 함께 접어서 노출한다. 무엇을 왜 걸렀는지 검증 가능해야 한다 | 필수 | 설계서 |
| F3-TR-05 | 실행 로그 추적 | 어떤 에이전트가 어떤 도구를 호출해 어떤 근거로 판정했는지 추적한다 | 필수 | 설계서 |
| F3-TR-06 | 반복 기각 표시 | 같은 쌍을 두 번 기각하면 영구 제외 후보로 표시한다. 사용자가 해제할 수 있어야 한다 | 권장 | 설계서 |
| F3-TR-07 | 피드백 집계 | 「판정이 틀림」 사유를 대상·항목별로 집계해 조회할 수 있다. 어느 판정이 자주 틀리는지가 개선 근거다 | 권장 | 신규 |
| F3-TR-08 | 격리 검증 노출 | 두 대리가 서로의 로그를 읽지 않았음을 실행 로그에서 확인할 수 있게 표시한다. 심사·시연에서 구조를 입증하는 근거가 된다 | 권장 | 설계서 |

### 15. 비기능 기준

| ID | 항목 | 기준 | 등급 |
|---|---|---|---|
| F3-NF-01 | 교차 판정 응답 | 저장·조회 후 5초 이내 판정 결과 표시. 초과 시 순차 표시로 전환 (F3-CR-09) | 필수 |
| F3-NF-02 | 후보 추출 응답 | SQL 후보 추출 100ms 이내 | 필수 |
| F3-NF-03 | 카드 재사용률 | 데이터 변경이 없는 후보의 카드 재생성이 발생하지 않는다. 교차 판정 1회의 신규 카드 생성이 평시 1~3회로 수렴한다 | 필수 |
| F3-NF-04 | 중개 판정 호출 수 | 교차 판정 1회당 중개 판정 LLM 호출은 1회다 | 필수 |
| F3-NF-05 | 캠페인 문안 호출 수 | 대상 100명 캠페인의 문안 생성 LLM 호출 10회 이하 | 필수 |
| F3-NF-06 | 배치 병렬 처리 | 대상 100명 규모의 대리 배치 실행이 병렬로 수행되며 진행률이 표시된다 | 필수 |
| F3-NF-07 | 장애 격리 | F3 전체 장애가 F1 기능을 중단시키지 않는다 | 필수 |
| F3-NF-08 | 재현성 | 같은 입력에 대해 판정 결과의 등급·기각 여부가 안정적으로 재현된다. 근거 없는 등급 변동이 없어야 한다 | 권장 |
| F3-NF-09 | 데이터 규모 | 7,200행 세대 · 로그 수만 건 규모에서 판정 품질과 응답 시간을 유지한다 | 필수 |
| F3-NF-10 | 모델 교체 가능성 | 에이전트별 모델을 설정으로 교체할 수 있도록 분리한다. 대리와 중개 판정이 다른 모델을 쓸 수 있어야 한다 | 권장 |

### 16. 데이터 및 개인정보

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-SE-01 | 최소 수집 | 판정에 필요한 항목만 F1에서 읽는다. 연락처·생년월일은 기본 마스킹 (F3-IF-06) | 필수 | F1 |

| F3-SE-04 | 반대편 정보 차단 | 판정 결과와 문안에 반대편 당사자의 식별 정보를 노출하지 않는다 (F3-GN-04) | 필수 | 신규 |
| F3-SE-05 | 권한 상속 | F3는 요청한 사용자의 권한을 넘어서는 데이터를 읽지 않는다. 읽기전용 사용자에게는 마스킹된 결과만 제공한다 (F1 12장) | 필수 | F1 |
