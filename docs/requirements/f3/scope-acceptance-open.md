# F3 제외 범위·수용 기준·미해결 사항

### 17. 제외 범위

| 항목 | 어디 소속 | 사유 |
|---|---|---|
| 일정 데이터 저장 | F1 | 임장·계약·잔금 약속은 장부 데이터다. F3는 제안만 한다 |
| 캘린더 동기화 | F1 | ICS 생성 또는 Calendar API 호출. 판단이 없는 배관이다 |
| 오늘 무엇이 있는지 | F1 | 캘린더가 답한다. 확정된 사실만 나가므로 AI가 필요 없다 |
| 만기 보드 · 진행 현황 | F1 | 중개사가 직접 찾아볼 수 있는 목록은 에이전트가 만들지 않는다 |
| 거래신고 기한 · 로그 누락 | F1 | 규칙 알림이다. 조건이 명확하므로 SQL로 충분하다 |
| 보류 목록 · 이월 | F1 | 인라인에서 [나중에] 한 것을 모아 보여주는 조회 화면이다 |
| 날짜 계산 | 코드 | SQL이다. LLM은 날짜 산수를 틀린다 |
| 아침 브리핑 · 스케줄 배치 | 제외 | 브리핑 항목 전부가 다른 곳에 있어야 할 것들이었다. F3는 사용자 행동에만 반응한다 (1.3 원칙 4) |
| 편성 에이전트 · 쿼터 · 이월 큐 | 제외 | 브리핑 부속이었다. 컷이 없으므로 불필요하다 |
| 정책 학습 · 감시 | 제외 | 정책은 중개사가 안다. 시스템은 그가 아는 조건을 장부에 적용할 뿐이며, 그 통로는 캠페인 대상 선정의 자연어 입력이다 |
| 시세 · 실거래 폴링 | 제외 | 중개사가 직접 확인하는 영역이다 |
| 계약서 작성 · 법률 판단 · 가격 평가 | 제외 | 책임 소재가 시스템 밖에 있다 |

### 18. 수용 기준

| # | 기준 | 검증 방법 |
|---|---|---|
| 1 | 후보 추출과 대상 선정이 LLM 없이 동작한다 | 유닛 테스트 |
| 2 | 포지션 카드의 각 판정 항목에 근거 원문이 있거나 「추정」으로 표시된다 | 표본 20건 검수 |
| 3 | 매물 대리와 손님 대리가 서로의 로그를 읽지 않는다 | 실행 로그 확인 |
| 4 | 양측 대리 방식이 단일 프롬프트 대비 우수하다 | 케이스 20건 비교 (19장) |
| 5 | 중개 판정이 앵커 1 + 후보 N을 한 번의 호출로 받으며 순위와 상호 비교 근거를 낸다 | 호출 로그 · 출력 확인 |
| 6 | 중개 판정이 후보 중 일부를 기각하며 사유가 로그에 남는다 | 실행 로그 확인 |
| 7 | 후보 추출 조건에 대리의 추정값이 반영된다 | 장부 표기값과 다른 케이스 재현 |
| 8 | 손님 또는 매물을 저장하면 5초 이내 같은 화면에 판정 결과가 표시된다 | 성능 측정 |
| 9 | 교차 판정 결과에 컷이 없다 (세대 상세의 기각 미노출은 예외이며 판정 수는 줄지 않는다) | 판정 수 = 노출 수 + 기각 수 대조 |
| 10 | 가격 변경 저장 시 새로 조건에 맞게 된 상대가 결과에 포함된다 | 27.5억 → 26.5억 시나리오 |
| 11 | 대상 100명 캠페인에서 발송 제외 대상이 로그 근거와 함께 식별된다 | 캠페인 시연 |
| 12 | 대상 100명 캠페인의 문안 생성 LLM 호출이 10회 이하다 | 호출 계측 |
| 13 | 포지션 카드가 캐시되어 로그 변경이 없으면 재생성되지 않는다 | 캐시 히트율 계측 |
| 14 | 중개사가 정정한 포지션이 다음 판정에 반영된다 | 정정 → 재판정 시나리오 |
| 15 | F3를 중단해도 F1의 모든 기능이 동작한다 | 장애 주입 테스트 |

#### 18.1 멀티 에이전트 구조 검증

> **[참고]** **"왜 나눴냐"에 수치로 답한다.** 같은 케이스 20건에 대해 ① 단일 프롬프트 ② 양측 대리 후 중개 판정 두 방식을 돌려 비교한다. 비교 지표는 — 걸림돌을 구체적으로 특정했는가 · 양보 지점을 제시했는가 · 로그의 비구조화 근거를 인용했는가 · 중개사 블라인드 선호도. 심사에서 답이 의견이 아니라 수치가 된다.

> **[주의]** **배치 판정은 멀티 에이전트가 아니다.** 대리 하나를 N번 돌리는 것이며, 교차 옵션(11.4)을 켜야 중개 판정이 개입한다. 유용하지만 멀티 에이전트 논증에는 기여하지 않는다 — 발표에서 이 점을 감추지 않는다.

### 19. 미해결 사항

| # | 질문 | 영향 | 우선 |
|---|---|---|---|
| 1 | 인라인이 사용자가 열지 않은 것을 못 본다. 6개월 방치된 손님을 어떻게 드러낼 것인가 | F1 그리드에 「90일 이상 무활동 12건」 배지를 띄우고 클릭 시 캠페인 대상으로 넘기는 것으로 대응한다. SQL 카운트이므로 AI가 아니다. F1 요구사항 추가가 필요하다 | 최우선 |
| 2 | 로컬 LLM인가 외부 API인가 | F3-SE-02의 치환 요구와 F3-NF-01의 5초 목표 달성 가능성이 여기서 갈린다. F2가 로컬 LLM을 쓰므로 자원 경합도 확인해야 한다 | 최우선 |
| 3 | 상담 로그의 ①②③ 표기 의미 | 로그에서 화자와 통화 방향을 읽어야 대리가 "누가 한 말인지"를 구분할 수 있다. F1 17장 2·3번과 같은 질문이다 | 최우선 |
| 4 | 얕은 판정(F3-BT-09)의 항목 범위 | 배치 판정 비용이 여기서 정해진다. 카드 전 항목이면 100명 캠페인이 감당되지 않을 수 있다 | 높음 |
| 5 | 등급 「강함 / 약함」의 판정 기준을 문서화할 것인가 | 기준이 없으면 재현성(F3-NF-08)을 검증할 수 없다 | 높음 |
| 6 | 중개사가 실제로 원하는 것이 후보 목록인가 행동 지시인가 | 후보 패널의 기본 표시 형태가 정해진다. 인터뷰 필요 | 높음 |
| 7 | 발송 제외 판정이 틀렸을 때의 책임 | 거절하지 않은 사람을 「최근 거절」로 분류해 빼면 기회 손실이다. 제외 명단을 항상 노출할지 정해야 한다 | 높음 |
| 8 | 포지션 카드 정정 이력의 보존 기간 | F3-SE-03의 파기 주기와 F1의 개인정보 보유 기간(F1 17장 21번)에 연동된다 | 중간 |
| 9 | 교차 옵션(11.4)을 MVP 시연에 포함할 것인가 | 포함하면 캠페인 문안의 설득력이 크게 오르지만 비용과 구현 범위가 늘어난다 | 중간 |
