# F3 조건부 자동 판정과 결과 목록 요구사항 검토안

2026-09-09 후속 사용자 요청을 반영한 권고안이다. [원문](../sources/f3-worker-auto-judgment-review-2026-09-09.md)의 GPU 상시 운영을 전제로 한다.
독립 카드 상세 표시를 주 기능으로 만드는 안보다 **조건부 자동 교차 판정 결과 목록**을 먼저 제공하는 안을 권고한다.
실효성은 아래 업무 동선의 분석이며 현업 인터뷰·사용성 실험 결과가 아니다. 정식 요구사항/Screen ID는 합의 후 부여한다.

## 카드와 결과 목록의 가치 비교

| 사용자 질문 | 포지션 카드 상세 | 교차 판정 결과 목록 |
|---|---|---|
| 이 매도자/손님의 사정과 협상 여지는? | 강점: 로그를 요약하고 한쪽 입장·근거 확인 | 상대 후보를 고른 뒤 양측 근거에서 제공 가능 |
| 지금 어떤 매물과 손님을 연결할까? | 여러 상세를 돌아다니며 사람이 비교해야 함 | 강점: 연결 후보·걸림돌·양보·다음 행동을 함께 제공 |
| 새 가격/상담 때문에 새 기회가 생겼나? | 해당 상세를 열어야 발견 | 강점: 새로 갱신된 결과를 목록에서 발견 |
| AI 판단을 검증·정정하려면? | 카드·원본 근거가 유용 | 결과 상세의 카드/근거 펼침으로 유지 |
| 중복 정보·탐색 부담 | 원장과 내용이 겹칠 수 있고 상세마다 별도 확인 | 준비된 결과를 비교하되 최신성·미판정 표시 필요 |

카드는 내부 판정 입력이자 설명 자료로 유효하므로 없애지 않는다.
주 메뉴는 결과 목록, 상세 화면은 준비된 판정 요약과 [결과 보기], 양측 포지션 카드는 근거 상세에서 펼치는 구성을 제안한다.
카드만 보려는 독립 분석 수요가 확인되면 [카드 독립 조회안](position-card-delivery.md)을 확장한다.

## 자동 실행 요구

- 유효·활성·지원 거래 유형인 대상의 의미 있는 입력 변경 또는 미생성 결과를 자동 접수한다.
- 메모 등 비입력 수정·동일 값 재저장·동일 입력 진행/완료 결과는 새 판정을 만들지 않는다.
- 앵커 카드와 후보 SQL로 최종 실행 필요성을 결정한다. 후보가 없으면 모델 판정을 생략하고 “후보 없음”을 저장한다.
- 다른 장부의 새 후보 진입·조건 변경도 영향 대상 결과를 갱신한다. 현재 대상 저장만 트리거로 삼지 않는다.
- 연속 저장은 최신 입력으로 합치고 늦게 끝난 구버전 결과가 최신 결과를 덮어쓰지 못한다.
- 저장 성공은 AI 완료와 독립이다. 이벤트 기록 실패의 원자성 선택은 기존 OQ-F3-02에서 합의한다.
- 처리 중 목록 진입·새로고침은 기존 작업을 조회한다. 수동 갱신은 중복 실행을 만들지 않고 기존 작업을 우선 처리한다.
- 자동 계산 범위·gate·날짜 기준·처리 우선순위는 [조건부 자동 판정 설계](../../architecture/f3/conditional-auto-judgment.md)를 따른다. 아직 승인 전이다.

## 목록 표시

1차는 **대상 앵커 한 건당 최신 결과 요약 한 행**을 권고한다. 매물 기준/손님 기준을 선택하고 검색·거래유형·결과 상태로 필터한다.
행에는 대상 표기, 거래 유형, 주요 조건, 생성/갱신 시각, 최신 여부, 강함/약함/기각/미판정 건수와 대표 후보를 표시한다.
여러 앵커의 AI rank=1을 하나의 전역 순위처럼 정렬하지 않는다. 최근 의미 있는 결과 갱신 등 결정적 기준과 안정적 tie-breaker를 쓴다.
같은 매물·손님 쌍이 반대 방향에 있어도 판정 맥락·순위가 다르므로 방향을 표시하고 결과를 임의 병합하지 않는다.
각 행을 열면 해당 앵커의 후보 목록·등급·걸림돌·양보·다음 행동·양측 근거를 보여준다.

| 상태 | 화면 의미 |
|---|---|
| 최신 결과 | 현재 입력·후보·구성에 대해 검증된 판정 |
| 이전 결과 / 갱신 중 | 접근 가능한 과거 결과와 현재 작업 상태를 함께 표시. 최신 결과로 세지 않음 |
| 준비 중 | 첫 판정의 대기/진행. 후보 0건과 구별 |
| 후보 없음 | 후보 검색이 완료됐으나 대상이 없음. 오류 아님 |
| 조건 미충족 / 정보 부족 | 자동 실행하지 않은 이유를 설명. AI가 기각한 결과와 구별 |
| 갱신 실패 | 이전 결과가 있으면 유지하면서 실패와 재시도 표시 |

현재 엔진은 상위 5개 후보만 AI 판정한다. 나머지 SQL 후보는 “미판정”으로 표시하고 필터로 확인할 수 있어야 한다.
목록을 전체 후보의 AI 순위로 소개하지 않으며, 미판정 후보를 기각으로 집계하지 않는다.
강함 위주 기본 필터를 제안하되 약함·기각 결과도 선택해 확인할 수 있게 한다. 무조건 강함만 있는 목록으로 빈 결과를 숨기지 않는다.
전체 갱신 목록이므로 이전 상세 부모별 기각 숨김 정책을 그대로 적용하지 않는다. 공개 필터 정책은 합의 대상이다.
문자 발송·일정 자동 생성은 범위에 넣지 않는다. [원장 열기], [근거 보기], 기존 [관심없음] 피드백을 연결한다.
사용자별 “새 결과/읽음” 배지를 넣는 경우 생성시각만으로 추측하지 않고 사용자·결과 revision별 확인 상태를 별도 저장한다. 1차 필수로 두지 않는다.

## API·저장 검토안

| 경로 | 책임 |
|---|---|
| `GET /api/v1/f3/judgment-results` | 인증 사무소의 앵커별 결과 요약. anchor_type·거래유형·상태·검색·cursor·limit 지원 |
| `GET /api/v1/f3/judgment-results/{result_id}` | 특정 결과의 후보·근거·최신성·현재 갱신 job 조회 |
| `POST /api/v1/f3/judgment-jobs` | 특정 앵커의 확보/갱신. 완료 재사용 200 또는 작업 접수·진행 재사용 202 |

GET은 모델·작업 생성 없이 DB를 읽는다. `result_id`는 저장 결과를 식별하고 현재 결과 포인터와 분리해 오래된 ID로 최신성을 위장하지 않는다.
기존 `agent_run`, `match_evaluation`, 후보·근거를 재사용하고 앵커별 최신 결과 포인터·summary 읽기 모델을 추가한다.
후보 이름·안전한 요약 필드는 Backend가 권한 검사 후 한 번에 반환한다. 현재 F1 화면에 전체 장부가 이미 로드돼 있어야만 이름이 보이는 방식은 새 목록에서 재사용하지 않는다.
전체 목록에서 실행별 `/result`를 반복 호출하는 N+1 방식을 피하고 서버에서 집계·페이지 처리한다.
snapshot identity·최근 변경 revision·현재 접근 권한을 확인하며 삭제·접근 불가 대상과 근거는 즉시 숨긴다.
새 결과를 원자적으로 게시하고, 실패한 갱신이 기존 성공 결과를 지우지 않도록 한다.
현재 합성 데이터 공개 경계를 유지하고, 화면·일반 로그에 전체 prompt·모델 원문·불필요한 개인정보를 넣지 않는다.

## 수용·사용성 검증

같은 합성 사례에서 두 방식으로 “가격 변경 후 연결 후보 3명 찾기”, “연락할 이유와 양보 지점 확인”, “근거 로그 확인”을 수행한다.
상세 이동/수동 실행 횟수, 과제 완료 시간, 최신 결과 준비 비율, 대기 시간, 근거 찾기 성공률과 사용자 선호를 비교한다.
부하 검증에는 후보 0건→새 후보 등장, 5건 초과, 양방향 중복, 결과 갱신 중 삭제·권한 변경, 날짜 경계·GPU 정체를 포함한다.
이 검증 전 “카드 상세는 쓸모없다” 또는 “목록이 검증된 최적안”이라고 결론 내리지 않는다.
자동 정책은 ADR-0018의 후속 결정과 API·화면 계약 개정을 동반한다. 이번 변경은 검토 문서만 작성한 상태다.
