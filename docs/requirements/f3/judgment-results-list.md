# F3 확장 기능 정의: 조건부 자동 판정과 결과 목록

dev `f700f5a` 병합 후 [1차 구현 요청](../sources/f3-expansion-implementation-2026-09-09.md)을 반영했다. [기획 요청](../sources/f3-expansion-planning-2026-09-09.md)과 GPU 상시 운영 전제를 유지한다. 코드·로컬 합성 검증 상태이며 팀 병합과 공유 dev 배포는 별도다.
이 문서가 기능 범위의 정본이다. [화면 명세](../../screen/f3-judgment-results.md), [API·내부 확장](../../architecture/f3/expansion-contracts.md), [기획 검토](../../architecture/f3/planning-validation.md)를 함께 본다.
추가 ID는 F3-JL-01~06이며 아래 기능을 묶어 추적한다. 구현 경로는 [추적표](../traceability.yaml), 검증 범위와 미측정 지표는 [구현 기록](../../architecture/f3/implementation-and-validation.md)을 따른다. 수용 기준 전체의 현장 검증 완료를 뜻하지 않는다.

## 목적과 사용자

매물·손님 조건/상담을 저장한 뒤 다른 업무를 하는 동안 가능한 연결을 계산하고, 돌아왔을 때 대상과 연락 근거를 함께 확인한다.
1차 사용자는 아파트 매매·전세·월세를 다루며 두 장부를 사용하는 소규모 중개사무소의 중개사다. 기존 사무소 권한 범위를 따른다.
핵심 업무는 새 매물에 맞는 손님 찾기, 손님 조건에 맞는 매물 찾기, 가격·상담 변경 후 이전에 없던 후보 확인이다.
자동 판정은 추천 준비이며 연락·계약·거래 성사를 자동 결정하지 않는다. ‘강함’은 후보 비교 등급이고 성사 확률이 아니다.

## 1차 기능 범위

| 검토 항목 | 정의 | 완료 조건 |
|---|---|---|
| 목록 진입 | 공통 상단 메뉴에서 구입장 다음에 ‘교차 판정’ 추가 | 장부 상세를 열지 않고 준비된 판정을 발견 |
| 기준 전환 | ‘매물 기준’/‘손님 기준’ 탭. 최초 매물 기준, 현재 탭 유지 | 같은 매물·손님 쌍의 방향·순위를 혼동하지 않음 |
| 대상 요약 | 앵커당 한 행, 대표 후보 최대 3건과 후보 담당자·핵심 조건·검토 이유·판정 범위·최신성 | 앵커·후보 모두 식별 가능, 이름 확인용 장부 전수 로딩 불필요 |
| 필터 | 기본 ‘연결 후보 있음’(CURRENT 강함 또는 약함), 전체·최신 강함 있음·미판정 조건 후보 있음·확인 필요, 거래유형·단지·담당자·대상/후보 검색 | 숨겨진 미판정/준비/이전 결과/실패 건수와 각 필터 진입을 항상 제공 |
| 정렬 | 의미 있는 결과 변경 시각 내림차순, 동일 시각은 앵커 ID·종류로 고정 | 재검증만 하고 내용이 같은 행은 위로 재등장하지 않음 |
| 후보 상세 | 행을 열면 해당 앵커의 상대 후보, 등급·걸림돌·양보·다음 행동·양측 카드/근거 | 근거 로그와 각 장부 상세로 이동하고 원래 목록 맥락 복원 |
| 장부 상세 접점 | 매물·구입장 상세에 판정 요약과 ‘결과 보기’·조건에 따른 ‘최신 분석 요청’ 제공 | 결과 보기 GET만 수행, 강제 재판정 없음 |
| 자동 처리 | 유효 대상의 의미 있는 변경에서 gate·변경 병합·카드/후보 확보·필요한 판정 실행 | 원장 저장 요청은 AI 완료를 기다리지 않음 |
| 최신성 | 최신 결과·이전 결과·생성 상태·실패를 별도 표시 | 변경·삭제·새 후보 유입을 놓친 결과를 최신으로 표시하지 않음 |
| 수동 갱신 | 최신 결과면 재사용, 진행 중이면 같은 작업 확인, stale/실패/미생성이면 접수 | 동일 입력 중복 클릭으로 모델 실행 증가 없음 |
| 기존 기록 확인 | 후보별 최근 상담·기존 피드백의 시각·기록 종류와 원본 이동 | 해당 쌍을 특정하는 기록과 대상 일반 상담 구분. 기록 없음은 미연락 의미가 아님 |
| 피드백 | 기존 ‘관심없음’과 이유를 후보 판정에 연결 | 현재 구현처럼 피드백 기록. 영구 제외·학습·처리 완료로 오해시키지 않음 |

## 자동 판정 조건

1. 저장 완료·현재 권한·삭제되지 않은 대상/부모·지원 거래유형·활성 상태를 코드로 확인한다.
2. 대상·상담·관계·세대 정보 등 실제 AI/후보 입력 변경이나 결과 미생성만 접수한다. 동일 값 재저장·비입력 메모/담당자 수정은 판정하지 않는다.
3. 동일 입력 진행 작업은 합치고 완료 결과는 재사용한다. 연속 저장 병합 기본값은 3초이며 운영 설정값으로 둔다. 자동 처리 flag는 기본 false이고 활성화한 Worker에서 실행한다. 사용자 요청은 대기 지연을 우회하되 중복 생성하지 않는다.
4. 유효 앵커 카드를 확보하고 기존 카드의 추정 조건으로 SQL 후보를 찾는다. 후보가 없으면 ‘후보 없음’을 저장하고 최종 AI 호출을 생략한다.
5. 후보 카드와 판정 입력 identity가 달라졌을 때만 최종 판정한다. 캐시·유효성 비교는 실제 모델 입력과 후보 집합·정책·모델 구성·날짜 기준을 포함한다.
6. 반대편 장부 변경으로 새 후보가 들어올 수 있는 앵커도 재검증한다. 기존 후보 역참조만으로 영향 대상을 계산하지 않는다.
7. 삭제/종료/권한 상실은 즉시 노출·늦은 결과 저장을 차단한다. 모델/UTC 날짜 변경은 점진적 재검증, 기존 데이터는 제한된 backfill로 처리한다.

원장 가격만 좁게 걸러 카드 생성 전 탈락시키지 않는다. 상담이 없다는 이유만으로 일률 제외하지 않는다.
원장 상태 어휘·가격 허용폭은 현재 구현 기준이며 승인된 도메인 규칙으로 승격하지 않는다.
상위 5건은 [F3-BR-12·13](delegates-and-brokerage.md)과 [2026-08-31 변경 이력](../changelog.md)의 승인된 최초 판정 상한을 유지한다.
F3-CR-05는 최초 상위 5건 안에서 판정한 결과를 모두 보존한다는 의미로 정리했다. 5건 초과 조건 후보는 미판정으로 조회하며 추가 판정은 후속이다.
GPU 상시 운영하에서도 사용자 요청·챗봇과 자동 작업의 처리 용량을 나눈다. 기준은 임대료 절감보다 준비된 결과 비율·사용자 대기·공유 모델 지연이다.

## 결과 의미와 표시 규칙

| 축 | 정의 |
|---|---|
| 최신성 | CURRENT / STALE / NONE. 새 원천 변경 후 소비자가 아직 처리하지 않았어도 CURRENT로 오표시하지 않음 |
| 생성 | IDLE / QUEUED / RUNNING / FAILED. 마지막 성공 결과 존재 여부와 별개 |
| 적격성 | ELIGIBLE / INELIGIBLE / INSUFFICIENT_INPUT. 미충족 이유를 안전한 고정 문구로 표시 |
| 공개 가능성 | AVAILABLE / UNAVAILABLE. 정책상 비공개·무효 카드로 본문이 없는 상태는 정상 무후보가 아니며 판정 건수를 null로 표시 |
| 후보 결과 | 후보 없음 / 강함·약함·기각 / 미판정. 전부 기각과 후보 없음은 다름 |

현재 상위 5건만 AI 판정한다. ‘후보 18건 · AI 판정 5건 · 미판정 13건’처럼 범위를 명시하고 나머지는 조건 후보로 조회할 수 있게 한다.
5건 전부 기각이어도 미판정 13건이 있으면 ‘미판정 조건 후보 있음’ 필터에서 발견할 수 있어야 한다. 기본 필터가 비어도 이 진입을 숨기지 않는다.
미판정은 기각이 아니며, 전체 후보가 AI 순서로 정렬된 것처럼 표시하지 않는다. ‘나머지도 판정’ 실행은 1차 제외다.
등급·순위는 앵커와 그 후보 집합 안에서만 유효하다. 앵커 간 전역 성사 순위·양방향 판정 통합을 만들지 않는다.
이전 결과는 행의 등급 바로 옆에 ‘이전 분석’을 표시하고 최신 추천 집계·기본 필터에서 제외한다. ‘확인 필요’와 전체에서 현재 조건 확인을 우선 제공하며 갱신 중인 마지막 성공 결과는 보존한다.
변경 이유·새 후보 표시는 이벤트 또는 이전 결과 비교로 확인된 사실만 사용한다. 이전 결과는 기준 시각·변경 이유와 함께 참고로만 제공한다. 장부/근거 이동은 현재 존재·권한을 재검사한다.
현재가 바뀌면 원장값과 분석 당시 값을 구분한다. stale 결과를 근거로 확정 연락 문안이나 외부 행동을 만들지 않는다.

## 1차 수용 기준

- 목록·결과 보기·새로고침 10회에 모델 호출/작업 증가 0건. 다른 브라우저도 동일 저장 결과를 복원한다.
- 의미 있는 입력 변경 후 자동 판정, 동일 입력 재사용, 후보 0건의 최종 모델 호출 생략을 검증한다.
- 새 상대 등록·조건 진입·삭제·상담 수정·날짜/모델 변경·빠른 연속 수정에서 잘못된 CURRENT 게시 0건.
- 다른 사무소·삭제 대상·접근 불가 근거 노출 0건. 로그·URL·큐에 상담 원문/연락처/모델 원문 없음.
- AI 5건 전부 기각·미판정 13건에서도 미판정 진입을 제공하고, 이전 강함을 최신 추천으로 집계하지 않는다.
- 후보 담당자/미지정·기록 시각/종류를 제공하고 최근 일반 상담을 해당 쌍의 연락 완료로 표현하지 않는다.
- 필터·탭·페이지·선택 대상은 원장/근거 이동 후 복원되고 미저장 원장 편집을 잃지 않는다.
- Worker 정지·재시작·중복 이벤트·늦은 응답에서 장부 사용 지속과 작업 복구, 이전 성공 결과 보존을 검증한다.
- 준비된 결과 비율·진입 후 사용자 대기·챗봇 p95를 수동 방식과 비교한다. 합격 수치는 [기획 검증안](../../architecture/f3/planning-validation.md)에 제안하고 실측 전 달성으로 쓰지 않는다.

기능 필요성의 페르소나 검토는 실사용자 조사와 구분한다. 검토 결과·반영/보류 사유는 같은 검증 문서에 기록한다.
