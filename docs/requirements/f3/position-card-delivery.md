# F3 포지션 카드 독립 조회 요구사항 검토안

출처: [2026-09-09 사용자 요청](../sources/f3-position-card-review-2026-09-09.md).
독립 API로 카드를 화면에 제공하는 것은 최초 신규 요청이다. 후속 검토의 1차 권고는 [조건부 자동 판정 결과 목록](judgment-results-list.md)이다.
이 문서는 카드 독립 기능을 선택할 때의 보조 대안으로 보존한다. 아래 화면 배치·경로·상태·갱신 정책은 팀 승인·구현 전이다.
정식 요구사항 ID는 합의 후 부여한다. 기존 [F3-PC](position-card.md)의 카드 내용·근거 규격은 재사용한다.

## 목적과 1차 범위

중개사가 교차 판정을 실행하지 않아도 저장된 매물 측·손님 측 포지션과 근거를 확인한다.
매물 상세와 구입장 상세에 포지션 카드 영역을 두는 안을 권고한다. 별도 전체 카드 목록은 후속 후보로 둔다.
대상은 세대가 아니라 `LISTING` 또는 `REQUIREMENT`다. 세대에 매물이 여러 건이면 대상 매물을 명시적으로 선택한다.
최초 분석, 입력 변경 후 갱신, 실패 재시도와 상태 조회까지 포함한다.
카드 직접 편집·이력 비교·문자 발송·일정 생성은 이 신규 범위에 자동 포함하지 않는다.

## 사용자 동작과 수용 기준

| 검토 항목 | 요구 동작·수용 기준 |
|---|---|
| 독립 조회 | 상세 카드 영역을 열면 대상별 GET으로 저장된 카드와 상태를 읽는다. run_id 사전 확보나 교차 판정 실행이 필요 없다 |
| 조회의 부수 효과 | GET은 AI 호출·작업 접수·후보 검색을 하지 않는다. 같은 GET을 10회 호출해 모델 호출 및 생성 작업 증가가 모두 0건이어야 한다 |
| 내용 | 의사·긴급도·거래 유형별 표기가/추정가·마감·양보 가능/불가·접촉 가능성·생성 시각을 표시한다. 미확인 값은 “정보 부족”, 추론은 “추정”으로 구분한다 |
| 근거 | 항목별 근거를 펼칠 수 있고 권한이 있는 원본 상담으로 이동한다. 조회 시 삭제·권한 상실 근거를 노출하지 않는다 |
| 신규·변경 | 카드 입력의 실질 변경을 이벤트로 접수한다. F1 저장은 AI 완료를 기다리지 않는다. 관련 없는 수정은 추가 모델 호출을 만들지 않는다 |
| 최신 여부 | 입력·모델 구성·날짜 기준이 맞을 때만 “최신”으로 표시한다. 생성 시각이 최근이라는 이유만으로 최신으로 간주하지 않는다 |
| 갱신 중 | 접근 가능한 이전 카드는 “이전 분석 · 갱신 중”으로 표시할 수 있다. 처음 만드는 경우에는 빈 카드와 진행 상태를 보여준다 |
| 분석·재시도 | 미생성·오래됨·실패에서는 [분석 생성/갱신/재시도]가 명시적 POST를 보낸다. 카드 작업만 접수하며 교차 판정으로 승격하지 않는다 |
| 반복 요청 | 동일 입력의 유효 카드가 있으면 재사용, 진행 작업이 있으면 같은 작업을 반환한다. 빠른 연속 저장은 미착수 작업을 최신 입력으로 합친다 |
| 경합 | 구버전 작업이 늦게 끝나도 최신 카드를 덮어쓰지 않는다. 최신 작업이 실패해도 이전 접근 가능한 카드와 실패 상태를 구분한다 |
| 화면 복원 | 새로고침·다른 브라우저에서도 DB의 동일 카드를 조회한다. 화면을 닫아도 작업은 지속하며 polling은 중단한다 |
| 장애 | 카드 조회/생성 실패는 카드 영역에 표시하고 F1 조회·편집을 계속 제공한다. 자동 무한 재시도는 하지 않는다 |
| 접근 범위 | 로그인·동일 사무소·현재 대상 접근 권한을 검증한다. 존재하지 않거나 삭제·접근 불가인 대상은 동일한 404 처리 |

## API 검토안

| 경로 | 역할 | 제안 응답 |
|---|---|---|
| `GET /api/v1/f3/position-cards?anchor_type=LISTING&anchor_id=…` | 대상의 현재 카드와 갱신 상태 | 대상이 유효하면 카드 미생성도 200. 대상 없음/접근 불가는 404 |
| `POST /api/v1/f3/position-card-jobs` | `{anchor_type, anchor_id}`의 카드 확보 요청 | 유효 카드 재사용은 200, 신규/진행 작업은 202. 인증·CSRF 검사 |
| `GET /api/v1/f3/position-card-jobs/{job_id}` | 접수한 작업 진행/실패 확인 | 200, 접근 불가는 404 |

응답은 `anchor_type`, `anchor_id`, `card`, `freshness`, `generation`을 분리한다.
`card`는 없으면 null, 있으면 카드 ID·본문·생성 시각·권한 검증된 근거를 포함한다.
`freshness`는 `CURRENT | STALE | NONE`, 갱신 작업 상태는 `IDLE | QUEUED | RUNNING | FAILED`로 제안한다.
서버의 내부 `ANCHOR_READY`를 사용자 상태에 그대로 노출하지 않는다.
완료 작업 조회는 `COMPLETED`와 생성 카드 ID를 반환하고, 대상 조회의 generation은 `IDLE`로 돌아간다.
`SUPERSEDED` 작업은 후속 job_id를 주거나 “최신 입력으로 다시 요청 필요”를 명시한다.
HTTP loading·offline·permission 오류는 저장된 작업 실패와 별도로 표시한다.

첫 조회에 카드가 없으면 명시적 분석 버튼을 제공하는 안이다. 상세 진입 자동 생성은 미확정이며 GET 내부에 숨기지 않는다.
polling은 생성 중에만 수행하고 간격을 늘린다. 화면 이탈·종료 상태에서 중단하며, 오래 걸릴 때는 수동 확인을 제공한다.
원문 개인정보·전체 prompt·모델 원문·내부 모델 설정은 공개 응답이나 브라우저 영속 저장소에 넣지 않는다.
현재 합성 프로토타입 공개 제한을 유지하며 실사용 데이터의 MASKED 입력·조회 권한 적용을 별도 완료해야 한다.

## 교차 판정 연계 요구안

- 판정 결과 보기와 새 판정 실행을 구분한다. 이전 결과는 DB에서 읽고 생성 기준·최신 여부를 보여준다.
- 사용자의 판정 요청은 같은 입력·후보 집합·AI 구성의 유효 완료 결과가 있으면 재사용한다.
- 없거나 오래된 경우에는 기존 비동기 실행을 접수하고 완료 후 DB 결과를 표시한다.
- 새 후보의 등록·조건 변경·삭제와 후보 없음→있음 전환도 완료 결과 최신성에 반영한다.
- 카드만 요청한 작업은 교차 판정으로 자동 승격하지 않는다. 별도의 조건부 자동 판정 작업과 실행 범위를 구분한다.
- 후속 권고는 GPU 상시 운영하에서 조건을 만족한 의미 있는 변경에 자동 판정을 수행하는 것이다. [최신 요구안](judgment-results-list.md)을 따르며 ADR-0018의 후속 개정은 아직 제안이다.

## 합의가 필요한 선택

화면 위치·진입 시 자동 생성·오래된 카드 표시·판정 자동 재계산 대상·날짜 경계와 최신성 SLA는
[프로젝트 미해결 질문](../../../.agents/skills/project-wiki/references/open-questions.md)의 OQ-F3-01~03에서 관리한다.
이번 문서는 요구사항 검토를 위한 정의이며 기존 ADR·공개 API의 승인된 계약을 변경하지 않는다.
