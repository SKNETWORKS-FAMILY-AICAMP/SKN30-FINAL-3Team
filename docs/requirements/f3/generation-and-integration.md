# F3 문안 생성·F1 연동

### 12. 문안 생성

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-GN-01 | 판단 금지 | 문안 생성은 판정 결과를 재료로 쓸 뿐 스스로 판단하지 않는다. 도구를 호출하지 않는다 | 필수 | 설계서 |
| F3-GN-02 | 근거 없으면 강등 | 판정 근거가 없으면 일반 템플릿 문안으로 강등한다. 없는 사실을 문안에 넣지 않는다 | 필수 | 설계서 |
| F3-GN-03 | 초안 성격 | 생성된 문안은 초안이며 사용자가 수정할 수 있다 | 필수 | 설계서 |
| F3-GN-04 | 개인정보 미포함 | 문안에 상대편 당사자의 성명·연락처를 넣지 않는다. "매수 희망자 2명"과 같이 익명 집계로만 표현한다 | 필수 | 신규 |
| F3-GN-05 | 광고성 표기 | 광고성 문안에는 `(광고)` 표기와 무료 수신거부 안내가 들어갈 자리를 확보한다. 실제 요건 충족 여부는 F1이 판단한다 (F1-MS 주의) | 권장 | F1 |
| F3-GN-06 | 템플릿 연계 | F1의 문안 템플릿(F1-MS-11)에 저장하고 재사용할 수 있다 | 권장 | F1 |
| F3-GN-07 | 호출 효율 | 대상 100명 캠페인의 문안 생성 LLM 호출이 10회 이하가 되도록 세그먼트 단위로 생성한다 | 필수 | 설계서 |

### 13. F1 연동

F2의 접점은 화면이지만 **F3의 접점은 데이터**다. F1 9.3장(F1-AG-01 ~ 07)의 대응 규약을 F3 측에서 정의한다.

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F3-IF-01 | 읽기 인터페이스 사용 | F1이 제공하는 정의된 읽기 인터페이스만 사용한다. 화면 스크래핑이나 DB 직접 접근을 하지 않는다 (F1-AG-01) | 필수 | F1 |
| F3-IF-02 | 변경분 조회 | 「특정 시점 이후 바뀐 레코드」 조회를 사용해 캐시를 갱신한다. 매번 전량을 읽지 않는다 (F1-AG-02) | 필수 | F1 |
| F3-IF-03 | 쓰기 범위 | F3가 쓰는 대상은 **상담 로그 추가 · 일정 등록** 두 가지로 한정한다. 세대·손님의 기존 필드를 직접 수정하지 않는다 (F1-AG-03) | 필수 | F1 |
| F3-IF-04 | 일정 등록 | 승인된 일정 제안만 F1에 등록한다. 외부 캘린더 동기화에는 관여하지 않는다 | 필수 | 설계서 |
| F3-IF-05 | 작성 주체 표시 | F3가 만든 로그·일정에 주체를 `F3`로 표시한다. 사람·F2와 구분되어야 한다 (F1-AG-04) | 필수 | F1 |
| F3-IF-06 | 개인정보 최소 수신 | F1에서 전달받는 데이터의 연락처·생년월일은 기본 마스킹 상태로 처리한다. 필요한 경우에만 명시적으로 요청하고 기록을 남긴다 (F1-AG-05) | 필수 | F1 |
| F3-IF-07 | 접근 감사 | F3의 모든 조회·쓰기를 F1의 감사 기록에 남긴다 (F1-AG-06) | 필수 | F1 |
| F3-IF-08 | 정정 결과 기록 | 중개사가 포지션 카드를 정정하면 그 내용을 해당 대상의 상담 로그에 append 한다. 로그는 추가 전용이다 (F1-LG-01) | 필수 | 설계서·F1 |
| F3-IF-09 | 실패 격리 | F3 호출 실패가 F1의 저장·조회를 실패시키지 않는다. F3 영역만 오류를 표시한다 (F1-AG-07) | 필수 | F1 |
