# F3 교차 판정

### 10. 교차 판정 — 인라인

매칭은 배치가 아니라 화면 부속이다. 등록한 순간의 맥락이 살아 있을 때 답이 나와야 한다.

> **[참고]** **가격 변경이 저장 이벤트라는 점이 중요하다.** 112동 401호를 27.5억에서 26.5억으로 내리는 순간, 어제까지 예산이 모자라 빠졌던 손님들이 후보로 올라온다. 별도 배치나 브리핑이 필요 없다.

현재 계약은 [결과 목록 F3-JL-01~06](judgment-results-list.md)과 [ADR-0035](../../../.agents/skills/project-wiki/references/decisions/ADR-0035-f3-conditional-automation-results.md)를 따른다. 아래 인용은 과거 변경 배경이며 저장 시 카드만 생성하던 정책은 부분 대체되었다. 자동 flag는 기본 false이고 공유 dev 배포는 별도다.

> **[2026-08-27 개정]** F3-CR-03·04를 상세 진입 자동 실행에서 버튼 실행으로 바꿨다. 상세를 여는 것만으로 실행이 접수되면 장부를 훑어보는 동안에도 판정이 쌓여, 사용자가 원하지 않은 실행 비용이 생긴다. 배치 화면은 같은 이유로 이미 버튼 실행이다(F3-BT-03). 저장 트리거(F3-CR-01·02)는 그대로다. 저장은 사용자가 명시적으로 일으킨 사건이고 그 순간의 맥락에서 답이 나와야 한다는 이 절의 전제가 유지된다.

> **[2026-08-31 개정]** 상세 저장이 후보 패널을 자동으로 열던 화면 동작을 없앴다. 패널을 여는 순간 화면도 실행을 확보하므로, 저장할 때마다 패널이 열리면 결과를 볼 생각이 없는 저장에서도 판정이 돌아 F3-CR-03·04를 버튼 실행으로 바꾼 이유가 저장 경로로 되살아난다. 서버 쪽 저장 트리거(F3-CR-01·02)는 유지한다. 저장이 접수한 실행은 서버에 남아 있고, 사용자가 상세에서 판정을 요청하면 같은 입력 버전의 활성 실행을 그대로 이어받는다. 같은 이유로 F3-CR-05의 기각 노출 부모에서 `저장 트리거`를 뺐다. 저장이 후보 패널을 열지 않으므로 그 부모에 해당하는 화면이 더 이상 없다. 기각을 접어서 노출하는 부모는 손님 상세(F3-CR-03) 하나이며, 세대 상세(F3-CR-04)가 강함·약함만 보여주는 규칙과 판정을 전부 수행한다는 전제는 바뀌지 않는다.

> **[2026-08-31 개정 2]** 프로젝트 요청자 승인에 따라 F3-CR-01·02의 저장 트리거가 하는 일을 **앵커 포지션 카드 생성까지**로 줄였다. 종전의 저장 1건 = 판정 완주 계약을 대체하며 근거와 대체 범위는 [ADR-0018](../../../.agents/skills/project-wiki/references/decisions/ADR-0018-f3-save-trigger-anchor-card-scope.md)에 있다. 종전에는 저장 하나가 후보 조회와 모델 판정까지 끝까지 돌려, 결과를 볼 생각이 없는 저장에서도 판정 비용이 그대로 들었다. 카드까지는 저장 시점의 맥락으로 만들어 두는 편이 이득이 크므로 남기고, 비용이 큰 후보 조회와 판정은 사용자가 요청할 때 돈다. 저장이 만든 실행은 `ANCHOR_READY` 에서 멈추고, 사용자가 판정을 요청하면 **그 실행을 그대로 이어받아** 후보 조회부터 진행한다. 앵커 카드를 다시 만들지 않으므로 요청 시 추가 카드 비용은 없다.
