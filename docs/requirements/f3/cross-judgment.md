# F3 교차 판정

### 10. 교차 판정 — 인라인

매칭은 배치가 아니라 화면 부속이다. 등록한 순간의 맥락이 살아 있을 때 답이 나와야 한다.

#### 10.1 트리거

| ID | 요구사항 | 상세 | 앵커 / 후보 | 등급 | 출처 |
|---|---|---|---|---|---|
| F3-CR-01 | 손님 저장 | 손님 신규 등록·조건 수정 저장 시 실행 | 손님 카드 / 조건 맞는 매물 | 필수 | 설계서 |
| F3-CR-02 | 매물 저장 | 매물 신규 등록·**가격 변경** 저장 시 실행 | 매물 카드 / 조건 맞는 손님 | 필수 | 설계서 |
| F3-CR-03 | 손님 상세 판정 실행 | 손님 상세의 **[교차 판정] 버튼을 눌러야** 캐시 카드로 실행한다. 상세 진입만으로 자동 실행하지 않는다 | 손님 카드(캐시) / 조건 맞는 매물 | 필수 | 설계서 · 2026-08-27 개정 |
| F3-CR-04 | 세대 상세 판정 실행 | 세대 상세의 **[교차 판정] 버튼을 눌러야** 캐시 카드로 실행한다. 상세 진입만으로 자동 실행하지 않는다 | 매물 카드(캐시) / 조건 맞는 손님 | 필수 | 설계서 · 2026-08-27 개정 |

> **[참고]** **가격 변경이 저장 이벤트라는 점이 중요하다.** 112동 401호를 27.5억에서 26.5억으로 내리는 순간, 어제까지 예산이 모자라 빠졌던 손님들이 후보로 올라온다. 별도 배치나 브리핑이 필요 없다.

> **[2026-08-27 개정]** F3-CR-03·04를 상세 진입 자동 실행에서 버튼 실행으로 바꿨다. 상세를 여는 것만으로 실행이 접수되면 장부를 훑어보는 동안에도 판정이 쌓여, 사용자가 원하지 않은 실행 비용이 생긴다. 배치 화면은 같은 이유로 이미 버튼 실행이다(F3-BT-03). 저장 트리거(F3-CR-01·02)는 그대로다. 저장은 사용자가 명시적으로 일으킨 사건이고 그 순간의 맥락에서 답이 나와야 한다는 이 절의 전제가 유지된다.

> **[2026-08-31 개정]** 상세 저장이 후보 패널을 자동으로 열던 화면 동작을 없앴다. 패널을 여는 순간 화면도 실행을 확보하므로, 저장할 때마다 패널이 열리면 결과를 볼 생각이 없는 저장에서도 판정이 돌아 F3-CR-03·04를 버튼 실행으로 바꾼 이유가 저장 경로로 되살아난다. 서버 쪽 저장 트리거(F3-CR-01·02)는 유지한다. 저장이 접수한 실행은 서버에 남아 있고, 사용자가 상세의 **[교차 판정]** 섹션에서 실행을 누르면 같은 입력 버전의 활성 실행을 그대로 이어받는다.
