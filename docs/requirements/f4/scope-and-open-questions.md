# F4 제외 범위·미착수 서비스·미해결 사항

## 1. 미착수 서비스

아래 세 서비스는 F4에 속하지만 **아직 설계도 구현도 하지 않았다.** 사용자가 처음 제시한 방향만
기록하며 확정된 요구사항이 아니다. 실제로 만들 때 각 서비스 문서를 이 폴더에 추가한다.

### 1.1 뉴스 요약

날짜를 기준으로 부동산 관련 뉴스를 찾아 요약한다.

먼저 답해야 할 것.

| 질문 | 왜 걸리는가 |
|---|---|
| 뉴스 출처를 무엇으로 할 것인가 | 저장소에 외부 검색·수집 연동이 하나도 없다. `ai/`는 OpenAI SDK만, `backend/`는 런타임 HTTP 클라이언트가 없다 |
| 수집 주체를 어디에 둘 것인가 | AI 모듈은 외부 I/O를 소유하지 않는다(ADR-0006). Backend adapter 또는 `data/` 파이프라인 중 하나를 정해야 한다 |
| 기사 본문 저장과 요약 재배포가 허용되는가 | 라이선스·저작권 확인이 필요하다 |
| 요약에 근거를 어떻게 붙이는가 | 원문 링크와 발행일을 필수로 걸지 않으면 환각 요약이 그대로 화면에 나간다 |

F3 17장이 「시세·실거래 폴링」을 「중개사가 직접 확인하는 영역」으로 제외한 판단과 성격이 비슷하다.
뉴스는 왜 다른지 설명이 필요하다.

### 1.2 문자 발송 초안

만기 안내, 신규 매물 알림 등 필요한 문자의 초안을 만든다.

**이미 정의된 요구사항이 있다.** 새로 쓰기 전에 아래를 먼저 읽고 무엇을 F4로 옮길지 정한다.

- [F1 연락 대상 및 문자 발송](../f1/messaging.md) — `F1-MS-01~16`. 초안·템플릿·치환 변수·수신 거부·
  최종 확인·발송 어댑터
- [F3 문안 생성](../f3/generation-and-integration.md) — `F3-GN-01~07`. 판단 금지, 근거 없으면 강등,
  개인정보 미포함, 호출 효율
- [F3 배치 판정](../f3/batch.md) — `F3-BT-13~20`. 세그먼트별 문안, 변수 치환, 일괄 승인, 실발송 경계

실발송은 계속 범위 밖이다. `F1-MS-14`의 전제(발신번호 사전등록, `(광고)` 표기, 무료 수신거부 안내,
야간 발송 금지, 수신 동의 이력)가 충족되기 전에는 어댑터를 활성화하지 않는다.

### 1.3 블로그 광고글 초안

사용자가 제공한 글에서 어투를 파악해 광고글 초안을 만든다.

| 질문 | 왜 걸리는가 |
|---|---|
| 어투 샘플을 저장하는가 | 저장하면 보존 기간과 삭제 절차 대상이 된다([OQ-007](../../../.agents/skills/project-wiki/references/open-questions.md)). 세션 내 1회 사용으로 끝낼 수도 있다 |
| 매물을 특정하는 광고글인가 | 특정하면 중개대상물 표시·광고 명시의무 대상이다. 일반 정보성 글이면 위험이 낮다 |
| 품질을 어떻게 평가하는가 | 어투 일치도는 정량 지표 설계가 어렵다. 현재 MVP의 평가 축과 맞지 않는다 |

## 2. 제외 범위

| 항목 | 어디 소속 | 사유 |
|---|---|---|
| 양측 포지션 판단·거래 가능성 판정 | F3 | F4는 판단하지 않는다 (`F4-CM-01`) |
| 일정 데이터 저장·캘린더 동기화 | F1 | F1-SC가 소유한다. F4는 읽기만 한다 |
| 계약 건 관리 | F1 | F1-CT가 소유한다 |
| 문자 실발송 | F1 | F1-MS-14의 발송 어댑터를 통한다 |
| 가격 평가·법률 판단 | 제외 | 책임 소재가 시스템 밖에 있다 |
| 앱을 열지 않아도 닿는 알림 | 미확정 | 서버 스케줄러와 발송 채널이 함께 필요하다. 아래 3번 참조 |

## 3. 미해결 사항

| # | 질문 | 영향 | 연결 |
|---|---|---|---|
| 1 | 기준값을 사무소별 설정으로 둘 것인가 | 브리핑 시각과 창 길이, 알림 빈도 | [OQ-011](../../../.agents/skills/project-wiki/references/open-questions.md) |
| 2 | 오래 방치된 재연락 대상을 어디에서 드러낼 것인가 | 일정 목록 범위와 미접촉 캠페인의 경계 | [OQ-013](../../../.agents/skills/project-wiki/references/open-questions.md) |
| 3 | 앱을 열지 않아도 닿는 알림이 필요한가 | 필요하면 서버 스케줄 실행 계층과 발송 채널이 새로 필요하고, 「정기 스케줄 실행을 두지 않는다」는 `F3-CM-01`과 F3 설계 원칙 4의 개정이 선행된다. `agent_run.requested_by`가 NOT NULL이라 사람이 아닌 실행의 요청자 처리도 함께 정해야 한다 | 신규 |
| 4 | 미착수 세 서비스를 이번 MVP 안에 넣을 것인가 | [현재 MVP 범위](../common/mvp-scope-and-evaluation.md)는 F2·F3 시연·평가를 우선한다. F4 확장은 그 범위를 넓히는 결정이다 | 신규 |
