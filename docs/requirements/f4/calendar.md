# F4 캘린더 — 일정 CRUD와 월간 뷰

사용자가 캘린더 화면에서 직접 일정을 추가·수정·삭제한다. Time Keeper(F4-TK)가 장부에서 계산해
읽는 일정과 저장은 분리하지만, "다가오는 일정"과 캘린더가 같은 목록을 두 형태로 보여준다는
원칙에 따라 조회는 하나로 합친다([ADR-0025](../../../.agents/skills/project-wiki/references/decisions/ADR-0025-calendar-storage-ownership.md)).

> **[제안]** 아래 요구사항은 **코드로 구현되고 검증됐지만 팀 승인 전이다.** Time Keeper 문서와
> 같은 이유로 상태가 `제안`이다. F2 음성 인식 기반 자동 일정 추가는 이 문서의 범위가 아니다 —
> F2가 아직 상담 발화에서 일정을 구조화 데이터로 뽑아내지 못하므로 별도 후속 작업으로 남는다.

## 1. 저장

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F4-CAL-01 | 캘린더 일정 CRUD | 사용자가 제목·종류·날짜·시작/종료 시각·장소·메모를 갖는 일정을 만들고 고치고 지운다. 저장은 F4가 소유한 `calendar_event` 테이블이며 F1 장부 테이블과 별개다 | 필수 | 신규 |
| F4-CAL-02 | 낙관적 잠금 | 수정·삭제는 `row_version`이 일치해야 한다. 다른 사용자가 먼저 저장했으면 409로 거절한다 | 필수 | F1-GR-26과 동일 원칙 |
| F4-CAL-03 | 장부 연결 없음 | 이번 범위는 일정을 특정 세대·매물·손님에 연결하지 않는다. 연결이 필요해지면 다음 번호의 ALTER migration으로 확장한다 | 필수(범위 제한) | 신규 |
| F4-CAL-04 | 종류는 열린 값 | 종류는 고정 열거형이 아니다. 화면은 임장·계약·잔금·이사·기타를 기본으로 제안하되 서버는 임의 문자열을 그대로 저장한다 | 필수 | F4-TK-01과 동일 원칙 |

## 2. "다가오는 일정"과의 통합

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F4-CAL-05 | Time Keeper 조회 통합 | `GET /api/v1/time-keeper/agenda`는 캘린더 일정을 여덟 번째 갈래로 포함한다. 사용자가 캘린더에서 만든 일정은 상단바 "다가오는 일정" 배지·목록·아침 브리핑에도 함께 뜬다 | 필수 | 사용자 확인, 2026-09-04 |
| F4-CAL-06 | 대상 표기 | 캘린더에서 온 행은 세대·구입장 필드가 모두 비고 제목을 대상 이름으로 세운다. 장소가 있으면 함께 표시한다 | 필수 | F4-TK-13 확장 |
| F4-CAL-07 | 연락 대상 없음 | 캘린더에서 온 행은 연결된 인물이 없으므로 "연락처 없음" 같은 장부 전용 문구를 그리지 않는다 | 필수 | 신규 |
| F4-CAL-08 | 창 규칙 공유 | 캘린더 일정은 날짜가 그대로 저장된 갈래로 취급해 F4-TK-07의 앞뒤 창(양끝 포함)을 그대로 적용한다. 재연락·재확인처럼 아래쪽 경계를 열어 두지 않는다 | 필수 | F4-TK-07 |

## 3. 월간 그리드

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F4-CAL-09 | 월간 뷰 | 상단바의 별도 진입점(달력 버튼)이 월간 그리드 창을 연다. Time Keeper의 "다가오는 일정" 버튼·브리핑과는 다른 진입점이며 서로의 동작에 영향을 주지 않는다 | 필수 | 사용자 확인, 2026-09-04 |
| F4-CAL-10 | 데이터 이중화 없음 | 월간 그리드는 캘린더 일정을 `GET /api/v1/calendar/events`로 직접 읽고, 장부 읽기 전용 일정은 Time Keeper 조회 결과 중 캘린더 갈래를 제외한 부분을 겹쳐 그린다. 같은 일정을 두 번 그리지 않는다 | 필수 | 신규 |
| F4-CAL-11 | 날짜 칸 상호작용 | 날짜 칸의 "+"가 그 날짜로 미리 채운 생성 폼을 연다. 캘린더 일정 칩을 클릭하면 수정 폼이 열린다. 장부 읽기 전용 항목은 클릭할 수 없다 | 필수 | 신규 |

## 4. 수용 기준

| # | 기준 | 검증 방법 |
|---|---|---|
| 1 | 캘린더 일정을 만들면 같은 날짜의 "다가오는 일정" 목록과 배지 건수에도 나타난다 | 통합 테스트 · 화면 확인 |
| 2 | 캘린더 일정 행에는 "연락처 없음" 문구가 뜨지 않는다 | 화면 확인 |
| 3 | 낡은 `row_version`으로 수정·삭제하면 409가 온다 | 통합 테스트 |
| 4 | 다른 중개사무소의 캘린더 일정이 조회되지 않는다 | 통합 테스트 |
| 5 | 조회 창(`within_days`·`overdue_days`) 경계 날짜의 캘린더 일정이 포함된다 | 통합 테스트 |
| 6 | 서버가 모르는 종류 문자열이 와도 화면이 죽지 않는다 | 단위 테스트 |
| 7 | 캘린더 일정을 삭제하면 월간 그리드와 "다가오는 일정" 양쪽에서 사라진다 | 화면 확인 |
