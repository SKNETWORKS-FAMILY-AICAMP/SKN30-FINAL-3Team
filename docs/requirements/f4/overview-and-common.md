# F4 개요·구성·공통 요구사항

> **[결정 · 2026-09-03] 기능 번호:** 사용자 지시로 F4를 독립 기능으로 두고, Time Keeper를 그 안의
> 서비스 하나로 둔다. 아래 구성 표의 서비스 중 **Time Keeper만 구현됐고 나머지는 미착수**다.
> 미착수 서비스의 상세 동작은 승인된 요구사항이 아니므로 이 문서에서 확정 사실로 쓰지 않는다.

## 1. 개요

### 1.1 목적

F4는 중개사가 하루를 시작하고 반복 업무를 처리하는 데 쓰는 보조 기능을 모은다. F1이 저장한 장부와
상담 기록을 재료로 쓰되, F3처럼 양측 입장을 판단하지 않고 **이미 정해진 사실을 제때 꺼내 놓거나
사용자가 고칠 초안을 만든다.**

F3와 갈리는 지점이 여기다. F3는 조건표에 안 들어간 말을 읽어 거래 가능성을 판단한다. F4는 판단하지
않는다. 만기일은 장부에 적힌 날짜이고, 재연락 시점은 마지막 접촉에서 세는 값이며, 문자 초안은 이미
나온 결과를 문장으로 옮기는 일이다.

### 1.2 범위

| 구분 | 내용 |
|---|---|
| 포함 | 일정·할 일 브리핑(Time Keeper) · 뉴스 요약 · 문자 발송 초안 · 블로그 광고글 초안 |
| 제외 | 실발송 · 계약 판단 · 가격 평가 · 법률 판단 · 양측 포지션 판단(F3 소유) |
| 타 기능 경계 | 저장·조회·화면은 F1, 음성 인식은 F2, 양측 판단은 F3 |

### 1.3 구성 서비스

| 서비스 | 내용 | 상태 | 문서 |
|---|---|---|---|
| Time Keeper | 장부의 날짜에서 일정·할 일을 모아 아침에 알린다 | **구현됨** | [time-keeper.md](time-keeper.md) |
| 뉴스 요약 | 날짜 기준으로 부동산 뉴스를 찾아 요약한다 | 미착수 | [scope-and-open-questions.md](scope-and-open-questions.md) |
| 문자 초안 | 만기 안내·매물 등록 알림 등 문자 초안을 만든다 | 미착수 | 같은 문서 |
| 블로그 초안 | 사용자 글의 어투를 반영한 광고글 초안을 만든다 | 미착수 | 같은 문서 |

미착수 서비스는 대상 데이터와 외부 연동이 확정되지 않았다. 상세 요구사항은 각 서비스를 실제로
설계할 때 이 폴더에 파일을 추가한다. 빈 파일을 미리 만들지 않는다.

## 2. 공통 요구사항

| ID | 요구사항 | 상세 | 등급 | 출처 |
|---|---|---|---|---|
| F4-CM-01 | 판단하지 않는다 | F4는 장부에 있는 사실과 이미 나온 결과를 재료로 쓴다. 양측 포지션 판단과 거래 가능성 판정은 F3가 소유한다 | 필수 | 신규 |
| F4-CM-02 | 날짜 계산은 코드가 한다 | 만기·기한·경과일 계산에 모델을 쓰지 않는다. F3 17장의 「날짜 계산 → 코드. LLM은 날짜 산수를 틀린다」와 같은 판단이다 | 필수 | F3 |
| F4-CM-03 | 없는 데이터를 만들지 않는다 | 장부에 대응 컬럼이 없는 항목은 화면에 종류 자체를 만들지 않는다. 빈 값을 0건으로 채워 있는 것처럼 보이게 하지 않는다 | 필수 | 신규 |
| F4-CM-04 | 승인 전 확정 금지 | F4가 만든 초안과 제안은 사용자가 확인하고 승인해야 F1 데이터가 되거나 외부로 나간다 | 필수 | F3-CM-03 |
| F4-CM-05 | F4 없이 F1 동작 | F4가 응답하지 않아도 F1의 모든 기능이 정상 동작한다. F4 영역만 실패 상태를 표시하고 재시도를 제공한다 | 필수 | F1-AG-07 |
| F4-CM-06 | 쓰기 범위 | F4는 F1의 장부 필드를 직접 고치지 않는다. 현재 구현된 Time Keeper는 조회만 한다 | 필수 | F1-AG-03 |
| F4-CM-07 | 언어 | 화면 문구와 생성 문안은 한국어로 만들고 현업 표기를 그대로 쓴다 | 필수 | F3-CM-07 |
| F4-CM-08 | 기준 시각 | 업무일과 기한은 중개사무소 시간대(UTC+09:00)로 정한다. UTC 날짜를 쓰면 한국 시각 오전 9시 이전에 하루가 밀린다 | 필수 | 신규 |

## 3. F1 알림 요구사항과의 관계

F1은 이미 알림 요구사항을 갖고 있다. F4는 그것을 대체하지 않고 **F4 쪽 구현으로 채운다.** 같은
상세를 두 곳에 복제하지 않으며 대응 관계만 아래에 둔다.

| F1 요구사항 | F4에서 채우는 방식 |
|---|---|
| F1-AL-01 만기 도래 알림 | `F4-TK-02` 임대차 만기를 일정 목록에 싣는다 |
| F1-AL-03 미접촉 알림 | `F4-TK-04` 마지막 접촉에서 재연락 기한을 만들고 오래 방치된 대상일수록 목록 위에 세운다 |
| F1-AL-04 알림 센터 | `F4-TK-08` 상단바 알림 버튼이 목록을 연다 |
| F1-AL-05 알림 규칙 설정 | 미구현. 기준값은 코드 상수이며 [OQ-011](../../../.agents/skills/project-wiki/references/open-questions.md)에 있다 |
| F1-AL-02 일정 임박 알림 | 미구현. 일정 테이블(F1-SC)이 없다 |
| F1-AL-06 담당자 귀속 | 미구현. 응답에 `assigned_user_id`를 싣지만 담당자별 필터는 없다 |
