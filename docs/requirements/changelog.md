# 요구사항 변경 이력

- 2026-09-08 (`CHATBOT-IMPLEMENT-20260908`): 사용자 구현 요청에 따라 F4 챗봇 1차와 DB 저장·복원을 구현했다. 정확도·안전성·warm 성능은 필수로, 팀원 사용성 평가는 후속으로 정했다. 후속 지시에 따라 Qwen 기동·실제 평가는 보류하고 Luna로 검증한다. 공유 dev DB 변경·배포는 제외한다. [범위 출처](sources/chatbot-implementation-scope-2026-09-08.md)와 [검증 결과](../architecture/chatbot/implementation-and-validation.md)를 연결한다.

- 2026-09-08: `F4-TK-04`(재연락 기한)를 폐기로 표시하고 Time Keeper의 세대·손님 재연락 계산과
  화면 표시를 모두 제거함(사용자 요청, 사유는 별도로 확인되지 않음). `LISTING_RECONTACT`·
  `CLIENT_RECONTACT` 종류와 `recontact_days` 조회 파라미터를 API·도메인·화면에서 함께 뺐다.
  `F4-TK-05`(매물 조건 재확인)는 영향 없이 유지되며, "밀린 재연락·재확인" 묶음(`F4-TK-22`)은
  "밀린 재확인"으로 이름을 바꿔 재확인만 남긴다. F1-AL-03(미접촉 알림)은 F4 쪽 구현을 잃어
  다시 미구현 상태다.
- 2026-09-08: `F1-DM-02`(구입장 기간 필터)를 폐기로 표시하고 화면에서 「3개월 이내만 보기 / 모두 보기」
  토글을 제거함. `F1-SR-01`(동-호 호출)의 상세 표시 방식을 상세 팝업을 여는 것에서 매물장 그리드
  안에서 해당 행을 스크롤·강조하는 것으로 바꿈. 구입장 상세 상담 로그에 음성 메모 입력 버튼을
  추가하고(기존 F2 연동 재사용), 구입장 그리드에 매물장과 같은 방식의 행 선택·일괄 삭제를 추가해
  `F1-DM-06`(손님 추가·삭제)의 삭제 쪽 구현을 채움. 모두 사용자 요청에 따른 변경이다.

- 2026-09-08: `F1-GR-10`(장부 구분 탭)을 폐기로 표시함. 현재 다루는 매물이 아파트뿐이라 상가·주택·
  재건축 탭을 화면에서 제거함. F1 열려 있던 질문 7 「상가·주택·재건축 탭도 실제로 쓰는가」를
  해소함(2026-09-08 사용자 확인).

- 2026-09-08 (`CHATBOT-DESIGN-20260908`): 사용자와 9개 설계 항목을 합의했다. F4 소속·조회 3종/F2 연결·DB 저장/복원·작성자 접근·사용자당 대화 1개·삭제/환경 폐기까지 보존·운영 DB 즉시 전체 삭제·직전 2회 문맥·브라우저 종료 후 서버 처리 지속을 계획에 반영했다. 서버 중단 후 자동 재실행과 SSE 재생은 제외하고 OQ-CHAT-01·02를 해소했다. 구현은 미착수다.

- 2026-09-08 (`CHATBOT-PLAN-20260908`): 챗봇 범위·수용 기준을 제안으로 추가했다. 사용자 선택인 기존 F2 화면 연결과 F3 개발 보류를 반영하고, 자연어 읽기 조회·SSE·최근 2회 문맥·선택 실거래 요약을 검토했다. 기능 번호·기존 MVP·승인 계약은 변경하지 않았다.

- 2026-09-04: F4 캘린더(`F4-CAL-01~11`)를 신설하고 구현함. 사용자가 캘린더 화면에서 직접 일정을
  만들고 고치고 지운다. 저장은 F4가 소유한 `calendar_event` 테이블이며, 기존 문서가 "일정 저장은
  F1(F1-SC)이 소유한다"고 정리했던 것을 이 범위에서 뒤집었다([ADR-0025](../../.agents/skills/project-wiki/references/decisions/ADR-0025-calendar-storage-ownership.md)).
  `GET /time-keeper/agenda`가 캘린더 일정을 여덟 번째 갈래로 포함하도록 확장되어, 캘린더에서 만든
  일정이 "다가오는 일정"의 배지·목록·아침 브리핑에도 함께 뜬다. F2 음성 인식 기반 자동 일정 추가는
  이번 범위에 없다.
- 2026-09-04: `F4-TK-22`를 신설함. `F4-TK-04`·`F4-TK-05`가 아래쪽 경계 없이 목록에 남기는 재연락·재확인 중 되돌아보는 기간을 넘긴 것을 화면이 "밀린 재연락·재확인" 묶음으로 따로 보여주고, 행마다 "다시 보지 않기"로 이 브라우저에서만 감출 수 있게 함. 사용자가 "371일 지난 일정까지 왜 표시되는지" 문의한 데서 비롯됨 — 서버 동작은 F4-TK-04·07 그대로 두고 화면 표시만 나눈다.
- 2026-09-03: `F4-TK-04`·`F4-TK-05`의 재연락·매물 재확인에서 되돌아보는 창을 떼어냈다. 창을 함께 걸면 마지막 접촉이 37일보다 오래된 대상이 목록에서 빠져 「일정 기간 이상 접촉이 없는 대상을 알린다」는 F1-AL-03을 채우지 못했다. `F4-TK-07`의 되돌아보는 기간은 장부에 날짜가 적힌 종류에만 적용한다(OQ-013 종료).
- 2026-09-03: 사용자 요청으로 F4를 독립 기능으로 두고 Time Keeper를 그 안의 서비스로 정의하는 안을 `제안` 상태로 추가함. 팀 승인 전까지 `결정`으로 올리지 않는다. `F4-CM-01~08`과 `F4-TK-01~21`을 신설했으며 F1-AL-01·03·04를 F4 쪽 구현으로 채우는 대응 관계를 명시함. 뉴스 요약·문자 초안·블로그 초안은 F4에 속하지만 미착수로 남기고 상세 문서를 만들지 않음. 계약 체결일·지급일·임장일·신고 기한·명도일은 대응 테이블이 없어 Time Keeper 대상에서 제외함.
- 2026-08-31: F3-CR-01·02의 저장 트리거 범위를 앵커 포지션 카드 생성까지로 축소하고, F3-CR-03·04의 판정 요청이 저장이 만든 실행을 이어받도록 개정함. 저장 하나가 모델 판정까지 끝내던 종전 동작을 대체하며 후보 조회·판정 시점은 사용자가 정한다. F3-CR-05의 기각 노출 부모에서 저장 트리거를 뺌.
- 2026-08-31: 프로젝트 요청자의 명시적 승인에 따라 F3-BR-12·13의 최초 카드화·AI 판정 상한을 15건에서 5건으로 변경함. 기존 15건 규칙을 대체하되 전체 SQL 후보·결정적 순위·남은 건수·페이징은 유지함.
- 2026-08-27: F3-CR-03·04 교차 판정 트리거를 상세 진입 자동 실행에서 상세의 [교차 판정] 버튼 실행으로 개정함. 상세를 여는 것만으로 실행이 접수되어 사용자가 원하지 않은 판정 비용이 생겼고, 배치 화면은 같은 이유로 이미 버튼 실행이다(F3-BT-03). 저장 트리거 F3-CR-01·02와 Backend 자동 접수는 그대로 둔다.
- 2026-08-17: F1을 최소 데이터 인터페이스로 축소하고 F2 입력 자동화와 F3 멀티 에이전트 판단의 시연·평가를 우선하는 현재 MVP 범위 정본을 추가함. 기존 상세 요구사항은 후속 제품 백로그로 보존함.
- 2026-08-14: 사용자가 제공한 F1·F2·F3 통합 요구사항을 출처 스냅샷으로 보존하고, 기능 내용을 바꾸지 않은 채 공통·F1·F2·F3 검색 의도별 문서로 분할함.
- 2026-08-14: 요구사항 관리 정본을 분할 문서로 정하고 라우터, 변경 절차와 구현·테스트 추적 골격을 추가함.
