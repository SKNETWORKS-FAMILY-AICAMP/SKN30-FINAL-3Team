# 요구사항 변경 이력

- 2026-09-03: `F4-TK-04`·`F4-TK-05`의 재연락·매물 재확인에서 되돌아보는 창을 떼어냈다. 창을 함께 걸면 마지막 접촉이 37일보다 오래된 대상이 목록에서 빠져 「일정 기간 이상 접촉이 없는 대상을 알린다」는 F1-AL-03을 채우지 못했다. `F4-TK-07`의 되돌아보는 기간은 장부에 날짜가 적힌 종류에만 적용한다(OQ-013 종료).
- 2026-09-03: 사용자 지시로 F4를 독립 기능으로 추가하고 Time Keeper를 그 안의 서비스로 정의함. `F4-CM-01~08`과 `F4-TK-01~21`을 신설했으며 F1-AL-01·03·04를 F4 쪽 구현으로 채우는 대응 관계를 명시함. 뉴스 요약·문자 초안·블로그 초안은 F4에 속하지만 미착수로 남기고 상세 문서를 만들지 않음. 계약 체결일·지급일·임장일·신고 기한·명도일은 대응 테이블이 없어 Time Keeper 대상에서 제외함.
- 2026-08-31: F3-CR-01·02의 저장 트리거 범위를 앵커 포지션 카드 생성까지로 축소하고, F3-CR-03·04의 판정 요청이 저장이 만든 실행을 이어받도록 개정함. 저장 하나가 모델 판정까지 끝내던 종전 동작을 대체하며 후보 조회·판정 시점은 사용자가 정한다. F3-CR-05의 기각 노출 부모에서 저장 트리거를 뺌.
- 2026-08-31: 프로젝트 요청자의 명시적 승인에 따라 F3-BR-12·13의 최초 카드화·AI 판정 상한을 15건에서 5건으로 변경함. 기존 15건 규칙을 대체하되 전체 SQL 후보·결정적 순위·남은 건수·페이징은 유지함.
- 2026-08-27: F3-CR-03·04 교차 판정 트리거를 상세 진입 자동 실행에서 상세의 [교차 판정] 버튼 실행으로 개정함. 상세를 여는 것만으로 실행이 접수되어 사용자가 원하지 않은 판정 비용이 생겼고, 배치 화면은 같은 이유로 이미 버튼 실행이다(F3-BT-03). 저장 트리거 F3-CR-01·02와 Backend 자동 접수는 그대로 둔다.
- 2026-08-17: F1을 최소 데이터 인터페이스로 축소하고 F2 입력 자동화와 F3 멀티 에이전트 판단의 시연·평가를 우선하는 현재 MVP 범위 정본을 추가함. 기존 상세 요구사항은 후속 제품 백로그로 보존함.
- 2026-08-14: 사용자가 제공한 F1·F2·F3 통합 요구사항을 출처 스냅샷으로 보존하고, 기능 내용을 바꾸지 않은 채 공통·F1·F2·F3 검색 의도별 문서로 분할함.
- 2026-08-14: 요구사항 관리 정본을 분할 문서로 정하고 라우터, 변경 절차와 구현·테스트 추적 골격을 추가함.
