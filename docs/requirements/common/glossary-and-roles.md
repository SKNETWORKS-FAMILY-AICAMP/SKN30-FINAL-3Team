# 공통 용어·역할·AI 구조

### 0.6 통합 용어

세 부에서 공통으로 쓰는 용어. 각 부의 고유 용어는 해당 부의 용어 절을 따른다.

| 용어 | 정의 | 정의 위치 |
|---|---|---|
| 세대 | 단지 내 개별 호실. 매물 여부와 무관하게 존재하는 장부의 기본 단위 | 제1부 2.1 |
| 매물 | 세대가 거래 대상이 된 상태. 세대에 종속되며 소멸·재생성될 수 있다 | 제1부 2.1 |
| 매물장 · 세대전체장부 | 세대 전수 대장. 현행 장부의 기본 화면 | 제1부 2.1 · 제2부 2 |
| 구입장 · 손님대장 | 손님(수요) 대장 | 제1부 2.1 · 제2부 2 |
| 상담 로그 | `[YY-MM-DD HH:MM 주①]본문` 포맷의 append 텍스트 | 제1부 2.1 · 7장 |
| 인물 인덱스 | 로그·연락처의 `①②③`. 같은 역할에 인물이 여러 명일 때의 순번 (남편 ①, 아내 ②) | 제1부 2.1 · 7.1 |
| 현상태 / 현매물 / 명도 / 경신 / 월환 / 붙박이 | 현업 표기. 시스템이 데이터와 함께 보관해야 할 정보 | 제1부 2.1 · 14장 |
| 상담 유형 | 매도의뢰 · 매수문의 · 기타상담 | 제2부 5.4 |
| 포지션 카드 | 대리 에이전트의 출력 규격. 당사자 한 명의 실제 입장 | 제3부 4장 |
| 앵커 / 후보 | 판정 기준이 되는 한쪽 카드 / 반대편에서 조회된 대상 | 제3부 2.1 |
| 교차 판정 / 배치 판정 | 앵커 1:후보 N 인라인 판정 / 같은 쪽 N건 배치 판정 | 제3부 2.1 · 10장 · 11장 |

### 0.7 사용자 역할 (공통)

| 역할 | 대응 | F1 | F2 | F3 |
|---|---|---|---|---|
| 소유자 | 개업공인중개사 | 전체 조회·편집 · 직원 관리 · 삭제 · 마스터 관리 | 실행·승인 | 실행·승인 · 캠페인 발송 |
| 직원 | 실장 · 김이순 | 전체 조회·편집 · 본인 담당 건 삭제 | 실행·승인 | 실행·승인 · 캠페인은 승인 필요 |
| 읽기전용 | 보조 인력 | 조회만. 개인정보 필드 마스킹 | 불가 | 마스킹된 결과 조회만 (F3-SE-05) |

### 0.8 AI 사용 구조

| 구분 | F2 | F3 |
|---|---|---|
| 모델 위치 | RunPod Whisper (STT) + 로컬 LLM (분류·슬롯 필링) | 미확정 (제3부 19장 2번) |
| 호출 시점 | 사용자가 [분석 실행] | 저장·조회·캠페인 실행 |
| 전달 데이터 | 음성 → RunPod / STT 텍스트 + 장부 종류 → 로컬 LLM | 구조화 데이터 + 상담 로그 (연락처·생년월일 마스킹) |
| 금지 | 장부 기존 데이터를 RunPod에 전달하지 않는다 | 반대편 로그를 대리에게 전달하지 않는다 |
| 보존 | RunPod에 음성·STT 영구 저장 금지 | 실행 로그 보관 기간 설정 후 파기 |

> **[확인]** **자원 경합** — F2의 로컬 LLM과 F3가 같은 자원을 쓰면 교차 판정 5초 목표(F3-NF-01)와 F2 분석 응답이 서로를 밀어낸다. 모델 배치를 확정하기 전에 동시 실행 시나리오를 정해야 한다 (제3부 19장 2번).
