# 챗봇 1차 설계 선택 기록

2026-09-08 같은 Codex 대화에서 사용자가 선택한 내용이다. 선택 기록은 변경하지 않고 후속 변경은 별도 기록한다.
사용자 요청: “설계 범위와 open question을 지금 저랑 정합시다”.

| 질문 범위 | 사용자 답변 |
|---|---|
| 1차 기능 | 매물·구입장·할 일 조회 + F2 연결 (권장) |
| DB 범위 | DB 설계와 저장·복원까지 구현 (권장) |
| 대화 접근 | 작성한 사용자만 조회·삭제 (권장) |
| 보존 기간 | 사용자가 삭제하거나 시연 환경을 폐기할 때까지 보존 |
| 삭제 방식 | 삭제 요청 시 운영 DB에서 즉시 삭제 |
| 모델 문맥 | 직전 2회 질문·답변 (권장) |
| 기능 소속 | F4 업무 비서 안의 챗봇 서비스 (권장) |
| 화면 관리 | 사용자당 대화 1개, 이력 조회·전체 삭제만 제공 |
| 새로고침·탭 종료 | 서버 처리는 계속하고 완료 결과를 저장 (권장) |

질문에 제시된 공통 조건:

- F2는 기존 화면 연결, F3 실행 연동과 시세 기능은 후속 범위다.
- DB 저장·복원은 대화방·메시지·요청 상태를 저장하고 새로고침 후 이력·상태를 조회한다.
- 서버 중단 후 실행 자동 재개와 SSE 이벤트 재생은 제외한다. 서버 자체가 중단되면 수동 재시도를 제공한다.
- 현재 dev 공용 합성 계정은 같은 사용자로 취급된다. 실제 사람별 분리는 별도 계정·인증이 필요하다.
- 삭제 대상은 대화·메시지·요청 기록이며, 향후 연결될 F3 감사 이력은 별도 삭제 정책을 따른다.
- 모든 문맥 선택안은 현재 검색 조건과 전체 입력 토큰 상한을 함께 적용한다.
- 기능 소속과 관계없이 UI는 공통 셸에 배치하고 F1 조회·F2 입력·F3 판단의 책임을 유지한다.

이 기록은 사용자 설계 합의의 출처다. 팀 병합 승인, 코드·SQL 구현, 실제 DB 배포가 완료되었다는 의미가 아니다.
