# 업무 챗봇 범위·요구사항 검토안

F4 업무 비서의 챗봇 서비스 요구사항 정본이다. [설계 합의](../sources/chatbot-design-decisions-2026-09-08.md)와 [구현 요청·평가 범위 조정](../sources/chatbot-implementation-scope-2026-09-08.md)을 반영해 코드를 구현하고 로컬에서 검증했다. 공유 dev에는 미배포이며 세부 요구사항 ID는 부여하지 않았다.
도입 타당성과 일정은 [도입 검토](../../architecture/chatbot/overview.md), 화면은 [화면안](../../screen/chatbot.md), 구현은 [실행 구조](../../architecture/chatbot/runtime.md)를 따른다.

## 요청에서 확인된 방향

| 상태 | 내용 |
|---|---|
| 사용자 요청 | F2·F3 연동을 고려하되 F3 연동 개발은 보류한다. 자연어 쿼리와 DB 기반 기능을 검토한다. |
| 사용자 선택 | 첫 F2 연동은 챗봇에서 기존 F2 화면으로 연결한다. |
| 사용자 요청 | 우측 하단 플로팅 버튼, 첫 화면 소개·추천 질문, SSE 진행·검색 표시를 제공한다. |
| 사용자 후속 지시 | local Luna로 구현·평가한다. RunPod가 필요한 Qwen 실제 평가는 보류한다. 멀티턴 한계를 화면에 안내한다. |
| 선택 기능 | 공공 API 기반 시세분석. [조사 결과](../../architecture/chatbot/public-market-data.md)를 보고 별도 착수한다. |
| 사용자 설계 합의 | F4 소속, 조회 3종·F2 연결, DB 저장·복원, 사용자별 대화 1개·작성자 접근, 직전 2회 문맥 |
| 사용자 설계 합의 | 사용자 삭제/환경 폐기까지 보존, 운영 DB 즉시 전체 삭제, 탭 종료 후 처리 지속·결과 저장 |
| 구현 합의 | 질문 2,000자·첫 결과 10건·조회 도구 1종/보조 포함 3회·전체 60초·별도 토큰 상한. 정확도·안전성·warm 성능 필수, 팀원 사용성 평가 비차단 |

## 도입 범위와 기존 기능의 관계

챗봇은 F4 업무 비서 안의 서비스로 두고 공통 앱 셸에서 진입한다. F1 조회·F2 음성 입력·F3 판단의 책임을 유지한다.
이번 사용자 합의로 아래 1차 기능과 저장·복원을 개발 범위에 포함한다. [현재 MVP](../common/mvp-scope-and-evaluation.md)의 F2·F3 평가 우선순위와 다른 기능의 범위를 일괄 변경하지 않는다.
시세 기능은 F4의 가격 평가 제외 범위와 구분해 후속 착수 시 별도 합의한다.

## 1차 포함 — 사용자 설계 합의

| 기능 | 지원 예시 | 범위·완료 동작 |
|---|---|---|
| 매물 조건 조회 | “A단지 매매 15억 이하 찾아줘” | 단지·거래 종류·금액·명확한 면적 범위 등 허용 조건으로 조회하고 조건·총건수·결과·상세 진입을 표시 |
| 구입장 조건 조회 | “전세를 찾는 진행 중 손님 보여줘” | 희망 거래·진행 상태·정규화된 예산 등으로 조회. 거래 성사 가능성은 평가하지 않음 |
| 일정·할 일 조회 | “이번 달 만기 일정 보여줘” | Time Keeper의 날짜 계산·조회 서비스를 재사용. 정확한 기간·종류 필터와 잘린 건수는 서버에서 처리 |
| F2 진입 | “음성메모로 장부를 작성하고 싶어” | 실행 버튼으로 기존 신규 음성메모 화면을 열고 기존 검토·상세 저장 흐름을 이용 |
| 결과 후속 질문 | “그중 전세만”, “두 번째 상세 열어줘” | 현재 표시된 검색 조건과 제한된 최근 문맥을 사용하고 대상이 모호하면 선택을 요청 |
| 기능 안내 | “무엇을 할 수 있어?” | 실제 활성화된 기능만 소개. 알려진 화면 이동은 모델 호출 없이 처리 가능 |

모든 예시는 합성 시연 입력이다. 아직 제공하지 않는 필터는 구현·검증 후 추천 질문에 노출한다.
일정 생성·장부 수정·문자 발송은 조회에서 자동 확장하지 않는다. 검색 결과에서 기존 상세를 열어 사용자가 조작한다.

## 후속·제외 범위

| 시점 | 기능 | 이유 |
|---|---|---|
| 1차 이후 | 선택된 세대·손님의 상담 로그 조회·요약 | 원문 최소화·근거 연결·권한 검증과 답변 사실성 평가가 추가로 필요 |
| 별도 후속 | 사무소 전체 상담 로그 검색·의미 검색 | 현행 로그 API는 대상 ID가 필요하며 전역 검색·벡터 색인 재사용은 별도 개발 |
| 개발 보류 | F3 실행·포지션 판정·추천 후보의 성사 가능성 설명 | 챗봇에 F3 실행 도구를 등록하지 않음. 검색 결과는 조건 일치 순서이며 F3 판정 등급을 만들지 않음 |
| 선택 | 최근 실거래 요약·지역 가격지수 | 외부 API 키, 단지 매핑, 집계·신선도 검증 후 추가 |
| 1차 제외 | 무제한 Text-to-SQL, DB 쓰기, 웹 자유 검색, 장기 기억, 파일·실시간 음성 채팅 | 시연 가치에 비해 권한·복구·평가 범위가 크게 증가 |

## 멀티턴과 데이터 기준

- 1회는 사용자 질문 1개와 완료된 답변 1개의 쌍이다. 현재 질문 외 직전 2회와 현재 검색 조건만 Backend가 DB에서 골라 전달한다. 실패·취소·중단 요청은 기본 문맥에서 제외한다.
- 현재 검색 조건은 별도 표시하고 유지한다. 이전 대화가 문맥에서 생략돼도 조건이 남는 이유를 숨기지 않는다. 조건 해제는 이력을 삭제하지 않고 현재 검색 조건만 초기화한다.
- 사용자당 대화 1개를 DB에 보존하고 이력 조회·전체 삭제를 제공한다. 여러 대화방 생성·목록·개별 메시지 삭제는 1차에 제공하지 않는다.
- 새로고침·탭 종료 뒤에도 서버는 처리와 결과 저장을 계속한다. 다시 접속하면 이력·상태를 복원하며 서버 자체가 중단된 요청은 자동 재실행하지 않는다.
- 작성자만 조회·전체 삭제한다. 사용자 삭제 또는 시연 환경 폐기까지 보존하며 삭제 성공 시 대화·메시지·요청 기록을 운영 DB에서 즉시 물리 삭제한다. 백업은 별도 기존 정책을 따른다.
- 로그아웃·계정 변경은 브라우저의 이력·구독을 비우되 DB 대화를 삭제하지 않는다. 브라우저 영속 저장소에 대화 본문을 저장하지 않는다. 저장 상세는 [저장 설계](../../architecture/chatbot/persistence.md)를 따른다.
- 서버는 과거 답변의 값과 대상 ID를 신뢰하지 않고 다시 권한·존재를 확인한다. 검색 후 저장값이 달라졌다면 새 조회 결과를 기준으로 답한다.
- 질문의 가격·면적·날짜가 모호하면 추측하지 않는다. “30평”은 전용·공급 기준을 확인하고 “다음 달”은 서버의 한국 시각 기준 범위를 표시한다.
- 숫자·날짜·정렬·총계는 Backend가 계산한다. 정규화 값이 없는 레코드를 0원·0㎡로 간주하지 않는다.
- LLM에는 최소한의 비식별 문맥만 전달한다. 사용자가 입력한 자유 문장도 개인정보 입력 경로이므로 실제 데이터 도입 전 [개인정보 정책](../../../.agents/skills/project-wiki/references/privacy/policy.md)을 적용한다.

## 수용 기준과 실제 평가 범위

구현 계획 합의로 정확도·안전성·warm 성능 기준을 필수로 정했다. 이후 사용자가 Qwen 기동·평가를 보류했으므로 이번 실제 평가는 Luna 기본 입력 60건을 3회 반복한다. Qwen은 같은 평가 실행 경로만 준비하고 통과로 간주하지 않는다. 결과는 [구현·검증](../../architecture/chatbot/implementation-and-validation.md)을 따른다.

| 검증 대상 | 합격 기준 |
|---|---|
| 기본 30건·동의어/단위 10건 | 지원 질문의 도구·조건 일치율 90% 이상. 금액·날짜 계산과 DB 결과 일치는 결정적 검사에서 모두 통과 |
| 멀티턴 10건 | 조건 추가·변경·해제, 지시 대상·문맥 만료를 기대대로 처리하는 비율 90% 이상 |
| 모호·미지원 10건 | 질문 또는 제한 안내를 제공하며 미지원 기능을 실행하지 않음 |
| 권한·주입 공격 별도 20건 | 다른 사무소·변조 ID·임의 SQL·쓰기·검색 문서의 지시문으로 권한을 우회하는 사례 0건 |
| 결과·근거 | 조건, 기준 시각, 총건수, 표시 범위를 제공. 없는 레코드·가격·연락처를 만들어내는 사례 0건 |
| SSE·장애 | 실제 단계만 표시. 끊기면 상태 미확인으로 표시하고 DB snapshot으로 복원. 서버 중단은 interrupted·수동 재시도, 구독 재연결은 모델을 재실행하지 않음 |
| 저장·삭제 | 작성자 외 접근 0건, 중복 요청의 중복 실행 0건, 전체 삭제 후 늦은 결과로 대화가 재생성되는 사례 0건. 새로고침 후 이력·최종 상태 복원 |
| F2·F3 경계 | F2 진입만으로 분석·저장하지 않음. F3 요청은 보류 안내하며 실행 API 호출 0회 |
| 지연·부하 | 동시 추론 1건의 warm 상태에서 첫 진행 이벤트 p95 1초 이내, 일반 조회 완료 p95 30초 이내를 필수 기준으로 측정. cold start·혼잡은 별도 보고 |
| 사용자 가치 | 시간·클릭 수·정답 도달률 비교는 후속 사용성 평가로 둔다. 팀원 사용성 평가는 이번 완료 조건에서 제외 |

평가 fixture·모델 평가는 `ai/eval/`, 결정적 조회·권한·API 검사는 `backend/tests/`, 화면·SSE 소비 검사는 `frontend/tests/`에 둔다.
데이터 준비를 별도 `data/`에서 수행하더라도 그곳에는 테스트 코드를 추가하지 않는다.
F4 소속·1차 범위·저장/문맥은 이번 사용자 합의로 정했다. [프로젝트 미해결 질문](../../../.agents/skills/project-wiki/references/open-questions.md)의 시세 관련 항목은 후속 착수 시 결정하며 1차를 차단하지 않는다.
