# 요구사항 관리

## 목적

F1·F2·F3 제품 요구사항을 사람이 검토할 수 있으면서 에이전트가 필요한 범위만 정확히 찾도록 관리한다. 긴 통합본을 일상적인 탐색 경로로 사용하지 않는다.

## 정본과 출처

- `common/`, `f1/`, `f2/`, `f3/`의 분할 문서가 저장소에서 편집하는 요구사항 정본이다.
- `sources/`는 사람이 제공한 원문을 변경하지 않고 보존하는 출처 스냅샷이다.
- 정본이라는 말은 저장 위치와 변경 책임을 뜻한다. 각 요구사항의 승인 상태는 문서의 `status`로 별도 표시한다.
- 통합 문서가 필요하면 분할 정본에서 생성하며 생성 결과를 직접 수정하지 않는다.

현재 분할 문서는 2026-08-14 제공 통합본에서 기능 내용을 그대로 옮겼으므로 `출처` 상태다. 팀이 승인한 범위만 별도 검토를 거쳐 `결정`으로 바꾼다.

## 탐색

1. [요구사항 인덱스](index.md)에서 기능, 검색 의도 또는 ID 접두어로 문서를 고른다.
2. 정확한 ID가 있으면 다음 명령으로 출처 스냅샷을 제외한 분할 정본을 찾는다.

```bash
rg -n --glob '*.md' --glob '!sources/**' 'F1-GR-02' docs/requirements
```

3. 둘 이상의 기능에 걸친 작업은 `common/`과 각 기능의 관련 문서를 함께 읽는다.
4. 출처 표현과 대조해야 할 때만 `sources/`를 연다.

## 변경 절차

1. 요구사항 ID 또는 검색 의도로 정본 파일을 찾는다.
2. 상세 정의는 한 파일에서만 수정하고 다른 문서에는 ID와 링크만 둔다.
3. 기존 ID는 유지하며 폐기된 ID를 새 요구사항에 재사용하지 않는다.
4. 변경 ID, 이유와 날짜를 [changelog.md](changelog.md)에 기록한다.
5. 구현 또는 테스트가 생기면 [traceability.yaml](traceability.yaml)에 경로를 연결한다.
6. 공통 계약, 개인정보, 모듈 경계 또는 승인된 프로젝트 결정이 바뀌면 같은 변경에서 project-wiki도 갱신한다.
7. 변경은 브랜치와 PR에서 검토하며 승인 전 내용을 완료된 사실로 표현하지 않는다.

## 품질 규칙

- 한 파일에는 하나의 검색 의도와 변경 책임을 둔다.
- 요구사항 ID를 제목 또는 표 행에 그대로 남겨 정확 검색이 가능하게 한다.
- 요구사항 본문, 추적 파일과 project-wiki 사이에 같은 상세 내용을 복제하지 않는다.
- 미확정 질문은 소유 범위의 open-questions 문서에 연결한다.
- 비밀값과 개인정보 원문을 요구사항, 예시, 로그에 기록하지 않는다.
