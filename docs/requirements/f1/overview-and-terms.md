# F1 개요·원칙·용어·역할

## 제1부 F1 장부 시스템

> **원본 문서** — `F1_요구사항정의서_5차수정.md` · 원제 「F1 장부 시스템 요구사항 정의서」

현행 장부 도구의 기능을 웹으로 이전한다. F2·F3가 읽고 쓰는 데이터 기반이며, 세 기능 중 유일하게 없어서는 안 되는 부분이다.

> 현재 사용 중인 장부 도구의 기능을 웹으로 이전한다. 기술적으로 불가한 항목만 제외한다.
- **문서 범위** — F1 장부 시스템 단독
- **작성일** — 2026-08-13 (5차 수정)
- **근거** — 현행 장부 화면 4매 · 세대상세 실물 캡처 · 현업 인터뷰
- **요구사항 수** — 235항목 (기능 222 · 비기능 13)
- **개정** — **데이터 이관 요구사항 전면 삭제**(15.2 및 F1-MG 전 항목, F1-NF-10 폐기) · 인물 인덱스 ①②③ 의미 확정 · 미해결 2건 해소

### 1. 개요

#### 1.1 목적

본 문서는 F1 장부 시스템이 충족해야 할 요구사항을 정의한다. F1은 F2(STT 입력)와 F3(비서 에이전트)가 읽고 쓰는 **데이터 기반**이며, F1이 현업 수준의 완결성을 갖지 못하면 나머지 두 기능은 시연 이상의 의미를 갖지 못한다.

#### 1.2 범위

| 구분 | 내용 |
|---|---|
| 포함 | 매물장(세대 전수 대장) · 구입장(손님 대장) · 상담 로그 · 세대/손님 상세 · **상태 전이 및 거래 이력** · **문서함** · 검색 · 문자 대상 수집 및 **문자 작성·발송 흐름(개인·단체)** · **F2·F3 연동 접점** · 일정 · **알림** · 마스터 데이터 · 권한 · **사용법 가이드** |
| 제외 | 전화 발신 및 통화 이력 연동 · `tel:` 링크 · SMS 실발송 · 원격제어 · 도움말 동영상 · **현행 장부 데이터 이관** (16장 참조) |
| 유보 | SMS 실발송은 **현 범위에서 제외하되 추후 활성화 가능한 구조**로 설계한다. 발신번호 사전등록 등 법적 요건 충족 시 설정 전환만으로 켠다 (F1-MS-14) |
| 타 기능 경계 | 음성 인식 자체는 F2, 판단·브리핑은 F3. F1은 **저장과 조회**, 그리고 **F2 결과를 받는 화면과 규칙**을 책임진다 (9장) |

#### 1.3 설계 원칙

> **[참고]** **원칙 1 — 장부는 세대 전수 대장이다.** 현행 장부의 기본 화면은 101동 101호부터 매물 여부와 무관하게 전 세대가 행으로 존재한다. 중개사는 매물을 관리하는 것이 아니라 **단지 전 세대를 대상으로 접촉 이력을 누적**한다. 최상위 단위는 매물이 아니라 세대이며, 매물화는 세대의 일시적 상태다.

> **[참고]** **원칙 2 — 기존 업무 흐름을 바꾸지 않는다.** 현행 장부의 조작 순서·용어·로그 포맷을 그대로 따른다. 새 UI를 강요하면 도입되지 않는다. 개선은 **제약을 없애는 방향**으로만 한다.

> **[참고]** **원칙 3 — 데이터는 지우지 않는다.** 현행 장부는 2018년 상담 기록까지 삭제 없이 누적한다. 이 누적이 F3 조사관의 자산이다.

> **[범례]** 필수 없으면 현업 사용 불가 권장 있어야 실용적 선택 여유 시 **출처** 매물장 / 구입장 / 세대상세 / 손님입력 = 현행 장부 화면. 인터뷰 / 신규 = 그 외

### 2. 용어 및 사용자 역할

#### 2.1 용어 정의

| 용어 | 정의 |
|---|---|
| 세대 | 단지 내 개별 호실. 매물 여부와 무관하게 존재하는 장부의 기본 단위 |
| 매물 | 세대가 거래 대상이 된 상태. 세대에 종속되며 소멸·재생성될 수 있다 |
| 매물장 | 세대 전수 대장. 현행 장부의 기본 화면 |
| 구입장 | 손님(수요) 대장. 매수·매도·전세·월세 의뢰인 관리 |
| 상담 로그 | 접촉 이력. `[YY-MM-DD HH:MM 주①]본문` 포맷의 append 텍스트 |
| 인물 인덱스 | 로그와 연락처에 붙는 `①②③`. **같은 역할에 인물이 여러 명일 때의 순번**이다 (예: 남편 ①, 아내 ②). 통화 회차나 발신·수신 구분이 아니다 |
| 현상태 | 세대의 현재 임대차 상태. 입주 / 경신 / 월환 등 |
| 현매물 | 해당 세대가 지금 어떤 거래로 나와 있는지. 매매 / 전세 / 월세 |
| 명도 | 매수인이 실제 입주 가능한 시점 조건 |
| 경신 | 계약 갱신 의미 확인 필요 |
| 월환 | 전세→월세 전환 추정 의미 확인 필요 |
| 붙박이 | 고정 설비·옵션. "에5"(에어컨 5대) "에폴" 등 축약 표기 |
| 임대부동산 | 해당 물건을 물어온 타 중개업소. "당사"는 본 사무소 |
| 담당 | 해당 건을 맡은 직원. 실장 / 김이순 등 |

#### 2.2 사용자 역할

| 역할 | 대응 | 권한 |
|---|---|---|
| 소유자 | 개업공인중개사 | 전체 조회·편집 · 직원 관리 · 삭제 · 마스터 데이터 관리 |
| 직원 | 실장 · 김이순 | 전체 조회 · 편집 · 본인 담당 건 삭제 |
| 읽기전용 | 보조 인력 | 조회만. 개인정보 필드 마스킹 |

- 현행 장부에 담당자 2인이 실재하므로 **멀티유저는 선택이 아니라 전제**다
- 동일 사무소 내 데이터는 기본 공유. 담당자별 **필터**는 제공하되 **격리**는 하지 않는다
