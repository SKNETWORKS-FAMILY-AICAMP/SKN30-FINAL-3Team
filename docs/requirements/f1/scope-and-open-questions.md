# F1 제외 범위·미해결 사항

### 16. 제외 범위

현행 장부에 존재하나 본 시스템에 넣지 않는 기능과 그 사유.

| 현행 기능 | 사유 | 대안 |
|---|---|---|
| 전화 걸기 | 기술적 불가 | 웹 브라우저는 발신할 수 없다. 시스템은 발신에 관여하지 않는다 |
| `tel:` 연결 링크 | 제거 대상 | 데스크톱에서 동작이 보장되지 않고 기기·OS별 편차가 크다. **구 F1-MS-08을 삭제**하고 번호 복사(F1-MS-05)로 대체한다 |
| 최근전화 · 재호출 발신 | 기술적 불가 | 통화 이력을 읽을 수 없다. 상담 로그 기반의 최근 조회 이력으로 대체한다 (F1-SR-04) |
| 전화 수신 팝업 | 기술적 불가 | 착신 감지 불가. 번호 붙여넣기 검색으로 대체한다 (F1-SR-03) |
| SMS 실발송 | 제도적 제약<br>**(한시적 제외)** | 발신번호 사전등록이 법적 의무이며 사업자 서류가 필요하다. **현 범위에서는 개인·단체 문자 작성, 수신자 확정, 번호 복사, 발송 이력 기록까지 제공**하고 실제 전송만 제외한다. 요건 충족 시 **설정 전환만으로 활성화**되도록 어댑터로 분리한다 (F1-MS-14). 화면·데이터 구조는 지금 발송을 전제로 만든다 |
| 원격제어 | 범위 밖 | 웹 서비스는 설치가 없어 원격 지원 대상이 아니다 |
| 도움말 동영상 | 범위 밖 | 화면 내 도움말·용어 툴팁·검색 가능한 매뉴얼로 대체한다 (14장) |
| 프로그램 종료 | 해당 없음 | 브라우저 탭을 닫으면 된다. 로그아웃은 제공한다 |
| 7,200건 표시 제한 | 제거 대상 | 현행 장부의 성능 한계다. 본 시스템은 제한을 두지 않는다 (F1-GR-03) |
| 수동 줄바꿈 요구 | 제거 대상 | 현행 장부의 렌더링 한계다. 자동 워드랩으로 없앤다 (F1-LG-08) |
| 주민번호 평문 저장 | 제거 대상 | 따라가서는 안 되는 관행이다 (F1-SE-03) |
| 로그 하단 인라인 표시 | 제거 대상 | 자동 스크롤로 그리드 하단에 상세 로그를 펼치는 방식은 보던 위치를 잃게 한다. 비동기 팝업으로 일원화한다 (F1-LG-19 · F1-ST-15) |
| 현행 장부 데이터 이관 | 범위 밖 | 현행 장부에 내보내기 기능이 없어 자동 이관 경로가 성립하지 않는다 (17.2). 초기 데이터는 사무소가 직접 입력한다 |
| 다국어 지원 | 범위 밖 | 단일 사무소·한국어 단독 사용을 전제한다. 명시적으로 제외하며 문구 외부화도 하지 않는다 |
| 외부 매물 사이트 연동 | 범위 밖 | 네이버·직방 등으로의 매물 게시는 본 시스템의 책임이 아니다. 내보내기(F1-GR-29)로 대체한다 |

### 17. 미해결 사항 및 해소 이력

#### 17.1 미해결 사항

인터뷰로 확정해야 요구사항이 확정되는 항목.

| # | 질문 | 영향 | 우선 |
|---|---|---|---|
| 1 | 「주」는 주인을 뜻하는가. 임차인 통화는 다르게 표기하는가 | 상대 구분 필드의 값 목록이 정해진다 | 높음 |
| 2 | 「현상태」의 경신·월환의 정확한 의미와 전체 값 목록 | 선택 값이 정해진다 | 높음 |
| 3 | 「사용자1~5」는 실제로 무엇을 적는 칸인가 | 확장 필드를 유지할지, 정식 컬럼으로 승격할지 결정된다 | 중간 |
| 4 | 「바탕색」과 색상값 검색을 실제로 쓰는가. 색마다 의미가 있는가 | 색상 기능의 우선순위가 정해진다. 의미가 있다면 태그로 정규화한다 | 중간 |
| 5 | 전화번호 옆 기호 ①②⊗◎☎는 무엇을 뜻하는가 | 연락처 태그의 값 목록이 정해진다 | 중간 |
| 6 | 「추천매물」 「중개매물」 버튼은 무엇을 보여주는가 | 연계 조회의 정의가 정해진다 | 중간 |
| 7 | 상가·주택·재건축 탭도 실제로 쓰는가 | 장부 구분 기능의 필요 여부가 정해진다 | 중간 |
| 8 | 「만기도래일 보기」와 「SMS 전송」을 실제로 쓰는가. 안 쓴다면 왜인가 | F3와의 경계가 정해진다. 안 쓰는 이유가 곧 개선점이다 | 높음 |
| 9 | 상담 로그를 나중에 검색해서 찾아본 적이 있는가 | 로그 검색의 우선순위와 F3 기억 도구의 가치가 검증된다 | 높음 |
| 10 | 7,200건 표시 제한이 실제로 불편한가 | 성능 개선이 판매 포인트가 될지 정해진다 | 낮음 |
| 11 | STT는 통화 중 실시간 인식인가, 통화 후 녹음 파일 업로드인가 | F1이 받는 입력 형태와 화면 흐름이 완전히 달라진다. 실시간이면 로그가 진행 중에 쌓이고, 사후면 일괄 반영이다 | 최우선 |
| 12 | 통화 녹음에 대한 상대방 고지·동의는 어떻게 처리하는가 | 녹취 보관 요건과 F1-ST-12의 파일 보관 가능 여부가 정해진다 | 높음 |
| 13 | 발신번호 사전등록에 필요한 사업자 서류가 준비되어 있는가 | 실발송 모드(F1-MS-14) 활성화 시점이 정해진다. 불가하면 번호 복사 흐름이 최종안이 된다 | 높음 |
| 14 | 단체 문자를 실제로 몇 명에게, 어떤 문안으로 보내는가 | 치환 변수(F1-MS-12)와 템플릿의 필요 수준, 성능 기준(F1-NF-12)이 정해진다 | 높음 |
| 15 | 상세 로그 팝업에서 로그 외에 어떤 필드를 함께 편집하는가 | 팝업 구성 범위와 F1-GR-32 저장 확인의 대상이 정해진다 | 중간 |
| 16 | STT 결과가 틀렸을 때 되돌릴 수 있어야 하는가 | 로그 추가 전용 원칙(F1-LG-01)과 충돌한다. 승인 전 취소로 충분한지 확인이 필요하다 | 중간 |
| 17 | 거래가 성사되면 장부에 무엇을 어떻게 적는가 | 5.4 상태 전이의 값과 필드가 정해진다. `매환24.04.20 18.7억`이 유일한 단서다 | 최우선 |
| 18 | 만기 알림을 며칠·몇 개월 전에 받고 싶은가 | F1-AL-01의 기본값이 정해진다. 너무 이르면 무시되고 늦으면 소용없다 | 높음 |
| 19 | 개인정보 보유 기간을 얼마로 잡는가 | F1-SE-09의 파기 주기가 정해진다. 「지우지 않는다」와 법적 파기 의무가 충돌하는 지점이다 | 높음 |
| 20 | 등기부등본·사진 등 파일을 지금은 어디에 두는가 | 문서함(5.5)의 필요 수준과 용량 요건이 정해진다 | 중간 |
| 21 | 외출 중 휴대폰으로 장부를 보는 일이 있는가 | F1-NF-13의 모바일 지원 범위가 정해진다 | 중간 |
| 22 | 「비고」가 두 곳(우측 열 · 전폭)인데 용도가 다른가 | 상세 화면의 비고 필드 수와 배치가 정해진다. 둘 다 동·호를 적는 데 쓰이고 있다 | 높음 |
| 23 | 「붙박이」 칸에 세입자 정보를 적는 이유는 무엇인가 | 정식 필드가 없어 빌려 쓰는 것이라면 신규 필드가 필요하다 | 높음 |
| 24 | 상담 로그 [편집] 버튼으로 과거 기록을 고친 적이 있는가 | 추가 전용 원칙(F1-LG-01)과 F1-LG-27의 타당성이 검증된다. 고쳐 왔다면 대안이 필요하다 | 높음 |
| 25 | 「사용자1~5」에 들어 있는 값의 의미는 무엇인가 | 5번 질문의 후속. 캡처에서 확인된 실제 값을 근거로 정식 컬럼 승격 여부를 정한다 | 중간 |

#### 17.2 해소된 항목

확인이 끝나 요구사항에 반영된 항목. 되묻지 않기 위해 남긴다.

| 원 # | 질문 | 확인 결과 | 반영 |
|---|---|---|---|
| 1 | 현행 장부 데이터 내보내기(엑셀·CSV)가 되는가 | **되지 않는다.** 내보내기 기능 자체가 없다 (2026-08-13 확인) | 자동 이관 경로가 성립하지 않아 **데이터 이관을 범위에서 제외**했다. 초기 데이터는 사무소가 직접 입력하는 것을 전제한다 (1.2 · 16장) |
| 2 | 상담 로그의 ①②③은 무슨 뜻인가 | **같은 역할에 인물이 여러 명일 때의 순번**이다 (예: 남편 ①, 아내 ②). 통화 회차나 발신·수신 구분이 아니다 (2026-08-13 확인) | 용어 정의 추가(2.1), 포맷 규격에 명시(7.1), F1-LG-33 · F1-LG-34 신설. 복수 인물 등록(F1-UD-09)의 순번과 연결 |

> **[참고]** **되묻지 않기 위한 장.** 해소된 항목을 목록에서 지우기만 하면, 몇 주 뒤 같은 질문을 다시 하게 된다. 무엇을 어떻게 확인했고 어디에 반영했는지를 함께 남긴다.
