# F2 매도의뢰 합성 데이터 개인정보 처리 기록

## 산출물과 목적

- 데이터셋: `f2_sell_request_scenarios.privacy_safe.v0.2.jsonl`
- 버전: `0.2.0`
- 상태: 개인정보 담당자 검토 전 초안
- 목적: F2 상담유형 분류용 `매도의뢰` 합성 대화 50건 제공
- 포함하지 않는 내용: 실제 상담 원문, 실제 이름·전화번호·주소, 정확한 실제 거래금액·날짜
- manifest: `f2_sell_request_scenarios.privacy_safe.v0.2.manifest.yaml`

이 기록은 데이터 생성 과정의 자체 점검 결과이며 법률 검토나 개인정보 담당자의 적정성 판단을 대체하지 않는다.

## 생성 방식

1. 실제 상담 레코드의 문장이나 구체 값을 행 단위 생성 입력으로 사용하지 않았다.
2. `매도의뢰`라는 상담 의도와 다음과 같은 일반적인 업무 축만 사용해 독립적인 시나리오 청사진 50개를 구성했다.
   - 거래유형: 매매·전세·월세·반전세
   - 물건유형: 아파트·빌라·오피스텔·주택·타운하우스·상가·업무시설
   - 점유상태: 소유자 거주·임차인 거주·공실
   - 조건상태: 확정·협의 가능·정정·추가 확인 필요
   - 소유관계: 단독소유·공동소유·법인소유·대리 접수
3. 청사진마다 고유한 `source_group_id`를 부여해 파생 사례가 서로 다른 분할에 섞이는 것을 방지할 수 있게 했다.
4. 합성 여부는 `source_type: fully_synthetic_from_abstract_blueprint`로 표시한다.
5. 생성에 사용한 도구, 설정과 난수 시드는 기록하지 않았다. 따라서 동일 산출물을 재생성할 수는 없고 sha256으로 무결성만 확인한다.

### 준식별정보

- 정확한 거래금액 대신 `억 원대 초반`, `시세 범위`, `수천만 원대`처럼 범주화했다.
- 정확한 날짜 대신 `다음 달 말`, `두 달 뒤`, `다음 반기`처럼 상대 시점으로 일반화했다.
- 정확한 면적 대신 `소형·중형·대형 평형`처럼 구간화했다.

### 원본과의 분리

- 실제 상담 원문은 이 데이터 파일이나 manifest에 저장하지 않았다.
- 원본과 합성 데이터 사이의 복원표·매핑표를 만들지 않았다.
- 원본을 추적할 수 있는 사례 식별자 대신 합성 청사진 식별자만 사용했다.

## 0.1.0 초안 처리 이력

- `f2_sell_request_scenarios.v0.1.jsonl`은 manifest와 개인정보 처리 기록 없이 저장소에 추가된 초안이었다.
- 내용 점검 결과 전 50건에 `*000동 *000호` 형태의 부분 마스킹과 `010-0000-0000` 형태의 마스킹된 연락처가 있었고, 48건에 정확한 금액 표현이 남아 있었으며, 6건이 하나의 `f2-sell-request-seed-0001` 그룹을 공유했다. 실제 마스킹 상담 전문에서 파생됐을 가능성을 배제할 수 없다고 판단했다.
- 작업 트리에서 파일을 삭제하고 `0.2.0`으로 대체했다. `registry.yaml`에 삭제 사실과 사유를 기록했다.
- 남은 위험: 해당 파일은 커밋 `9e7ba4b`의 Git 이력에 그대로 남아 있다. 이 커밋은 `front/refactor`와 `origin/front/refactor`에만 있고 `main`에는 없다. 병합 전에 이력에서 제거하려면 해당 커밋을 squash 또는 재작성하고 강제 푸시해야 한다. 이 조치는 브랜치 소유자와 팀의 결정이 필요하다.

## 남은 한계와 사용 조건

- 현재 대화 인계에는 과거에 부분 마스킹된 상담 예시가 제공된 이력이 있으므로, 이 산출물을 완전한 클린룸 생성 결과라고 단정하지 않는다.
- 실제 상담 원문과 정확한 문자열·의미 유사도를 안전한 내부 환경에서 직접 비교한 것은 아니다.
- 자동 패턴 검사는 개인정보가 없음을 법적으로 확정하는 절차가 아니다.
- 사람 검수를 거치지 않았다(manifest `human_verified: false`).
- 합성 데이터는 실제 상담 분포를 대표한다고 보장할 수 없다.
- 라벨이 `매도의뢰` 한 종류뿐이라 이 산출물만으로 분류 성능을 판단할 수 없다.
- 개인정보 담당자의 검토 전에는 내부 MVP 실험용 초안으로만 사용한다.
- 외부 공개나 최종 학습에 반영하기 전에는 별도 환경에서 원본 유사도, 희귀 조합, 재식별 가능성을 사람과 도구로 재검토한다.
- 최종 학습·평가 분할 시 같은 `source_group_id`를 둘 이상의 분할에 배치하지 않는다.
